# 准备 GUI 支持界面

只在已选择 GUI 且产品真实需要支持界面时使用。每类界面和出站能力独立选择；用户只需要关于页或标题时，不得顺带加入赞助、更新或遥测。

## 工作流程

1. 读取 `AGENTS.md`、最新 Product Spec、`docs/ENGINEERING_RULES.md`、相关 ADR、已批准的 `docs/GUI_APP_PROFILE.md` 和现有 GUI 实现。确认需求已进入产品范围；若新增能力会改变产品边界、隐私承诺或对外协议，先转 `$desktop-define-product`。未选择 GUI 或应用身份尚未批准时停止实施并报告缺口。
2. 列出本次明确选择的支持界面，例如窗口标题、关于页、帮助/联系入口、赞助入口、更新检查或遥测。只收集所选项仍缺失的产品事实，不把某个既有下游的产品名称/标识、路由、主机、协议、秘密或默认开关推广到其他产品。`assets/brand-support/brand-support-profile.json` 中的工作室品牌、两类联系人、三档价格/权益与支付材料是项目负责人批准的产品家族例外，不得当成来源产品身份删除或改写。
3. 按需从 `assets/brand-support/GUI_SUPPORT_SURFACES.template.md` 创建或更新 `docs/GUI_SUPPORT_SURFACES.md`，记录已批准的实例字段、内容/资源来源、i18n 键、可访问名称、所有权、启用状态和未决项。该文件是下游产品事实，Harness 模板不得预创建；升级器必须将其视为 `protected`。详细字段与所有权矩阵见 [references/gui-support-surfaces.md](references/gui-support-surfaces.md)，关于/赞助模板与媒体集成见 [references/about-and-sponsor-pages.md](references/about-and-sponsor-pages.md)。
4. 先划分职责再实现：
   - 当前产品名、版本、功能与宿主交互留在 GUI；标题使用打包版本与已批准模板动态组装，不写死一次构建版本。共享品牌联系人、赞助内容和媒体读取 `assets/brand-support/`，不得另建漂移副本；
   - 领域校验、跨接口可复用的资格判断、状态转换、默认值和稳定错误进入 shared core，并先覆盖成功路径与最高风险失败路径；
   - 窗口标题、系统浏览器、原生通知、平台元数据采集、Tauri 权限和 WebView 展示属于 GUI adapter；React 只拥有路由、展示和纯交互状态；
   - 赞助若只展示本地内容可留在 GUI；一旦产生权益、订单、支付或账户状态，就是新的业务与外部副作用，必须另行定范围和授权。
5. 对任何更新检查、遥测、远程帮助内容或其他出站能力逐项建立显式能力清单。未获批准时保持禁用且不得发请求。清单至少包含目的、触发器、HTTP 方法、允许的 origin/路径模板、请求字段、响应 schema、重定向范围、超时、响应大小、重试/并发上限、失败语义、日志脱敏、秘密来源引用，以及适用的同意、保留和删除政策。
6. 秘密只能由已批准的安全运行时来源提供。不得把实值放入 Rust/TypeScript 源码、常量、文档、配置样例、测试夹具、日志或前端 bundle；产品事实只记录秘密引用名和归属。前端不得持有能代表服务端或发布者身份的长期秘密。
7. 可选网络支持默认 fail-open：失败、超时或取消不得阻断应用主要业务，也不得被解释为成功。异步任务必须有应用生命周期 owner、取消路径、超时和关闭回收，禁止 detached task。生产更新地址默认使用 HTTPS；下载 URL 和重定向必须经过允许列表与无嵌入凭据检查，并使用系统浏览器或另行批准的更新器。强制更新、自更新、签名校验或渠道发布属于独立产品/安全边界，不从“检查更新”自动推导。
8. 遥测默认关闭。只有产品、隐私和适用法律边界已明确批准，且用户同意策略、精确事件/字段、标识符生命周期、保留期和删除路径均已记录时才启用。禁止自由文本业务载荷、令牌、绝对路径、会话内容或未批准的稳定设备标识；不得用“匿名”替代字段级审查。
9. 用户可见文字必须接入既有 `i18next`/`react-i18next` 与 `rust-i18n`，跟随主题、键盘导航和无障碍语义。当前产品名、版本、功能、路由和动作仍由下游注入；共享品牌联系人、三档价格/权益、支付码与视觉资源默认复用品牌包。页面不得强制固定导航位置或页面数量，赞助布局不得恢复固定 800px、固定三栏或全页 `pointer-events: none`。
10. 对品牌包执行选择性打包：GUI 下游完整保留 Skill 的 13 个源图片；选择赞助页时把 `media/sponsor/*` 全部复制到应用 public 的 `/brand-support/sponsor/`，包括当前未引用小图；选择更新视觉时复制 `media/updater/banner.jpg`。未选择的表面不得进入应用 bundle。禁止优化、重绘或解码重建支付二维码；复制后以 `media-manifest.json` 的字节数和 SHA-256 复核。
11. 使用 `$desktop-implement-change` 直接实施。只运行本次所选界面必需的非空单元/回归测试，覆盖其核心成功路径与最高风险失败路径；例如本次确实涉及的品牌数据、替代文本、响应式布局、零出站、URL 边界、秘密隔离、取消回收、同意撤回、去重、动态版本、i18n 或无障碍。不得为未选能力制造占位实现或测试。
12. 日常实施不自动追加全仓格式、类型、lint、中文注释、生产构建、最终 `dist` 扫描或完整验收；媒体清单/摘要复核仅在本次复制品牌媒体时运行。只有独立事件触发时才更新 Product Status、ADR 或 Changelog。用户显式请求构建时交给 `$desktop-build-tauri-release`，由构建流程逐次确认 E2E 并全量运行单元测试；本 Skill 不发送真实遥测、调用生产更新服务、执行支付或发布。

## 边界

- 本 Skill 是可选 GUI 产品能力，不属于中性 scaffold，也不要求 CLI/TUI/MCP 存在。
- `docs/GUI_APP_PROFILE.md` 继续拥有应用展示身份；`docs/GUI_SUPPORT_SURFACES.md` 只拥有已批准的支持界面实例与出站清单，两者不得互相覆盖。
- Harness 不保存来源下游产品名/标识、路由、固定 endpoint、秘密、版本、遥测实例或批准结论；产品家族共享的工作室品牌、联系人、固定赞助内容和 13 个媒体文件是 `assets/brand-support/` 的封闭例外。
- 本 Skill 在选择 GUI 的终端下游完整保留，包括品牌依赖资产；非 GUI 下游必须在初始化裁剪中删除。Harness 升级传播整个条件 Skill，但不覆盖产品实例文档。
- 支付二维码是敏感静态品牌材料。携带或展示它不授权订单、权益、账户、自动支付、支付回调或支付状态确认；真实交易副作用必须独立定范围和授权。

## 完成输出

报告本次选择与未选择的界面、产品事实文档位置、GUI/core 所有权、出站清单与默认禁用项、秘密来源是否仅为引用、运行过的检查、未验证平台和剩余隐私/发布风险。
