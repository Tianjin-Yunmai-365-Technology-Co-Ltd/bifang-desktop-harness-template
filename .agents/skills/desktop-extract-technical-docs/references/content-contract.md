# 内容与证据合同

每个重要结论给出实际文件的相对链接，必要时注明函数/配置键或行号。概览记录 `YYYY-MM-DD` 提取日期、实际范围、Git HEAD（若有）及未提交变更；快照不是持续同步服务。

## 技术选型

从清单、入口、工具配置和相关 ADR 确认语言、接口、框架、存储、构建/测试工具及其职责。区分项目当前使用、可选模板和未实现计划。表格建议为“技术 / 当前用途 / 声明版本或下界 / 证据 / 决策依据”；找不到决策依据时写“未记录”，不推导“为什么选”。提取无需联网查询最新版本，除非用户另行要求升级或版本核验。

## 依赖清单

- 先用 `rg --files --hidden` 等只读方式发现实际清单，覆盖子工作区及目标平台声明；跳过 `.git`、缓存、构建产物和原样第三方包。列明扫描范围和排除项。
- 对实际语言采用对应清单：例如 Cargo 的 workspace/member、普通/开发/构建/目标依赖和 features；Node 的 production/dev/peer/optional；其他语言读取其自己的声明，不套用 Cargo 结构。
- 保留包名、所属模块、用途、作用域、版本约束、features/可选条件、registry/git/path 来源。workspace 继承追踪到声明，不把 workspace 池里的可选项全判为正在使用；alias 与真实包名分别说明。
- 约束不等于安装版本。只有锁文件或本次明确执行的解析结果能证明精确解析版本；无锁时写“未锁定”，传递依赖写“未枚举”。不为了补齐表格运行包管理器、解析下载或更新锁文件。
- 工程工具、外部 CLI 和 Skill 运行时与项目库依赖分开。第三方快照只列来源、版本/摘要和用途，不把其内部依赖混入项目直接依赖。

## 架构与文件结构

从真实入口沿调用或导入追到核心逻辑、适配层、驱动和状态写入。解释主路径及影响结果的分支，箭头的执行者必须由源码证明。只有工程规则的模板仓库可以用工程控制流架构，不能画成已经运行的桌面产品。

目录树只展开读者需要定位的真实模块，附职责、入口和关键文件；说明忽略第三方、缓存和生成物。把整个提取过程生成的 `knowledge/` 作为一个派生目录，不递归引用自身的全文。

## 当前技术债

优先读取存在的 `docs/TECH_DEBT.md` 或项目指定登记源，再核对与当前源码相关的记录。已解决/历史条目不冒充当前债务；仍需核对的条目标注原状态及未知项。源码中的临时标记、缺失测试或依赖约束只是调查线索，不能单凭关键词认定缺陷。

建议字段为“来源/标识 / 当前状态 / 证据 / 影响 / 建议 / 优先级依据”。未找到登记源时写“未发现已登记债务”，并记录覆盖范围；不能声称项目没有技术债。推断项单列“待确认风险”，附支持线索和确认方法。只生成提取快照，不自动修复或写回权威技术债。
