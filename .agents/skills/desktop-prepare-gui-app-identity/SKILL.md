# 准备 GUI 应用身份

在首次真实 GUI 开发变更前收集面向用户的应用身份。中性脚手架不属于产品 GUI 开发。

## 工作流程

1. 读取 `AGENTS.md`、`docs/product_spec/README.md` 与日期最新的产品规格、`docs/project_status/README.md` 与日期最新的产品状态、`docs/ENGINEERING_RULES.md`、已选接口及相关 ADR。确认已选择 `GUI`，且产品目的已经批准。
2. 在首次产品 GUI 规划或实施前，请用户确认应用展示名称、简短描述、应用标识符或包标识符、图标方向，以及任何品牌色或源资产。主窗口标题不是自由文案：记录并预览固定公式 `{applicationName} {version} {contactChannel}:{contactValue}`，其中应用名来自本资料、版本来自权威打包元数据、联系字段来自品牌 profile 的 `contacts.windowTitle`；不得询问或保存一份会漂移的手写版本标题。若批准的分发格式包含 macOS DMG，先展示初始化生成的 `<project-id>_gui/src-tauri/dmg/background.png`，再让用户选择批准该中性基线或替换它；同时确认需要覆盖的文案语言、660×400 窗口尺寸和应用/Applications 落点。软件许可页只按产品/渠道明确要求决定。只询问缺失值，不得推断法律权属或品牌权属。
3. 只提供以下三种图标路径，并由用户选择：
   - **自动生成**：根据已批准的应用信息生成多个图标方向，展示预览，取得选择，并保留选中的母版。
   - **确定性备选方案**：根据已批准的名称和颜色创建简洁、确定性的备用图标，例如字母组合或几何标记，然后取得批准。
   - **用户上传**：检查用户提供的图像，保留原图，规范裁剪、留白、透明度和 sRGB 色彩，并通过图像编辑或高清处理能力生成干净的高分辨率母版，不得拉伸图像或虚构品牌细节。
4. 先制作或批准一份 1024×1024 的正方形无损母版，再生成平台变体。通过真实 Tauri 工具链或另一种有文档记录的确定性转换器生成平台图标集；不得手工编写二进制图标文件，也不得在未展示结果时声称已完成视觉批准。DMG 背景同样必须展示预览并确认；批准初始化基线时保留 `<project-id>_gui/src-tauri/dmg/background.png` 的现有字节，选择替换时把最终 660×400 PNG 写回同一路径并重新展示。不得复用 Harness、其他产品或带第三方身份的图片；文字必须通过批准语言清楚表达拖到 Applications 的动作。
5. 在 `docs/GUI_APP_PROFILE.md` 中记录已批准值、固定标题公式与权威字段来源、所选图标路径、来源与溯源、母版路径、平台变体、适用时固定为 `<project-id>_gui/src-tauri/dmg/background.png` 的 DMG 背景路径、SHA-256、660×400 尺寸、落点、文案语言和“批准初始化基线/已替换”结论，以及尚未解决的分发元数据。只有身份选择构成长期重要决定时才写 ADR；只有发布/完整验收、重要阻断、跨会话交接或用户要求时才更新 Product Status。
6. 将已批准资料直接交给 `$desktop-add-gui-adapter` 实施，不自动创建 Work Plan 或完整验收步骤；更新应用显示名后同时验证原生标题、`document.title` 和关于页使用新名称且仍保留权威版本与品牌联系方式。如果用户推迟图标选择，则保留中性脚手架图标并明确标记为临时图标；允许非打包业务开发继续，但阻止生产打包或发布声明。固定标题、关于页与赞助页已经由 GUI 初始化启用；只有修改这些默认界面、增加其他支持界面、更新检查或遥测时，才在身份资料批准后再次调用 `$desktop-prepare-gui-support-surfaces`。

## 边界

- 不得静默复用 Harness 徽标、生成草稿或用户上传的低分辨率文件作为正式发布图标或 DMG 背景。
- 不得虚构商标权属、商店元数据、签名身份、发布者身份或法律声明。
- 选择生成或编辑图标时，必须使用可用的图像生成或编辑能力；如果该能力不可用，则使用确定性备选方案或请求用户上传，不得假装已经生成。
- 本 Skill 在初始化后保留；首次产品 GUI 开发时触发一次，此后只有已批准的 GUI 身份发生变化时才再次触发。
