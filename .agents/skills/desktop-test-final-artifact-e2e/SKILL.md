# 测试最终产物 E2E

通过真实用户或宿主使用的同一可见交互路径，验证已批准范围内的场景。

## 工作流程

1. 读取已批准成功标准、当前构建的 E2E 选择、`docs/VERIFICATION.md` 及适用接口 Skill。要求当前构建选择为 `enabled`，或存在已批准产品/渠道的 `required` 规则；`milestone_e2e` 不能替代当前构建选择。
2. 要求 `$desktop-verify-delivery` 已定位与源码提交、构建身份和 manifest 绑定的完整真实最终产物。拒绝开发预览、源码调用、模拟后端、脚手架、占位内容或推测路径；没有 Work Plan 不阻断 E2E。
   GUI 性能按 manifest 的当次 `performanceSelection` 独立处理。选择 `enabled` 或产品/渠道硬要求时，`$desktop-test-gui-release-performance` 是打包前针对同一 clean HEAD Release no-bundle 探针的必需门禁：E2E 关闭不能替代或跳过，最终候选 E2E 通过也不能替代性能结论，E2E 交互不得倒填为更早的探针样本。开始最终 E2E 前先由 `$desktop-verify-delivery` 证明包内运行时与探针的逐字节或受验证签名变换绑定；安装容器摘要不能冒充探针摘要。选择 `disabled` 且无硬要求时，只复核 `performanceStatus: Not run`、原因/剩余风险和探针/证据/绑定字段缺席，不要求不存在的运行时绑定，也不得把 E2E 结果倒填为性能通过。
3. 根据批准标准定义有边界的核心成功路径和最高风险失败路径，说明前置条件、隔离且可逆的数据、预期观测、清理和超时。
4. 启动真实产物，使用已安装的 `computer-use` Skill 与 GUI、浏览器、终端或宿主界面交互。每项操作前后检查全新状态；优先使用无障碍树，只有依据最新截图才使用坐标。
5. 验证状态、输出、持久化数据或错误呈现；单独一次点击或按键不构成证据。除非另获授权，必须在凭据、支付、生产、发布或不可逆操作前停止。
6. 记录产物/版本、源码提交、平台、步骤、预期/观测结果、适用截图、关闭、清理和通过/失败结果，遮盖敏感信息与不必要个人路径。
7. 任何失败、超时、取消或已启用但未运行的场景都拒绝候选并返回 `$desktop-implement-change` 增加回归测试；修复后重新构建完整候选。最终容器字节变化会使旧 E2E 证据失效；若变化同时影响运行时字节、启动器、配置、依赖或行为，当次性能启用时包内 runtime 与探针绑定及旧性能证据也失效，必须从新的 clean HEAD 探针重跑；性能关闭时不得因此制造不存在的性能证据。只有用户要求的活动计划存在时才重开或新增 Todo。
8. 未实际执行的操作系统、显示环境、浏览器、终端、MCP 宿主和包格式标记为 `Unverified`；必需人工最终复核仍是独立步骤，Agent 不得代签。

## 接口覆盖

- CLI：真实二进制调用、输出流、退出状态、取消和关闭。
- TUI：键盘导航、焦点、尺寸调整、错误恢复和终端还原。
- MCP：批准真实宿主的发现、调用、错误、取消和干净断开。
- GUI：启动、完整用户闭环、无障碍状态、错误、持久化和干净退出。
- GUI 更新日志：先从最终候选自身只读定位并校验 `release-notes.json`；`about_page = enabled` 时在真实应用打开 `/about`，点击“更新日志”自身按钮，确认加载来自候选资源、按最新在前最多五版、每版固定“功能优化/问题修复”各最多十条、当前版本与全部版本仅一个小写 `v`，并验证关闭后重开仍显示同一候选事实。资源缺失/损坏的受控失败候选只在已有隔离夹具且无需破坏最终候选时验证本地错误与重试；不得改写正式候选制造失败。`about_page = disabled` 时确认关于路由、入口、命令和弹窗均缺席。

## 完成输出

报告精确产物、当前构建选择/硬要求来源、场景、可观察证据、清理、通过项、失败项和未验证范围；GUI 另报告当次 `performanceSelection`，启用时报告已经复核的包内 runtime/性能探针绑定，关闭时报告 `Not run` 原因与剩余风险。不得把最终 E2E 指标倒填到探针证据、自行改判性能状态或签署人工复核字段。
