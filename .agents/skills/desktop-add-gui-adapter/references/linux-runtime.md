# Tauri Linux 运行时与测试边界

本引用供已有 Tauri 下游排查 Linux 用户目录、扫描、桌面生命周期及 WebView 问题。它只沉淀可复用机制；产品数据布局、排除政策、网络目标、能力选择及历史验收结论留在下游。阅读本引用不授权扫描真实用户数据、安装系统包、改登录项或启动应用。

## 用户目录与平台规则

- 先区分应用自身配置、数据、缓存和第三方应用目录，不能把它们统一当成 `~/.config`。第三方目录必须遵循该应用的实际布局，不能由 XDG 规范推断其已存在。
- XDG 环境变量只接受绝对路径；空值或相对值按无效处理后使用对应默认位置。`XDG_CONFIG_HOME` 默认 `~/.config`，`XDG_DATA_HOME` 默认 `~/.local/share`；主目录无法可靠取得时返回明确的缺失状态，不回落当前目录。依据：[XDG Base Directory Specification](https://specifications.freedesktop.org/basedir/latest/)（核对：2026-10-20）。
- 平台优先目录的选择、Agent/来源过滤和顺序属于产品策略，可以用接收平台标识的 core 纯函数跨宿主回归；adapter 只负责取得宿主根、拼接路径和执行受限 I/O。不要把真实主目录藏在 core 或测试夹具中。
- 桌面启动环境与终端 login shell 不等价，不假定 GUI 能取得 shell dotfiles 中的 PATH。只有产品已批准的外部程序确实缺失时才按专用 Skill 诊断，不为了启动注入用户 shell 或新增 PATH 修复依赖。

## 卷枚举与遍历边界

对只允许扫描特定本地卷的产品，分别核对以下三层：

1. 驱动枚举哪些挂载点，以及它在返回前省略了什么。记录锁定依赖的实现；库名或“列出所有卷”的 API 名称不能证明结果完整。
2. core 如何分类持久/临时、网络、可移动和未知文件系统，以及如何形成允许根和排除根。具体 allowlist 只取产品规格，不能在 Harness 固定一份跨产品政策。
3. worker 在递归入队、候选提交和最终打开时是否使用一致的边界。允许遍历挂载容器，不等于容器内所有挂载均获准；显式允许的子卷也不能在提交候选时被父路径一律拒绝。

“枚举库没有返回该卷”不等于“遍历时会排除该挂载”。例如根卷 `/` 获准，而枚举库省略挂在用户目录下的 tmpfs，单靠已返回卷的排除集合仍可能进入它。按字符串前缀过滤 `/proc` 还可能误吞 `/processed` 的独立挂载；路径包含关系应按组件判断。bind mount、FUSE、容器 mount namespace 和运行中挂载变化也不能由启动时的一份允许根快照自动证明安全。

优先复用已声明驱动；读取原始 mount 表或引入新驱动必须遵守下游文件/依赖边界。需要解析时先按结构分字段，再解码路径转义，保留无法分类的挂载边界；不要用 shell 的 `mount` 输出或 `split_whitespace` 后的未解码文本直接构造路径。解析器及分类器测试可在任意宿主执行，真实挂载隔离仍需 Linux 证据。

## 发现测试与取消

- 使用合成用户根、合成 XDG 值和注入的卷表；避免为测试改进程全局环境，确需更改时隔离并恢复。重复枚举只比较合成数据，不能依赖用户会话文件的创建时序。
- 只有产品政策会排除 tmpfs，且夹具需要通过该卷政策时，才把 `TMPDIR` 指向已经确认位于允许文件系统上的忽略目录，如 `target/test-tmp`。项目目录本身也可能在 tmpfs/网络卷，目录名不是持久性证据；不要修改生产排除政策来让测试通过。
- 队列 worker、目录枚举、签名探测和结果消费各层都检查同一个取消令牌；覆盖预先取消、工作中取消、终态回收与取消后重启。纯策略回归不替代真实大目录的取消延迟测量。
- 最小卷表用例包含：允许根下被省略的临时/网络子挂载、系统路径的同名前缀兄弟、允许的挂载容器子卷、未知类型和符号链接。安全边界缺口应保留失败证据，不能用扩大扫描范围“修复”。

## 托盘、窗口与登录启动

- Linux 的 Tauri `TrayIconEvent` 不发送图标点击/双击事件；恢复窗口和退出必须有实际菜单入口，不能只依赖图标点击回调。依据：[Tauri System Tray](https://v2.tauri.app/learn/system-tray/#listen-to-tray-events)（核对：2026-10-20）。
- 托盘可见性、菜单和焦点结果依赖具体桌面会话及其 AppIndicator 支持。关闭隐藏前须按已选 profile 验证可恢复入口；记录发行版、桌面、X11/Wayland 和实际场景，不能把安装运行库当作托盘已可用。
- 已创建的原生菜单在切换语言时优先更新现有条目，保持稳定 ID 和回调；状态/测试不能只证明翻译字符串存在。
- 登录项以真实插件/OS 状态为准；启用、关闭、失败重读和测试后恢复原状态按独立 autostart Skill。`--background` 只在产品批准且可恢复时使用；注册成功不能证明重新登录后可启动、隐藏和恢复。
- 单实例唤醒、托盘恢复及窗口状态插件必须对同一个主窗口协作；恢复时依次尝试 show、unminimize、focus，真实焦点效果仍由宿主验证。禁用能力不因 Linux 知识文档存在而启用。

## WebView 与 command 权限

- 默认打包协议通常是 Linux/macOS 的 `tauri://localhost` 与 Windows 的 `http://tauri.localhost`；Windows `useHttpsScheme`、自定义协议或外部 URL 会改变前提。先核对实际配置、最终页面 URL 与 CSP，再精确授权所需 origin，不能增加裸 `http:`/`https:` 或通配网络源来绕过失败。依据：[Tauri useHttpsScheme](https://v2.tauri.app/reference/config/#usehttpsscheme)（核对：2026-10-20）。
- command 必须注册在真实 `invoke_handler`。若项目以 `AppManifest::commands` 启用应用命令 ACL，还要同步 build.rs 清单、生成的命令权限与命名窗口 capability；通过权限契约及真实 IPC 区分注册遗漏、ACL 拒绝和业务错误。默认应用命令并非天然都需要自定义 `allow-*`，不能把这一项目选择写成 Tauri 通则。依据：[Tauri Capabilities](https://v2.tauri.app/security/capabilities/)（核对：2026-10-20）。
- 直接调用 Rust 函数或前端 mock 只能证明映射逻辑，无法证明 WebKitGTK 实际资源加载、CSP 或 IPC 权限。最终 Linux 交互仍绑定精确应用字节和目标宿主。
