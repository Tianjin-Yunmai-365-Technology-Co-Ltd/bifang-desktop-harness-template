# 增加 GUI 适配器

直接在共享核心之上增加最小的已批准 Tauri 2 桌面接口。GUI 与 CLI、TUI 和 MCP 相互独立。

## 固定图标契约

- `package.json` 必须把 `@tabler/icons-react` 声明为直接生产依赖，使用经过最低直接版本验证的完整三段 caret 下界；所有图标使用命名导入，保留 tree-shaking。
- 菜单、操作、状态、空态及图表周边控件存在适用 Tabler 图标时，必须优先从该包选择；不得另装图标库，也不得改用手写 SVG、字符或 emoji。数据可视化图表本身仍按真实产品需求选择图表库。
- 功能菜单项以 `TablerIcon` 组件类型注入，赞助、设置和关于图标由固定模板直接提供。侧栏只有 `136px` 单态，不得提供展开/收起图标；`56px` Logo 与每个 `30px` 菜单图标必须显式水平居中且无裁切，菜单名称位于图标下方。
- 偏离上述包或图标来源属于固定技术栈硬规则例外，必须先记录 ADR。

## 工作流程

1. 先判断调用模式。由 `$desktop-initialize-rust-project` 分派时是“中性初始化”，只读 `AGENTS.md`、Agent Policy、`docs/ENGINEERING_RULES.md` 和 Rust/GUI 基线，不要求 Product Spec、Work Plan、ADR、Verification 或 `$desktop-manage-version`（初始版本由 `$desktop-initialize-rust-project` 统一建立）；初始化后新增 GUI 是新增用户可见能力，只有在改变产品边界时才先更新 Product Spec，再以 `--kind feature` 调用 `$desktop-manage-version plan` 取得稳定 `change_id` 与 `required_version`，然后直接实施，不自动创建计划或验收记录，并在本次相关测试通过后以相同参数调用 `apply`。
2. 确认当前工作目录是真实下游 Rust 工作区，具有共享核心，且初始化选择或已批准产品范围中记录了 GUI。`Draft` 项目只能获得不含业务操作的中性脚手架状态 GUI。若当前目录只是文档 Harness，或缺少核心，则停止。不得要求另选目标目录，也不得要求 CLI。
3. 选择依赖或设计页面前，完整阅读 [references/gui-baseline.md](references/gui-baseline.md)、[references/react-frontend-baseline.md](references/react-frontend-baseline.md) 和 [references/mantine-ui-guidelines.md](references/mantine-ui-guidelines.md)。
4. 中性 GUI 初始化先要求 `$desktop-prepare-gui-app-identity` 已建立 `docs/GUI_APP_PROFILE.md` 的初始化 Logo 记录：正好 3 个 1024×1024 PNG 候选均已预览且有摘要，用户明确选择一个，选中母版位于 `<project-id>_gui/src-tauri/icons/app-icon-master.png`，运行时副本位于 `<project-id>_gui/public/app-identity/logo.png` 且字节一致，平台图标来自项目本地 Tauri `icon` 命令。`<project-id>_gui/src-tauri/icons/32x32.png` 还必须是普通非符号链接、32×32 8-bit RGBA 非交错 PNG 且至少含一个非透明像素，`tauri.conf.json` 的 `bundle.icon` 必须精确引用 `icons/32x32.png`；这是固定托盘的可见图标来源。缺少任一证据不得使用中性占位图或无图标托盘继续。首次真实产品 GUI 开发再要求资料补齐应用显示名称、固定标题公式、说明与应用标识符；选择 macOS DMG 时还必须记录对初始化生成的本地拖拽背景 `<project-id>_gui/src-tauri/dmg/background.png` 的预览批准或同路径替换，以及尺寸、落点和文案语言。中性初始化使用当前项目展示身份和 workspace 初始版本组装标题；首次完整身份批准后必须更新名称来源但保留公式。
5. 选择 GUI 即调用 `$desktop-prepare-gui-support-surfaces` 消费固定本地基线：动态标题、`136px` 单态且顶部固定 `56px` Logo→当前版本的左侧菜单、`/settings`、`/about`、`/sponsor`、应用导航入口和完整 sponsor 媒体在初始化时直接建立。每个产品功能项和赞助/设置/关于固定项必须提供 `30px` 图标；每项固定图标在上、名称在下，名称以 `11px` 字号在 `10em` 行内宽度中居中、最多两行并保留完整可访问名称，不得提供展开/折叠状态、开关或 Tooltip-only 名称。产品功能项从侧栏顶部向下增长，底部固定组按视觉顺序为赞助、设置、关于，即从底部向上为关于、设置、赞助。设置页固定展示应用版本、中英文和浅色/深色/跟随系统，不得包含隐私标题、统计同意、未配置占位或对应固定翻译键；关于页固定展示当前应用名、权威版本、手动检查更新、作者、作者联系方式和三段免责声明。没有产品 profile 时关于页更新显示 `NotConfigured`，全部远程请求为零。应用根初始化亮色/暗色的页面背景、surface、主/次文字、边框与强调色，并持久化主题偏好；赞助页固定使用品牌 profile、翻译与双支付码，并从 Mantine 已解析主题同时支持亮色和暗色呈现。初始化不得预创建 `docs/GUI_SUPPORT_SURFACES.md`，但 GUI 下游必须完整保留该 Skill 的品牌源资产和更新/统计契约供默认页面和未来受控配置使用；只有产品明确启用统计时才另建产品级同意界面。
6. 识别已批准的人类使用场景、产品功能菜单项、状态与错误展示、键盘与无障碍要求、刷新/并发语义、平台集成、隐私边界、预期分发格式和 i18n 接入范围（默认语言探测、设置页语言切换和需要覆盖的原生文案）。产品若配置更新、强更或统计上报，完整阅读 `$desktop-prepare-gui-support-surfaces` 的 `references/update-and-telemetry.md`，只询问会实质改变范围的缺失选择。
7. 中性初始化直接按接口选择建立无业务 GUI；初始化后新增真实 GUI 也直接实施。GUI 适配器必须与 CLI 解析和 MCP 协议代码相互独立。
8. 执行时检查官方软件包仓库和文档。为 Tauri 2（启用 `tray-icon` feature）、官方 `tauri-plugin-single-instance`、Vite、React、TypeScript、Mantine UI、TanStack Router、TanStack Query、Jotai、`i18next`、`react-i18next`、`rust-i18n`、`tauri-plugin-os`、ESLint/`typescript-eslint`、Prettier、Vitest 与 Testing Library 声明满足 Rust MSRV、Node.js/pnpm、目标 WebView/平台、安全与所用 API 的最低兼容稳定范围；Rust 使用完整三段 Cargo 兼容下界，前端使用完整三段 caret 或官方支持范围，禁止普通依赖的精确版本、`latest`、tag 和通配符。根 `[workspace.dependencies]` 是 `tauri-plugin-single-instance` 版本与来源的唯一事实源，GUI member 只使用 `workspace = true`。以临时最低直接版本解析和项目最低工具链运行相关测试，再由正常 `Cargo.lock`/`pnpm-lock.yaml` 固定实际解析结果。这些技术对 `Draft` 和 `Approved` GUI 项目都是硬规则；技术栈不兼容时必须提高到首个通过的稳定下界，仍不兼容则阻断实施，直到记录硬规则例外。
9. 在 `<project-id>_gui` 中增加桌面应用边界，并将该标识用于 Cargo 软件包、Rust crate 和真实应用二进制。不得要求独立二进制名称；面向用户的名称来自已批准 GUI 资料。由中性 `$desktop-initialize-rust-project` 调用时，接收其选中 Logo、平台图标和逐字节复制的 `<project-id>_gui/src-tauri/dmg/background.png`。在 `tauri.conf.json` 的 `app.windows` 中把主窗口写为 `width: 1440`、`height: 900`、`minWidth: 960`、`minHeight: 640`、`center: true`、`preventOverflow: true` 和可调整大小；默认逻辑像素足以同时显示固定 `136px` 侧栏与赞助页三张档位卡片，较小工作区则由响应式布局降列。在独立的 `bundle.macOS.dmg` 中写入 `background: "./dmg/background.png"`、`windowSize: { width: 660, height: 400 }`、`appPosition: { x: 180, y: 220 }` 与 `applicationFolderPosition: { x: 480, y: 220 }`；主应用窗口和 DMG 安装卷窗口不得混用。不得把已删除初始化 Skill 的资产路径写入运行时配置。建立职责单一且强制存在的桌面生命周期模块：把官方 `tauri-plugin-single-instance` 作为 Tauri Builder 的首个 plugin 注册；同一用户会话再次启动相同应用身份时，第二进程必须通知并退出，只调用共享 `restore_main_window` 恢复、取消最小化并聚焦既有 `main` 窗口，不得新建第二个主窗口。中性脚手架回调必须忽略参数与工作目录，不记录它们，也不得把它们解释为产品动作；未来确需文件关联或深链时另行批准并经 core 判定。根 Tauri 依赖同时启用 `tray-icon`。托盘安装函数必须从 Tauri Builder 的 `.setup(...)` 实际调用，在同一实现中用 `Menu::with_items`（或等价官方 builder）组装稳定 ID `show_window`/`quit` 两项并以 `.menu(&menu)` 绑定；可见标签必须通过 `rust_i18n::t!("tray.show_window")` 与 `rust_i18n::t!("tray.quit")` 按当前规范化 locale 解析，中文精确为“显示窗口/退出”，英文精确为“Show Window/Quit”，不支持的 locale 回退英文，运行时语言变化必须刷新已安装菜单而无需重启，严禁把稳定 ID 或 `tray.*` 键直接显示。必须把 `default_window_icon()` 解析为必需值，缺失即使初始化失败，随后以 `.icon(...)` 和 `.build(app)?` 创建托盘，禁止 `if let Some(icon)` 后无图标继续。主鼠标左键释放或 `show_window` 复用同一 `restore_main_window`；主窗口 `WindowEvent::CloseRequested` 处理必须由 Builder 的 `.on_window_event(...)` 实际注册，调用 `api.prevent_close()` 并隐藏，不能退出进程；只有 `quit` 执行显式、可回收的应用退出，存在 owned task 时先取消并等待回收。该菜单绑定同时满足 Tauri 官方说明的 Linux 可见性要求；不得因 Draft、宿主差异、页面简单或实现偏好省略单实例/托盘，也不得默认加入自动启动。Linux Snap/Flatpak 渠道必须在对应清单声明官方插件要求的会话 DBus own/talk 权限，并在真实沙箱候选上重验；普通本机调试结果不能替代该渠道证据。复用 Tauri 基于 Tokio 的单例异步运行时；不得创建嵌套 Tokio 运行时。Tauri Rust 适配器可以依赖核心；核心不得依赖 Tauri、WebView、React、路由、查询、命令、窗口或前端状态类型。维护的 Rust/前端代码和测试必须遵守工程规则。
10. 公开窄而有类型的普通 `async fn` Tauri 命令，只验证反序列化、协议必填字段和调用窗口/WebView 能力，然后构造 core 请求、调用一个异步 core 用例并映射结果。值域、跨字段约束、资源状态、业务权限、默认值和包含条件/重试/状态决策的调用编排属于 core；Tauri Rust command 不得承载这些逻辑。I/O、等待、计时器和进程调用保持异步。只有测量确认的 CPU 密集工作才可考虑 Tauri 异步运行时的 `spawn_blocking` 或另行批准的线程边界，并记录所有权、取消、并发上限、资源预算和测试。仅支持阻塞调用的依赖应替换为异步能力，否则停止并进入范围或硬规则例外流程。为命名窗口/WebView 使用明确 CSP 及最小能力、权限和作用域集合。默认只加载打包的本地内容。
11. 只实现已批准管理闭环和固定 GUI 基线。使用 Mantine UI 负责组件/布局，TanStack Router 文件路由负责导航并生成唯一 `src/routeTree.gen.ts`。以固定 `136px` 单态侧栏作为应用壳层：不得创建折叠 atom、折叠状态或切换按钮；顶部第一项始终渲染 `56px` 的 `/app-identity/logo.png`，其下紧接当前版本；产品功能项位于可滚动顶部区域，底部固定组严格为赞助、设置、关于并分别到达 `/sponsor`、`/settings`、`/about`。所有菜单项的 `30px` 图标为必填；图标在上，名称以 `11px` 字号在 `10em` 行内宽度中居中显示于下方并最多两行，始终保留完整 `aria-label`，不得使用 Tooltip-only 名称。Mantine 根使用唯一 `AppThemeProviderTemplate`、`defaultColorScheme="auto"`、明确的 local-storage manager，并同时提供亮色/暗色的页面背景、surface、主/次文字、边框与强调色；设置页通过 Mantine color-scheme context 提交 `light`、`dark`、`auto`，赞助页以 `useComputedColorScheme` 消费运行时有效主题。不得在初始化时只生成宿主当前主题版本。TanStack Query 负责命令支撑的异步状态，Jotai 只负责确有必要的跨组件客户端交互状态；语言与主题偏好由 GUI adapter 的设备级本地存储持久化。主窗口标题固定动态组装为 `{applicationName} {version} {contactChannel}:{contactValue}`，应用名与版本来自权威 Tauri/打包元数据，联系字段来自品牌 profile 的 `contacts.windowTitle`；原生窗口标题和 `document.title` 必须消费同一组事实并保持一致。不得把 Query/核心/持久数据镜像到 atom 中，也不得在 React event handler、Router loader、Query mutation 或 atom 中实现业务规则和领域状态转换。
12. 设置页始终只渲染当前应用名/版本、中文/英文和浅色/深色/跟随系统；不得渲染隐私标题、统计上报同意、未配置占位或对应固定翻译键。关于页始终渲染手动检查更新与状态。未配置更新能力时关于页只呈现 `NotConfigured`/禁用状态，不安装网络插件、不创建 endpoint 或占位请求。产品启用更新时才接入官方 Tauri updater：更新制品签名验证不可关闭，默认拒绝降级和 target/arch/channel 不匹配；不得信任远端 `forcedUpdate` 布尔值，强更只能由 adapter 验证策略后把 `minimumSupportedVersion` 交给 core 作严格 SemVer 判定，根级强更门不挂载普通功能且只允许安装或安全退出。产品启用统计时才另建产品级明确同意界面，并只由 Rust adapter 在明确同意后以 HTTPS JSON POST 发送固定 `app_started` 字段，禁止 GET/query、稳定标识符和桌面内置 secret；撤回同意必须取消请求并清空有界内存队列。所有任务由应用生命周期拥有并回收，失败默认 fail-open。
13. 稳定资源 ID 必须与视图位置分离，选择范围和批处理范围必须明确，真实展示空/加载/错误状态，并从共享核心/存储获取全部持久状态。
14. 在 GUI 前端项目自有工具目录复制 [TypeScript Compiler AST 中文注释检查器](references/check-typescript-chinese-comments.cjs) 与 [专项测试](references/check-typescript-chinese-comments.test.ts)，调整相对导入后同时接入 `pnpm lint` 和项目 validator。检查器必须识别直接及后置命名/默认导出的箭头组件与 hook，只在测试文件或显式 `vitest` 导入中识别 `test`/`it` 场景；精确排除 `src/routeTree.gen.ts`，对解析错误/非法 UTF-8/NUL/源码符号链接/空扫描失败关闭；禁止扩张到所有局部变量或普通匿名回调，禁止加入自动批量注释。
15. 先用 core 测试覆盖业务成功路径、最高风险领域失败和状态转换，再测试 Rust 异步命令映射、任务取消、动态标题及 GUI 生命周期。单实例必须提供固定命名回归 `single_instance_plugin_is_registered_first` 与 `second_launch_restores_existing_main_window`；托盘生命周期必须提供 `tray_show_restores_and_focuses_main_window`、`close_request_hides_without_exit`、`tray_quit_exits_application`，托盘 i18n 必须另提供 `tray_labels_resolve_for_supported_locales`、`tray_labels_fall_back_to_english`、`language_change_updates_tray_menu_labels`，分别锁定中英文精确标签、未知 locale 英文回退和运行时切换刷新。不得用只有源码字符串的断言替代行为回归。其余回归覆盖三个 Logo 候选选择与选中资产接线、侧栏 `136px` 单态、Logo→版本 DOM 顺序、`56px` Logo、`30px` 图标、图标上/文字下、`11px`/`10em` 名称、无折叠状态/开关/Tooltip-only 名称、主窗口 1440×900/最小尺寸配置、应用亮暗语义变量、浅色/深色/跟随系统回调及持久化、默认设置页无隐私/统计控件和翻译键、赞助页亮色/暗色差异、功能区与固定底部顺序、设置/关于/赞助路由、语言切换、关于页 `NotConfigured` 零出站、作者/联系人/免责声明、赞助媒体、查询生命周期、Jotai 纯交互转换、前端交互、键盘导航、无障碍语义、能力拒绝和并发刷新/写入行为。启用更新/统计后，按支持 Skill 的参考增加 SemVer 强更、签名、同意撤回、字段白名单、任务回收和失败语义测试。布局属于验收范围时使用视觉质量检查。
16. 只有真实下游需要前端公开配置时，才建立 `development/test/release` 逻辑 profile 和类型化冻结配置对象；全部 Vite 变量视为用户可读，禁止凭据且产品模块不得散落读取 `import.meta.env`。真实需要前端日志时使用稳定、脱敏的结构化事件，优先通过窄 Tauri 命令汇入 Rust `tracing`；Release Vite `dist` 必须静态拒绝 source map、开发/测试 endpoint、debug/info 哨兵、本机路径和未经批准的 console 输出。
17. 本 Skill 只运行本次 GUI/core 变化必需的非空 Rust 与前端单元/回归测试；不自动追加全仓格式、lint、类型、静态扫描、生产构建、冒烟或完整验收。中性初始化完成这些测试后返回 `$desktop-initialize-rust-project`，由后者固定调用一次 `$desktop-test-gui-initialization-e2e`：先用 `verify-gui-lifecycle-contract.mjs` 检查单实例依赖/首插件/回调、托盘 feature、32px RGBA 非透明图标与配置引用、`.setup`/菜单/图标/`.build(app)`/`.on_window_event` 真实接线、稳定 ID、由 `rust-i18n` 解析的双语资源和八个命名回归，再双启动真实本机调试二进制，证明第二次启动只唤醒既有主窗口并退出且只剩一个长期应用主进程/主窗口，最后检查有可见图形而非空白点击区域的真实托盘及关闭隐藏/恢复/退出生命周期，并在中文/英文切换后逐次核对托盘精确标签且确认无 `tray.*` 原始键；后续日常开发不自动 E2E。只有用户显式请求发布构建时才调用 `$desktop-build-tauri-release`；构建流程必须确认自己的最终候选 E2E 选择，并在打包前运行完整 Rust 与前端单元测试套件。

## 硬边界

- GUI 必须保持独立，并通过相同核心和错误模型与每个已选适配器保持行为一致。
- GUI 初始化已经交付真实页面与托盘原生文案，因此必须立即通过 `i18next`/`react-i18next`（前端）与 `rust-i18n`（Rust 原生文案）接入；默认语言跟随 `tauri-plugin-os` 探测到的系统语言，并提供可发现的语言切换入口，偏离需硬规则例外 ADR（见 ADR-20260806-001）。
- React 事件、Tauri command 和平台回调不得承载业务规则、领域校验、权威状态或跨 core 调用编排；当前只有 GUI 也不是例外。
- 绝不能从 GUI 自动操作 CLI 或解析 CLI 输出。
- 绝不能把业务规则、持久状态、迁移或平台无关验证放入 React 组件、路由、查询、atom 或事件处理器。
- 不得创建第二套存储或由前端拥有的权威数据副本。
- 不得仅因 GUI 较小或熟悉其他技术栈就替换任何固定 React 前端库。偏离必须形成硬规则例外 ADR。
- `@tabler/icons-react` 是固定图标库；适用图标不得由其他库、手写 SVG、字符或 emoji 替代。图表相关控件优先使用 Tabler 图标，但该包不承担图表绘制。
- 未经批准的真实需要，不得启用远程 URL、宽泛 Tauri 权限、伴随进程、自动启动、updater 网络配置或其他平台集成；`tauri-plugin-single-instance` 与 `tray-icon` 只用于固定本地生命周期基线，关于页 `NotConfigured` 状态也不授权其他插件或网络能力。
- 不得把来源下游产品名/标识、产品功能、更新协议、endpoint、秘密或统计字段复制为 GUI 默认值。固定 `/settings`、`/about`、`/sponsor`、侧栏顺序、版本展示、标题公式和产品家族品牌联系人/免责声明/赞助内容/支付码/小图是经批准的封闭默认基线；更新 banner 只保留在 Skill 源资产，未经选择不进入 bundle。
- 固定单实例、系统托盘和窗口生命周期在 GUI adapter 实现并属于 GUI 初始化硬门禁：官方单实例插件必须最先注册，第二次启动只恢复、取消最小化并聚焦既有主窗口后退出，不得形成第二个长期应用主进程或主窗口；托盘必须消费已配置且非透明的 `icons/32x32.png` 对应默认应用图标，安装函数从 `.setup(...)` 真实调用，双项 `Menu` 绑定到同一 builder，图标缺失即失败，`.build(app)` 成功后才算创建；只有稳定 ID `show_window`/`quit` 对应的“显示窗口/退出”，窗口关闭处理由 `.on_window_event(...)` 注册且只隐藏，左键和显示菜单项都恢复并聚焦，退出菜单项结束应用。缺少资产/配置引用/运行时接线、依赖/实现、首插件顺序、命名回归、双语资源、真实双启动唯一性或托盘生命周期证据都必须阻断 GUI 初始化完成，不能以宿主不便观察、Draft 或小型应用为由跳过；改变或移除该基线需先变更产品/平台范围并记录硬规则 ADR。通知、自动启动、快捷键和其他桌面机制仍需单独批准。其回调触发的业务动作必须调用既有 core 用例，不能直接修改权威业务状态；中性单实例回调不触发业务。平台机制本身无需 core-first 例外 ADR。
- 没有真实项目需求时，不得增加其他路由器、服务器状态缓存、通用全局存储或可选前端包。
- 不得用宽泛目录名排除人工 TypeScript 源码，不得用自动生成套话代替业务注释；非 GUI 下游不适用 TypeScript 门禁，也不得因此要求 Node.js 或 pnpm。
- 不得用同步 I/O、休眠、进程等待或 CPU 密集命令阻塞 Tauri 的 Tokio 运行时，也不得创建嵌套运行时。
- 不得仅为编译、测试或构建允许 unsigned 的本地候选而要求签名材料；经批准的候选冒烟可以使用明确 unsigned 制品。Developer ID 直接分发一旦使用签名身份，就必须同时完成公证与 stapling，不能交付只签名制品。
- 除初始化选中的应用 Logo、固定本地标题、`136px` 单态侧栏、精简设置/关于/赞助页、应用导航、单实例和托盘生命周期外，不得捆绑其他页面、业务操作或产品状态。设置页只读取当前应用身份与语言/主题偏好，不读取或展示统计能力状态；关于页只读取当前应用身份与 adapter 提供的更新状态，未配置远端能力时不得发请求。随附中文注释检查器只属于治理工具参考，不是页面或业务资产。
