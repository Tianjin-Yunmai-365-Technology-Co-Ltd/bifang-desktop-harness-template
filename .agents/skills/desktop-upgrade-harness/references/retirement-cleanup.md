# 退役服务清理选择

更新、统计和 Updater 已退出 Harness 工程能力。保留旧名称的唯一用途是识别旧下游资产，不能恢复 Skill、接口、远程追踪候选、更新签名门禁或运行时占位。

## 询问与复用

1. 先只读生成计划，展示发现的退役工程文件以及是否存在本地定制。路径来自 [精确识别表](../scripts/harness_upgrade_retirement.mjs)，不可按名称关键词扩大范围。
2. `cleanup_selection_required` 表示该项目尚未确认。向用户询问“是否清理这些旧更新、统计及 Updater 工程资产，并在本项目记住选择？”，提供“清理并记住”和“保留并记住”。漏答、普通升级授权、apply approval 或人工合并标志都不是选择。
3. 明确答复后重新 `plan`，追加 `--retirement-cleanup remove` 或 `--retirement-cleanup preserve`。后续重算沿用同一参数，不逐文件重复确认。没有残留时不询问；用户主动要求更改选择时也可显式传入参数。
4. `record` 成功时把 `retirement_cleanup` 写入目标 `.harness/upstream-lock.json`，保持 schema 2。字段是 `scope: gui-update-statistics-v1`、`selection: remove | preserve` 和真实 `confirmed_at`。后续计划自动复用；不能由源候选导入用户选择，也不能在失败后声称已经记忆。
5. 新退役范围不能复用本范围的批准。非法选择或未知 scope 失败关闭，先调查，不应用默认值。

## 清理与完成

- 选择清理：`cleanup_required` 必须在复核后逐路径实际删除。升级 helper 的 `apply` 仍只替换安全受管文件，不递归删除；由 Agent 在当前批准范围执行精确文件操作，再重新 `plan`。删除后的缺席状态才可由 `record` 记为完成，本地仍有文件时不能用 `--resolved-manual` 绕过。
- 选择保留：`preserve_retired` 保持本地字节与权限，记录用户选择并明确报告；不恢复源工程能力。未来升级继续复用保留选择，用户可主动更改。
- 目标独有、旧来源锁未登记的退役文件也必须发现。旧 `conditional` mode 不改为 managed/tombstone，避免破坏旧锁兼容；符号链接、特殊文件和计划后的目标/选择漂移继续阻断。
- 混合规范和仍在使用的共享资产按章节合并，移除旧服务条款、旧技能入口和更新密钥前置要求，保留安装包代码签名、公证和本地发布日志。`preserve` 时受管新规范仍可更新，但不得把下游自有能力说明写成已删除；必要的本地差异按现有合并合同保留。
- 产品源码、Cargo/npm 依赖、Tauri 配置、能力 profile、真实发布记录和秘密均不属于上述精确工程清单。发现旧产品实现时另列产品变更范围，经用户明确授权后由产品实施流程处理；不能把记住的工程清理选择当作删除产品实现或凭据的权限。

完成报告应区分：本次选择/复用选择、删除项、保留项、未解决的产品实现、来源锁是否已经记忆，以及实际运行的相关检查。
