# 2026-08-03 变更记录

## 新增

- 新增 POSIX 与 PowerShell `release/` 刷新辅助程序：在独立 Git 根校验后原子隔离旧目录、创建全新空目录，并以不跟随符号链接/重解析点的方式清理隔离树。
- 新增构建/发布专用校验器与回归测试，机械检查根锚定忽略规则、默认三平台路由、派发前回退边界、条件签名、源码提交绑定、精确候选文件集和 `pending` 状态。
- 候选清单新增结构化 `signingEvidence`，区分固定钩子验证成功、`unsigned` 不适用及可选的独立签名证据。

## 变更

- `docs/` 与 20 个项目 Skills 中面向读者和 Agent 的英文自然语言已统一翻译为中文，覆盖 Skill 说明、参考资料、UI 元数据、工作流标签、脚本诊断和中性 Rust 资产展示文本；命令、路径、字段、状态、协议令牌和技术标识保持原样。
- `$build-rust-release` 默认先构建 Windows、macOS、Linux 原生 Rust CLI 候选；只有提供方、权限、运行器或结果取回在派发前不可用时才回退当前宿主。已启动矩阵的测试、构建、签名、打包、超时或取消保持真实失败。
- 构建在已有批准的非交互钩子、工具和授权凭据可用时尝试签名并验证；签名尝试失败不再静默降级，条件不存在时明确记录 unsigned 原因。
- 构建结果统一进入项目根 `release/`，允许 `milestoneAcceptance: pending` 供后续验收；目录存在仍不表示 ready、已验收或可发布。
- 三平台工作流在运行校验脚本前显式选择 Python 3：优先 `python3`，仅在其缺失时使用 `python`，两者都不可用则明确失败。
- `$collect-release-artifacts` 可保留 `pending`、`rejected`、`accepted` 状态，发布准备仍只接受与精确候选匹配的 accepted 证据。
- 初始化生成的 `.gitignore` 精确忽略 `/release/`，并忽略原子刷新被中断时可能遗留的根 `/.release-clean.*` 隔离目录。

## 安全

- 三平台候选工作流新增必填 40 位 `source_commit`，检出固定到该提交、关闭凭据持久化，并在运行仓库代码和签名钩子前复核 `HEAD`。
- 提供方制品不再上传整个目录或从目录中猜测归档；每个平台先在同根唯一暂存区生成归档、校验和、清单三件套，再以目录级原子重命名提交完整 `release/`，并只上传这三个显式路径。
- 签名钩子输出被抑制，不能通过工作流输入注入任意签名命令；签名和验证任一失败都会使对应平台作业失败。
