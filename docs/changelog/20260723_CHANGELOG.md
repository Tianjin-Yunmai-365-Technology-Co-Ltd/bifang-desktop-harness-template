# 2026-07-23 变更记录

## Unreleased

### 变更

- CLI、TUI、MCP 项目 Skills 统一使用 Tokio current-thread 异步入口；GUI 复用由 Tokio 支撑的 Tauri 运行时并使用异步命令。I/O 与等待型开发优先异步，仅测量确认的 CPU 密集任务才考虑受控线程边界。
- 随附的核心+CLI 资产从 Tokio `rt-multi-thread` 改为最小 `rt` 特性与 current-thread 入口。
- GUI 的本地生产构建、测试、产物检查和启动冒烟不再以签名材料为前置；无签名结果明确标记，真实分发渠道签名继续独立阻断。
- 发布制品收集统一刷新项目根 `release/`：每次安全清理历史内容，只复制当前项目、版本、源码提交与明确构建批次的最新已完成结果。
- 初始化流程、Harness 根和随附的资产的 `.gitignore` 均加入根锚定 `/release/`。
- 下游实例化现在完整排除 ADR、变更记录、产品规格、工作计划；这些目录、索引和首份正文分别由产品定义、计划和实施 Skill 在首次真实需要时创建。
- 初始化收尾现在使用用户现有 Git 身份创建唯一的本地基线提交，并验证独立 Git 顶层目录、`main`、可解析 `HEAD`、空远端与空 porcelain 状态。
- 产品规格、产品状态与工作计划已从 `docs/` 根目录固定单文件迁移到各自日期目录，正文统一使用 `YYYYMMDD_product_spec.md`、`YYYYMMDD_product_status.md`、`YYYYMMDD_work_plan.md`。
- 三类项目记忆新增稳定 `README.md` 规则与日期索引；同日持续整理同一文件，新自然日从前一份综合重写为完整当前快照，当前事实取日期最新文件。
- `AGENTS.md`、README、工程规则和相关项目 Skills 已统一改为通过目录索引读取最新日期正文；Harness 自身保留按日事实源，但下游实例化不再迁移四类开发记忆。
- 下游改为一次性初始化：脚手架验证后裁剪实例化/初始化 Skills、模板专用内容和活动派生入口，并永久保留 `AGENTS.md` 的 Skills 地图与约束地图。
- 开发环境门禁拆为长期保留的 `$check-development-environment`：Rust 始终检查，GUI/WEB 额外检查并自动补齐 Node.js 与 pnpm。
- GUI 首次真实开发新增 `$prepare-gui-app-identity`，由用户补齐窗口/应用资料并选择自动图标、确定性备用方案或上传标准化/高清路径。
- 下游 Rust 最低支持版本从 1.85 提升到 1.90；新项目根清单、初始化门禁和三平台候选工作流只接受 Rust 1.90 及以上。
- 全量复审 18 个项目 Skills、对应 UI 元数据、参考资料和全部当前文档；通用 Skills 继续读取项目声明的 MSRV，所有硬编码版本事实已统一为 1.90。
- 随附的核心+CLI 资产的 `rust-version` 已更新为 1.90，并在 macOS arm64 使用精确 Rust 1.90.0 完成锁定依赖检查、Clippy、7 个测试、发布构建和真实成功/失败冒烟。

### 修复

- 修正普通异步适配器默认启用 Tokio 多线程运行时、与“异步优先且仅 CPU 密集考虑多线程”不一致的问题。
- 修正发布候选散落在版本暂存区目录且默认保留历史文件、可能混入旧结果的问题。
- 修正 GUI 构建与分发签名门禁未明确分离的问题。
- 修正“已初始化独立 Git”仍处于尚无提交的 `HEAD` 且全部文件未跟踪、无法称为干净状态的语义冲突。
- 修正下游在真实产品需求、计划或可见变更出现前就预生成四类项目记忆的问题。
- Harness 校验器现在检查五类日期项目记忆，拒绝三类旧单文件、错误的小写 snake_case 日期命名、缺失日期正文、未纳入索引及新日综合规则缺失。
- Harness 校验器新增 Rust 1.90 一致性门禁，核对产品规格、Rust 基线、POSIX/PowerShell 门禁、边界测试、Cargo 资产和候选工作流，并拒绝项目 Skill 内容重新出现 Rust 1.85 兼容声明。
- 前置门禁测试现在以 Rust 1.90 验证成功边界，并以 Rust 1.89 验证最低版本失败边界。
- 修正门禁的版本比较语义：1.90.0 是最低版本，不是精确版本锁；新增 1.91.0、1.97.1 和未来 2.0.0 stable 的通过覆盖。

### 已知问题

- Windows/Linux 原生 Rust 1.90、Windows MSVC 安装、TUI/MCP/GUI/WEB 真实下游兼容组合仍为 `Unverified`。
- Harness 根目录仍无 Git 元数据，无法记录本次分支、提交或脏工作树证据。
