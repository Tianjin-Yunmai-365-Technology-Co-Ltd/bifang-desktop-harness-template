## 文件边界与实施顺序

1. **协作原语**：初始化 `.agents/skills/run-parallel-worktrees/`；脚本只接受显式项目根、任务标识、工作单元和操作，验证 Git top-level、干净基线、路径边界、分支前缀和现有 Worktree，拒绝覆盖与危险清理。结果以稳定 JSON 输出，测试覆盖成功创建、脏工作树、重名/越界、未整合或脏 Worktree 拒绝清理。
2. **Agent 协议**：更新 `AGENTS.md`、README、规划/实施 Skills。主 Agent 先公开拆分与所有权，再启动 Subagent；每个启动、阻塞、阶段完成、整合和验证节点向用户更新，并等待所有必需结果。重叠写入转串行。
3. **验证分层**：更新工程、验证、发布文档和相关 Skills。开发层保留非空单元测试、回归测试和变更相关检查；发布层重新执行完整构建、最终产物、冒烟、E2E、跨平台状态和人工复核。
4. **机械契约**：扩展 validator 和脚本测试，使规则退化返回非零；历史记录中的“19 个 Skills”等真实旧证据保持不改写，只更新当前矩阵和当天证据。
5. **项目记忆**：同步 Product Status、Work Plan、Changelog、VERIFICATION；如实施中出现新的重大取舍，更新当天 ADR 而不新建同日文件。

## 不包含

- 本轮不实际启用多 Agent/Worktree 来实施自身，不创建或清理真实项目协作分支，不改变 Git remote、tag、版本或发布状态。
- 不修改 Subagent 平台实现，不承诺显示内部推理或每条工具调用，不构建独立任务监控 UI。
- 不取消编译相关的必要检查、非空测试、缺陷回归或发布前完整验收。
- 不执行 bundled Rust release build、最终产物冒烟、Computer Use E2E、跨平台候选或人工复核；这些是发布级检查，本轮没有准备发布。
- 不改变接口技术栈、Rust MSRV、许可证、产品定价或商业化路线。

## 风险与回退

- 当前工作树含用户已有修改和未跟踪报告；实施只新增 2026-07-29 文件并基于现状编辑共享入口，绝不重置或清理现有内容。
- 脏基线无法安全复制到新 Worktree；并行 Skill 必须阻断并要求用户先决定如何形成可追踪基线，不得自动 stash 或 commit。
- Git Worktree 清理可能丢失未整合工作；脚本默认仅检查，只有显式清理且目标干净、已整合、路径和分支完全匹配时才移除，其他情况返回阻断状态。
- 宿主无法流式展示全部 Subagent 细节时，最低可见性仍是主 Agent 的阶段更新和同步等待；不得伪造实时状态。
- 验证延迟可能把集成问题集中到发布前；若真实失败重复出现，按 ADR-20260729-002 将对应检查前移到受影响开发轮次。
