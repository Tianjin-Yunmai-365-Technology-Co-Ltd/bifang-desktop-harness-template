# 工作计划索引

本目录是当前已批准变更 TodoList、状态和验证里程碑的唯一正文来源。

## 写入规则

- 文件名固定为 `YYYYMMDD_work_plan.md`，日期使用计划更新所在时区的自然日。
- 同一天只维护一份工作计划；计划变化后持续整理并更新当日文件，不得为同一天新建第二份。
- 新自然日首次写入时，必须读取前一份工作计划，将仍有效步骤、未完成事项和当日新范围综合重写为一份完整的当前计划；不得只追加增量。
- 日期文件是当日完整有效快照，只保留当前计划。已完成结果进入产品状态、验证、ADR 与变更记录；旧计划文件保留历史，但不作为当前计划入口。
- 每份活动工作计划必须包含 `Todo` 批次和对应验证里程碑。每个 Todo 至少包含稳定 ID、预期行为、影响边界、验证方式及 `pending`、`in_progress`、`blocked`、`done` 之一。
- Todo 只有实现与对应非空单元测试/相关检查通过后才能标记 `done`。当前批次任一 Todo 非 `done` 时，计划不得进入验证里程碑，不得执行冒烟/E2E，也不得产生已验收结论。
- 验证里程碑必须记录进入条件、完整真实产物、批准场景、冒烟/E2E 策略解析和失败回流。源码片段、模拟实现、桩实现、占位、中性脚手架或开发预览不能作为可验收产物。
- 验收发现已批准范围内的缺失或偏差时，重开或新增 Todo 并返回编码；只有所有 Todo 再次 `done` 后才能重跑完整里程碑。
