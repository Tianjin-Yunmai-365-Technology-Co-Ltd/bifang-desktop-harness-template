## 目标

统一 CLI/TUI/MCP/GUI 的 Tokio 异步优先边界，允许 GUI 在无签名身份时完成构建验证，并把当前项目最新构建结果安全刷新到根 `release/`。

## 范围

- [x] 将 CLI/TUI/MCP/GUI Skills 和 references 统一为 Tokio async 入口、异步优先、仅测量确认的 CPU 密集任务才考虑受控多线程边界；同步阻塞依赖改为异步能力或进入例外确认。
- [x] 把 bundled CLI Tokio feature 从 `rt-multi-thread` 改为 `rt`，入口改为 current-thread，并同步锁文件与验证。
- [x] 明确 GUI 无签名可以完成构建/本地验证，渠道分发、Store、notarization、updater 的签名要求单独判定。
- [x] 将 `$collect-release-artifacts` 改为安全清理并刷新项目根 `release/`，让相关发布 Skills 统一交接该目录。
- [x] 让初始化 Skill 确保根 `.gitignore` 包含 `/release/`，同步 Harness 根与 bundled asset。
- [x] 同步 AGENTS、README、产品规格、RELEASE、Skill UI 元数据、validator、状态、验证和 Changelog。
- [x] 运行 Skill 快速校验、Python/Harness validator、Rust asset 全门槛、残留扫描和隔离 release 收集语义测试。

## 不包含

- 不改变 TUI、Tauri 或 React 固定技术族，不把 WEB adapter 纳入 Rust Tokio 入口约束。
- 不默认引入 Rayon、线程池或 Tokio multi-thread runtime。
- 不配置签名身份、证书、notarization、Store、updater、remote、push、tag 或上传。
- 不从其他项目、旧版本、未完成构建或来源不明目录收集制品。
- 不把 Harness 隔离验证扩张为真实 GUI/TUI/MCP 或其他平台交付证明。

## 风险与回退

- current-thread runtime 中的同步阻塞会冻结整个 adapter；代码审查与测试必须覆盖 blocking 边界。
- `release/` 清理是用户明确要求的破坏性动作；只能操作 canonical 项目根下非 symlink 的精确目录，并在清理前确定完整来源清单。
- “最新”不能依赖含糊的 provider latest；必须绑定当前项目、版本、源码 commit 与构建 run，歧义时停止。
- 无签名 build 不能升级为可分发或商店就绪结论；验证必须分别记录 build 与 distribution signing 状态。

## 完成标准

- 四类 Rust adapter Skills 都明确 async 入口、Tokio runtime 所有权和仅 CPU 密集任务的多线程准入条件。
- bundled asset 不再启用 `rt-multi-thread`，格式、lint、非空测试、release build 与真实冒烟通过。
- GUI Skill 明确无签名 build 可通过，同时保留真实分发渠道签名门禁。
- release 收集 Skill 只刷新根 `release/`，安全清理历史并拒绝非当前项目或非最新构建文件。
- 初始化确保 `/release/` 进入根 `.gitignore`；validator 可拒绝旧 `dist/v<version>/` 收集语义和缺失 ignore。
- Skill 快速校验、Python/Harness validator、Rust asset 门槛和隔离收集测试全部通过。
