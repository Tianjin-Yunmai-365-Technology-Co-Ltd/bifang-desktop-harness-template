# 当前工作计划

> 记忆日期：2026-07-23

## 目标

统一 CLI/TUI/MCP/GUI 的 Tokio 异步优先边界，允许 GUI 在无签名身份时完成构建验证，并把当前项目最新构建结果安全刷新到根 `release/`。

## 范围

- [x] 盘点四类适配器、初始化资产、Rust 基线、GUI 基线和发布 Skills 的异步/运行时、签名、制品目录与清理语义。
- [x] 将 CLI/TUI/MCP/GUI Skills 和参考资料统一为 Tokio 异步入口、异步优先、仅测量确认的 CPU 密集任务才考虑受控多线程边界；同步阻塞依赖改为异步能力或进入例外确认。
- [x] 把随附 CLI 的 Tokio 特性从 `rt-multi-thread` 改为 `rt`，入口改为 current-thread，并同步锁文件与验证。
- [x] 明确 GUI 无签名可以完成构建/本地验证，渠道分发、商店、公证、更新器的签名要求单独判定。
- [x] 将 `$collect-release-artifacts` 改为安全清理并刷新项目根 `release/`，让相关发布 Skills 统一交接该目录。
- [x] 让初始化 Skill 确保根 `.gitignore` 包含 `/release/`，同步 Harness 根与随附的资产。
- [x] 同步 AGENTS、README、产品规格、发布、Skill UI 元数据、校验器、状态、验证和变更记录。
- [x] 运行 Skill 快速校验、Python/Harness 校验器、Rust 资产全门槛、残留扫描和隔离发布收集语义测试。

## 不包含

- 不改变 TUI、Tauri 或 React 固定技术族，不把 WEB 适配器纳入 Rust Tokio 入口约束。
- 不默认引入 Rayon、线程池或 Tokio 多线程运行时。
- 不配置签名身份、证书、公证、商店、更新器、远端、推送、标签或上传。
- 不从其他项目、旧版本、未完成构建或来源不明目录收集制品。
- 不把 Harness 隔离验证扩张为真实 GUI/TUI/MCP 或其他平台交付证明。

## 风险与回退

- current-thread 运行时中的同步阻塞会冻结整个适配器；代码审查与测试必须覆盖阻塞边界。
- `release/` 清理是用户明确要求的破坏性动作；只能操作规范化后的项目根下不是符号链接的精确目录，并在清理前确定完整来源清单。
- “当前”不能依赖含糊的提供方最新版本；必须绑定当前项目、版本、源码提交与明确的构建/运行身份，歧义时停止。
- 无签名构建不能升级为可分发或商店就绪结论；验证必须分别记录构建与分发签名状态。

## 完成标准

- 四类 Rust 适配器 Skills 都明确异步入口、Tokio 运行时所有权和仅 CPU 密集任务的多线程准入条件。
- 随附的资产不再启用 `rt-multi-thread`，格式、代码规范检查、非空测试、发布构建与真实冒烟通过。
- GUI Skill 明确无签名构建可通过，同时保留真实分发渠道签名门禁。
- 发布收集 Skill 只刷新根 `release/`，安全清理历史并拒绝非当前项目或非最新构建文件。
- 初始化确保 `/release/` 进入根 `.gitignore`；校验器可拒绝旧 `dist/v<version>/` 收集语义和缺失忽略规则。
- Skill 快速校验、Python/Harness 校验器、Rust 资产门槛和隔离收集测试全部通过。
