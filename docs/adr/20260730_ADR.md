# 2026-07-30 ADR

## ADR-20260730-004：移除独立 WEB 支持并保留 Tauri GUI Web 技术栈

- 日期：2026-07-30
- 状态：Accepted
- 关联需求：项目负责人要求将独立 WEB 支持整体移出 Harness，但不得改动 Tauri 的 Web 前端及其技术选型。
- 决定：当前可选接口从 CLI/TUI/MCP/GUI/WEB 收缩为 CLI/TUI/MCP/GUI；删除 `$add-web-adapter`、`<project-id>_web`、初始化选择与分派、独立 WEB 构建/验收契约、专属安全规则及校验器契约。Tauri GUI 继续使用 React、TypeScript、Mantine UI、TanStack Router、TanStack Query 与 Jotai，并继续要求 Node.js 与 pnpm 门禁。
- 边界：Tauri 的本地 WebView、前端包管理、路由、异步状态、客户端状态、构建与测试仍属于 GUI 适配器；不得因为共享过 WEB 基线文件而删除或弱化。GUI 所需的共享前端说明迁入 GUI Skill 自有路径，消除对被删除 WEB Skill 的反向引用。
- 影响范围：`AGENTS.md`、README、产品规格、产品状态、工作计划、Rust/方法论文档、初始化/实例化/环境/GUI/TUI/交付/E2E Skills、Harness 校验器、门禁测试、验证记录、变更记录，以及删除整个 `$add-web-adapter` Skill。
- 不适用：不改变 CLI、TUI、MCP、Tauri GUI 的产品边界；不替换 GUI 技术栈；不改变 Rust 1.90、Tokio、许可证、版本、并行协作或发布门禁。
- 理由：独立浏览器 Web 产品已不属于模板目标；Tauri GUI 仍以本地 Web 技术承载桌面界面，二者是不同适配器边界，必须分别处理。
- 风险：机械删除 `WEB` 字样可能误伤 Tauri WebView、GUI 前端基线或 Node/pnpm 门禁；历史日期文件仍会记录旧五接口决定，检索时必须以最新产品规格和本 ADR 为当前事实。
- 验证：校验器和非空测试必须证明初始化只接受四类接口、无 `$add-web-adapter`/`_web` 当前入口、GUI 技术栈与 Node/pnpm 契约仍存在；全仓审计区分历史记录与当前入口，完整 Harness 校验器和 `git diff --check` 通过。
- 恢复或调整标准：未来若重新引入独立 Web 产品，必须重新通过范围闸门，建立新的适配器 Skill、安全/部署边界、测试与发布契约；不得复用 Tauri GUI 入口冒充独立 WEB。
- 历史关系：本条替代 ADR-20260722-008 中 WEB 作为第五类独立接口的当前适用部分，并收窄 ADR-20260722-003 的固定前端技术族到 Tauri GUI；两条 ADR 中关于其余接口、共享核心和 GUI 技术栈的决定继续有效。

## ADR-20260730-001：并行 Worktree/Subagent 询问仅限设计与编码阶段

- 日期：2026-07-30
- 状态：Accepted
- 关联需求：仅在设计与编码阶段询问是否使用 Worktree 和 Subagent。
- 背景：ADR-20260729-001 把询问应用于所有会修改仓库或执行交付工作的任务，导致纯文档维护、验证复核、构建、发布准备和交付阶段也出现与阶段目的无关的协作模式打断。
- 决定：以任务目的而非是否写入仓库判断触发。产品定义或范围设计、实施计划设计、代码或实现变更在实质执行前询问一次；纯文档维护、纯问答、只读调查、验证复核、构建、发布准备、交付工作和即时安全处置不询问。混合任务只要包含尚未完成的设计或编码阶段，就在该阶段开始前询问一次；授权仍只对当前任务有效且不得继承。
- 保留规则：用户同意后仍须至少两个独立范围、独立 Worktree/`codex/` 分支、写入目标 guard、公开所有权与状态、同步等待和串行化重叠写入；拒绝、未答复或不可拆分时继续单 Agent。
- 影响范围：`AGENTS.md`、README、产品规格、产品状态、工作计划、`$define-product`、`$plan-change`、`$implement-change`、`$run-parallel-worktrees`、Harness 校验器、验证记录与变更记录。
- 不适用：不改变工程文件/注释规则、Rust/适配器约束、CLI 契约、开发验证、发布门禁、版本、许可或技术债状态。
- 理由：设计与编码最可能从并行拆分获得收益；验证、构建和交付阶段已有确定流程与独立的发布验收选择，重复询问会增加认知成本而不改变门禁。
- 风险：混合任务的阶段分类可能不一致；“纯文档维护”与“需求设计”可能被混淆；跳过询问不等于允许自动启用 Subagent。
- 验证：校验器要求新触发与排除语句，拒绝旧的“所有修改/交付任务”当前描述；非空单元测试覆盖旧规则回归，相关 Skills 结构和完整 Harness 校验器通过后记录证据。
- 恢复或调整标准：若阶段判断频繁漏掉适合并行的设计/编码任务，或其他阶段出现可重复且显著的并行收益，以新 ADR 扩展明确阶段，不恢复基于任意仓库写入的一刀切触发。
- 历史关系：本条替代 ADR-20260729-001 中“所有仓库修改或交付任务均询问”的触发范围；其授权不继承、隔离、可见性、同步等待和安全清理决定继续有效。

## ADR-20260730-002：并行 Worktree/Subagent 进一步限定为编码阶段

- 日期：2026-07-30
- 状态：Accepted
- 关联需求：项目负责人明确“Worktree + Subagent 仅编码时使用”。
- 决定：产品定义、范围设计和实施计划设计固定使用单 Agent 当前工作树，不再询问并行模式；只有代码或实现变更在实质编码前询问一次。混合任务只在进入编码/实现阶段前询问，授权仍不跨任务继承。
- 保留规则：获批后的至少两个独立范围、独立 Worktree/`codex/` 分支、guard、公开状态、同步等待、重叠写入串行化和保守清理规则不变。
- 影响范围：`AGENTS.md`、README、产品规格、产品状态、工作计划、`$define-product`、`$plan-change`、`$implement-change`、`$run-parallel-worktrees`、校验器、验证记录与变更记录。
- 理由：并行写入的主要收益和风险都发生在编码/实现阶段；设计和计划需要单一上下文与统一决策，额外拆分会增加协调成本。
- 风险：混合任务可能在设计完成后进入编码，Agent 必须在实际编码前补做一次当次授权询问；不能把修改 Markdown 自动视为编码。
- 验证：校验器要求仅编码触发、设计/计划排除，并以负向测试拒绝旧设计阶段触发契约。
- 恢复或调整标准：若有持续证据证明某类非编码任务存在可安全拆分且显著收益，需由项目负责人重新确认并形成新 ADR。
- 历史关系：本条替代 ADR-20260730-001 中产品/范围设计和实施计划设计也触发询问的部分；其他排除项和安全约束继续有效。

## ADR-20260730-003：Harness 使用上海时区分钟级时间版本

- 日期：2026-07-30
- 状态：Accepted
- 关联需求：项目负责人要求为 Harness 增加清晰版本概念，并以 `YYYYMMDDHHMM` 日期时间为准。
- 决定：Harness 从当前变更起使用 `Asia/Shanghai` 的 12 位 `YYYYMMDDHHMM` 时间版本，当前版本和时间版本起始值均为 `202607301002`；`1.0.0` 作为迁移前旧版本标识保留。下游 Rust 产品继续使用根 `Cargo.toml` 的独立 SemVer 事实。
- 唯一性：同一分钟内如需产生第二个不同版本，等待下一分钟，不追加秒、时区或自定义后缀。
- 影响范围：`Version.md`、README、产品规格、产品状态、工作计划、`docs/RELEASE.md`、变更记录、`$prepare-release`、Harness 校验器与验证记录。
- 理由：时间版本可直接表达确定顺序，适合 Harness 高频维护；固定时区避免协作者所在地区造成版本歧义。
- 风险：分钟粒度限制同一分钟内的多版本发布；时间版本不表达兼容性语义；系统时间错误会生成错误排序。
- 验证：校验器解析 12 位版本并校验真实上海时区年月日时分、当前摘要一致性和下游排除契约；单元测试覆盖非法日期与旧固定 SemVer 回归。
- 恢复或调整标准：若真实发布需要兼容性语义或同分钟多版本，由项目负责人通过范围闸门批准新方案并记录迁移关系；不得静默回退或覆盖已发布版本。
