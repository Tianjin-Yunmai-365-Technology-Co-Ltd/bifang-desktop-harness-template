## ADR-20261030-001：统一无横滚 Grid 与原生中文排版基线

- 日期：2026-10-30；状态：Accepted；变更标识：`HARNESS-FEAT-GRID-TYPOGRAPHY`；`required_version = 202610301829`。本次正式发布将该变化绑定到此所需版本，发布状态以 Git 引用复核为准；当前版本仍由 [Version.md](../../Version.md) 管理。
- 确认来源：负责人提供完整 Grid/字体要求，并明确选择“完善 Harness 通用 Grid 与字体规范及中性资产”。该范围只维护模板，不包含具体产品或真实下游界面验收。
- 背景与决定：[通用 Grid](../design_standards/data_grid.md) 统一密度、无横向滚动、稳定排序/分页、选择范围、后台刷新、键盘和真实恢复；[UI 基座](../design_standards/ui_foundation.md) 补齐系统中文回退、语义字体层级、等宽数字、亮暗对比和文本缩放合同。Tauri 用现有列表/主题资产落实，GPUI 保留原生机制与职责隔离，不预建无消费者的 Rust 网格。
- 取代范围：仅取代原 Mantine 列表“强制带 minWidth 的局部横向滚动”和无条件每次挂载刷新；其他 offset、URL/session/Query、稳定 ID、列偏好、权限和薄适配边界继续有效。新鲜期由数据源显式声明，跨页选择数量与范围分离并确认查询指纹；既有下游消费新模板时须显式适配新增字段，不由升级覆盖产品代码。
- 理由与影响：避免窄窗口及文字放大时横向浏览和内容裁切，统一长时阅读排版；不增加依赖或业务动作。字体和颜色值集中于主题，完整值使用真实语义按钮及可访问浮层。
- 风险与验证：纯函数、组件与主题对比测试只证明中性资产行为和默认色板；支持系统的实际字形、显示缩放、真实窄窗口/200% 文本缩放、滚动性能与 E2E 均未执行。实际门禁结果在交付回复报告，不把 jsdom 当视觉证明。
- 恢复或调整标准：若下游出现列过密或字体回退问题，修正主题、列职责与完整行详情；新设计方向由用户明确修订，不通过裁切、隐藏不可达字段或恢复并行主题掩盖问题。

## ADR-20261028-003：当前设计基座统一权威并退役竞争风格

- 日期：2026-10-28；状态：Accepted；变更标识：`HARNESS-CHANGE-CURRENT-DESIGN-ONLY`；`required_version = 202610282034`。开发阶段不取时间版本；本次正式发布将已包含变化绑定到该版本，发布状态以 Git 引用复核为准。
- 确认来源：负责人明确要求检查整个 Harness，“所有的设计以当前设计规范为准，旧的相应抛弃、清理”。该指令修订此前为兼容旧像素而保留的设计优先级。
- 决定：`ui_foundation.md` 是当前唯一视觉规则来源；专项文档只补充相容的框架、交互、无障碍和数据/状态合同。展示值在 Tauri `appDesignTokens.ts` 与 GPUI `app/design_tokens/` 集中定义并被真实模板消费，删除独立像素表与局部配色，不用旧标识、旧 profile 或第三方审美恢复旧风格。
- 取代范围：取代本日 ADR-20261028-001 的“旧像素/尺度优先”和不改运行时主题的适配边界；取代 ADR-20260930-001 的 taste 自动安装/全接口保留，保留其既有下游资产保护；取代 ADR-20260827-003/004 的旧侧栏像素硬锁及普通像素调整的重复批准；ADR-20260919-002 的固定调色映射改由中央表格 Token 表达。其他数据、事件、权限、窗口/平台和无障碍约束继续有效。
- 实施：删除 taste installer、对应测试与完整 vendor 快照；退役页仅为历史链接导航，不进入活动设计索引。GPUI Kit 原文与许可不改，通过本地集成说明限定为 API/组件/原生交互知识；既有下游自有第三方目录继续 protected，不执行删除或重装。
- 真实模板：Tauri 强调色随 primaryColor，支持页和表格消费完整语义色，侧栏常用展示尺寸采用统一节奏；GPUI 卡片/标题/侧栏/支持页引用原生 Token，扫码白底作为媒体语义保留。原始支付媒体、业务能力、列表查询/分页/选择/存储合同均不扩张。
- 当前记忆：完整承接前一份 Harness 规格，修订其中竞争视觉约束与成功标准；同日 ADR/Changelog 反映最终有效结果。历史归档不改写，不把旧视觉证据改判为当前通过。
- 风险与验证：主题纯函数、渲染器和结构回归验证当前工程合同；同步移除会强制旧像素的机械断言，保留模式/偏好/事件/可访问名称检查。真实下游视觉、完整 GUI 构建和 E2E 未执行，最终报告给出实际检查结果。
- 恢复或调整：若存在视觉或兼容缺陷，修正中央 Token 和实际消费者；新方向由用户之后的明确指令修订基座。回退不得恢复并行风格权威、误删下游资产或绕过数据/可访问性约束。

## ADR-20261028-001：把统一 UI 基座纳入受管设计标准

- 日期：2026-10-28；状态：Accepted。
- 关联需求与确认：负责人提供《软件 UI-Harness 设计规范》v1.0，要求将风格烧入 Harness、自行选择知识库或 DESIGN.md 归属，并在完成后校验。
- 变更标识：`HARNESS-FEAT-UNIFIED-UI-FOUNDATION`；`required_version = 202610282034`。本次正式发布取号时物化；当前版本仍由 [Version.md](../../Version.md) 管理，发布状态以 Git 引用复核为准。
- 背景：已有框架和组件标准，但附件跨框架的一致性规则需要成为实际读取与传播合同；直接把完整规范复制到根文件会与受管目录及下游自有设计竞争。
- 决定：根 [DESIGN.md](../../DESIGN.md) 只作入口，[UI 统一设计基座](../design_standards/ui_foundation.md) 是共用规则唯一来源；设计索引、日常实施、Tauri/GPUI、初始化与升级共同接入。新下游复制入口，已有下游自有 DESIGN.md 继续 protected，升级直接接入标准索引。
- 后续取代：原先保留旧像素优先的适配已被本日 ADR-20261028-003 明确替换；Token/组件分层、业务范围、三态主题和工具依赖边界继续有效。
- 影响与理由：共用规范沿既有设计目录传播，候选遗漏或旧字节被阻断；升级保护下游自有设计。当前视觉及 taste 退役以 ADR-20261028-003 为准，列表存储与能力边界继续有效。
- 风险与验证：文档/入口校验和隔离升级回归只证明工程合同；真实下游的视觉、构建与 E2E 未执行。相关实际命令及结果在交付回复报告，不复用历史测试结论。
- 恢复或调整标准：发现与专项标准冲突时修正共用基座及对应入口；产品偏离仍按索引治理；需要撤销本次接入时从本分支变更恢复，不覆盖下游自有设计或改写历史批准。

## ADR-20261020-001：经明确授权提炼有效约束并完整归档历史快照

- 日期：2026-10-20；状态：Accepted。
- 关联需求与确认：负责人要求梳理整个 Harness、检查各平台知识库与方案，确认截止日期为 2026-11-20，并明确选择“先提炼有效约束，再将截止日前原文完整归档”。
- 变更标识：`HARNESS-MAINT-KNOWLEDGE-MEMORY-CONSOLIDATION`；分类为 maintenance。Harness 当前版本继续取根 [Version.md](../../Version.md)，本次不提升、不取号，也不改变 Git 发布事实。
- 背景：旧 ADR 与 Changelog 同时累积有效约束、已失效的子句和历史执行记录；逐条审查没有可以整体认定失效的旧 ADR。仅按日期删除将丢失仍有效的决定及真实证据。
- 决定与范围：本次一次性采用“有效约束完整映射 + 原始快照永久保留”。归档对象只包括本次任务开始时已存在、日期早于 2026-11-20 的 ADR/Changelog；本日新提炼快照不重复归档。每个旧 ADR ID 均在下表承接；Changelog 提炼当前能力并保留历史标识及证据入口。
- 例外与取代范围：负责人明确授权本次偏离 `desktop-curate-harness-memory` 仅迁移完全失效条目的通常准入，允许在有效约束已提炼、原文可逐字节恢复的前提下归档仍含有效子句的完整旧快照。本例外只适用于本次 Harness 自身记忆整理，不扩展通常清理规则、不向下游传播，不删除 Product Spec、Product Status、Work Plan、真实 Verification 或人工签署。
- 当前边界校正：GPUI Linux GNU x64/ARM64 已有独立 deb/tar.gz/local_package 路线；macOS/Windows 的 cargo-packager 为全局工具。CLI 候选默认当前宿主，矩阵须明确请求及满足远端来源门禁。Tauri Linux 托盘恢复以菜单为准，需安装的各平台 scheme 注册留给最终安装候选；Linux WebKitGTK/GTK 缺包不交给不具备该能力的通用 helper。详见相应现行规范。
- 历史远端强制子句的失效关系仍成立：同时取代 ADR-20260908-013“正式候选必须从已推送、带远端 tag 的提交构建”、ADR-20260908-007“本地/远端默认主分支与远端 tag 必须无条件一致”，以及 ADR-20260908-006“生命周期必须完成远端 push、构建只复核远端 tag”的远端强制子句。这不恢复旧的本地/远端双发布模式；当前 Git 发布仍止于本地主分支和同 HEAD 的 tag。
- 影响与理由：缩短当前读取入口，保留稳定 ID、当前约束、原始历史、失败和未执行事实；归档不是对旧候选重新批准，也不证明其他平台已验证。
- 风险与替代验证：摘要可能遗漏边界，故逐 ID 对照现行来源、检查全覆盖与本地链接，并对整个迁移源及原有归档前缀逐字节比对；历史版本绑定继续保留。实际检查结果由本次交付报告给出。
- 恢复或调整标准：若发现摘要漏项，先从原文与现行规范核对并补回当前快照；需要恢复旧日期文件时从归档的精确字节恢复，既有归档只追加、不改写。今后整理仍按通常 Skill 准入，其他整快照归档需新的明确授权。
