# 2026-08-04 ADR

## ADR-20260804-001：为 Tauri GUI 增加 macOS 原生与 Windows xwin 候选，并把 Developer ID 签名与公证合并

- 日期：2026-08-04
- 状态：Accepted
- 关联需求：项目负责人要求构建 Skill 在 macOS 宿主支持通过 pnpm/Tauri/xwin 交叉编译 Windows，缺少环境时先补齐；设备和授权条件允许时，macOS 安装包必须签名并公证，而不是只签名。
- 背景：现有 `$build-rust-release` 与原生三平台矩阵只覆盖 Rust CLI raw binary，Tauri GUI 仍由适配器临时处理。CLI 的二进制签名钩子、单归档字段和原生运行器语义无法可靠表达 macOS 宿主上的 Windows NSIS 交叉候选，也无法表达 Apple Developer ID 签名、公证、ticket stapling 后才形成最终安装包字节。
- 决定：保留 `$build-rust-release` 和 `$prepare-cross-platform-release` 的 CLI 原生矩阵边界，新增 `$build-tauri-release`。该 Skill 在 macOS 构建原生 DMG，并在批准 Windows x64 目标时使用 `pnpm tauri build --bundles nsis --runner cargo-xwin --target x86_64-pc-windows-msvc` 生成 NSIS；macOS 不生成 WiX/MSI。xwin 结果必须标记 `cross-compiled-xwin` 和 Windows runtime `Unverified`。
- 环境决定：扩展 `$check-development-environment` 的 macOS 发布门禁，以确定性脚本探测并在缺失时安装 LLVM/LLD、NSIS、Windows Rust target 与 `cargo-xwin`，随后复探。脚本只使用既有 Homebrew、rustup 和 Cargo 的官方稳定安装路径；不得自动安装 Homebrew、静默升级已有不兼容工具或通过远程 shell 文本绕过门禁。
- macOS 决定：面向直接分发的 Developer ID 候选把签名、公证和 stapling 视为不可拆分阶段。只有 Apple 设备、Developer ID Application 身份、完整的 App Store Connect API 或 Apple ID 公证凭据、`notarytool`/`stapler` 和既有授权全部就绪时才执行；命令不得使用 `--skip-stapling`。最终签名、公证、stapling 和验证完成后才计算 SHA-256。
- 降级决定：只具备签名而不具备公证/stapling 时不得产出“仅签名”的 Developer ID 候选。渠道允许 unsigned 时显式使用 `--no-sign` 并记录原因；渠道要求签名公证时阻断。任一尝试开始后失败不得回退 unsigned。
- 清单决定：Tauri 候选增加接口、安装包类型、bundle 格式、原生/交叉构建模式、宿主/目标、runtime 验证、签名作用域和结构化公证状态/理由/证据；收集、验收和发布准备必须验证这些字段。stapling 改变最终字节，因此摘要和后续验收只绑定 stapled 结果。
- 影响范围：产品规格、AGENTS/README、GUI/环境/构建/收集/验收/发布 Skills、发布与 GUI 基线、环境脚本和测试、Harness 校验器、升级受管清单、技术债、验证证据和变更记录。不改变 CLI 原生工作流文件及其受审摘要。
- 不包含：不自动创建、索取、导出或输出 Apple/Windows 凭据；不自动安装 Homebrew；不生成 Windows MSI；不把 xwin 构建当作 Windows 原生运行证据；不增加 Linux GUI 交叉构建、TUI/MCP 发布模型、商店提交、标签、上传或正式发布。
- 理由：CLI raw binary 与 Tauri 安装包在工具链、签名作用域、产物结构和平台证明上不同，独立 Skill 能保留已验证 CLI 契约并为 GUI 提供清晰门禁。把 Developer ID 签名、公证和 stapling 放在同一候选阶段，可避免验收后再改变字节或交付一个 Gatekeeper 不完整的只签名产物。
- 风险：cargo-xwin/NSIS 路线是 Tauri 官方注明的有条件兜底能力，不能证明 Windows 运行时；Homebrew/Cargo 安装可能因权限、网络或供应链策略失败；Apple 公证依赖付费开发者身份、服务可用性和机密凭据；当前 Harness 没有真实 Tauri 产品，无法在本仓库完成真实 DMG/NSIS/公证前向验证。
- 验证：为环境脚本增加隔离正负向回归，为新 Skill 增加 macOS/xwin、MSI 拒绝、只签名中间态拒绝、摘要顺序和秘密不输出的静态契约检查；运行相关 Python/Shell 测试、Skill 结构验证、`python3 scripts/validate_harness.py` 和 `git diff --check`。真实 xwin、Windows 运行、Developer ID 签名、公证和 stapling 保持 `Unverified`。
- 恢复或调整标准：若真实下游证明 xwin 不能稳定生成所需 NSIS，则保持清单和不误报边界，退回 Windows 原生运行器；若 Tauri 或 Apple 改变签名公证接口，更新受测环境探测和最终字节顺序，但不得恢复只签名 Developer ID 候选或把交叉构建冒充原生运行。
- 替代关系：本决定扩展 ADR-20260803-001 的构建范围，并局部取代其中“构建不执行公证”和“GUI 仅由适配器处理”的表述；CLI 原生矩阵、release 原子刷新、候选 pending 与不授权发布等其余决定继续有效。
