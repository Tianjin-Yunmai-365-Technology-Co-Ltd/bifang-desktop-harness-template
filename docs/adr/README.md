# ADR 索引

本目录是已确认需求与重要工程决定的唯一正文来源。

## 写入规则

- 文件名固定为 `YYYYMMDD_ADR.md`，日期使用需求确认所在时区的自然日。
- 每个已确认需求写成独立 `ADR-YYYYMMDD-NNN` 条目；同一天不得新建第二个 ADR 文件，而是在当日文件顶部追加并更新本索引。
- 条目至少包含状态、关联需求、背景、决定、影响范围、理由、风险、验证或替代验证，以及恢复或调整标准。
- 需求确认时同步检查产品规格、相关设计或接口文档、项目状态和工作计划；无需修改时在条目中记录不适用理由。
- 已发布版本、真实人工复核和真实验证事实不得回写删除。
- 同一未发布日期内，被后续决定完全替代且会污染当前检索的旧规范可以合并成最新有效描述；必须在当日新增独立 ADR 条目说明合并范围、风险和恢复依据。
- 新下游项目在产品规格仍为 `Draft` 且尚无确认需求时可以只有索引；规格转为 `Approved` 前必须创建首个当日 ADR。
