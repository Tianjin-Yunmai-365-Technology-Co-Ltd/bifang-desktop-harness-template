## ADR-20260722-012：下游项目必须拥有独立 Git 根

- 日期：2026-07-22
- 状态：Accepted
- 决定：`$instantiate-project` 在目标根执行 `git init --initial-branch=main .`；直接调用 `$initialize-rust-project` 时，若当前根不是独立 Git 顶层目录，也必须在脚手架写入前建立相同边界。即使目标位于父仓库内，下游 Git 顶层目录仍须精确等于项目根。
- 边界：不得复制源 `.git`，不得自动提交、创建标签、配置远端、推送、创建托管仓库或签名。Git 缺失、不支持初始分支参数、初始化失败或 Git 顶层目录不匹配均阻断。
- 验证：检查 `inside-work-tree`、规范 Git 顶层目录、`main` 符号引用 HEAD、尚无提交的 HEAD 和初始未跟踪状态。Windows/Linux 及完整真实下游复制仍为 `Unverified`。

## ADR-20260722-011：固定 TUI 与 React 前端技术族

- 日期：2026-07-22
- 状态：Accepted
- 决定：TUI 固定使用 Ratatui、tui-realm、tui-realm-stdlib；WEB 与 Tauri 2 GUI 前端固定使用 React、TypeScript、Mantine UI、TanStack Router、TanStack Query、Jotai。Query 管理异步状态，Jotai 只管理跨组件客户端交互状态，权威业务数据留在共享核心/存储中。
- 边界：技术族在 Draft 与 Approved 状态都适用。实际版本须满足 MSRV、Node、浏览器/WebView、三平台、安全与完整验证门槛；偏离需要硬规则例外 ADR。
- 验证：真实 TUI/WEB/GUI 下游完成依赖解析、锁定、代码规范检查、非空测试、生产/发布构建、真实产物启动和交互前保持 `Unverified`。

## ADR-20260722-010：通过 Computer Use 验收真实最终产物

## ADR-20260722-008：五类接口独立可选，空选择默认 CLI

- 日期：2026-07-22
- 状态：Accepted
- 决定：初始化询问 CLI/TUI/MCP/GUI/WEB，可单选或多选；显式选择时只创建所选适配器，空选择才默认 CLI。五类适配器各由独立 Skill 负责，直接依赖共享核心，彼此不依赖、不启动也不解析输出。
- 边界：CLI 契约只在选择 CLI 时适用。随附的 `rust-lib-cli` 只证明默认 CLI 路径，不构成全局 CLI 要求。Draft 项目只能暴露中性脚手架状态。
- 验证：CLI 资产已在 macOS 验证；TUI/MCP/GUI/WEB 脚手架与多接口组合仍为 `Unverified`。

## ADR-20260722-007：Windows 缺失 MSVC 构建工具时自动安装

- 日期：2026-07-22
- 状态：Accepted
- 决定：Windows 门禁探测 `cl` 与 `vswhere`；缺失时下载 Microsoft 官方构建工具引导安装程序，验证有效 Microsoft Authenticode 签名，安装 C++ 工作负载并复探。只有复探成功才报告通过。
- 风险：安装需要网络、磁盘、权限并可能触发组织策略或重启；任一失败均阻断。
- 验证：静态契约和 Python 回归测试已通过；Windows 原生签名、安装、3010 与复探仍为 `Unverified`。

## ADR-20260722-006：先中性初始化，再定义产品

- 日期：2026-07-22
- 状态：Accepted
- 决定：实例化只要求项目名称、ASCII `snake_case` 标识、完整目标目录、负责人和目标平台。产品目的、核心输入输出、成功标准和风险可保持 `待确定`。Draft 项目可先创建共享核心与所选适配器，但只能暴露 `scaffold status` 或等价可观察状态，并报告 `productDefinitionRequired=true`。
- 边界：产品规格批准前不得猜测业务逻辑或副作用，也不得发布或声明产品交付。之后必须依次使用 `$define-product`、`$plan-change`、`$implement-change` 替换中性状态。

## ADR-20260722-004：目标目录由用户明确提供

- 日期：2026-07-22
- 状态：Accepted
- 决定：`$instantiate-project` 必须取得完整目标目录路径；相对路径以 Harness 根解析。解析后的目标目录基本名称必须等于项目标识，目标须不存在或为空，不得是 Harness 根或祖先，也不得经符号链接落入禁止位置。目标可以位于 Harness 内或外。
- 安全边界：复制前固定源文件清单，排除源 `.git`、目标本身、其他下游、缓存、构建产物和本机状态，防止覆盖、碰撞与递归复制。完成后目标根是后续工作的唯一项目根。

## ADR-20260722-003：单一项目根 Cargo 工作区

- 日期：2026-07-22
- 状态：Accepted
- 决定：首次 Rust 脚手架在当前下游项目根创建唯一工作区 `Cargo.toml`，登记共享核心与实际选择的适配器；未来新增 crate 继续由同一根清单管理，不创建第二项目树。

## ADR-20260722-002：Rust 2024 共享核心与适配器基线

- 日期：2026-07-22
- 状态：Accepted；MSRV 部分已由 ADR-20260723-001 替代
- 当前有效决定：默认 Rust 2024、MSRV 1.90、Tokio 适配器、运行时中立的共享核心。根 `[workspace.dependencies]` 是全部 Rust 成员第三方依赖和内部路径的唯一来源，成员只使用 `workspace = true`。Cargo.lock 固定解析结果。MSRV 的现行理由、兼容影响和验证以 ADR-20260723-001 为准。
- 边界：只有真实业务需要 Tokio 原语时核心才增加 Tokio 生产依赖；不得默认启用 `full`。依赖版本采用满足 MSRV、平台、最小特性集和完整验证的较新稳定版本。

## 当前基础决定

- 模板产品规格已于 2026-07-21 由项目负责人批准；Harness 根保持无具体产品代码。
- AI Agent 是第一消费者，人类负责方向、范围变化、破坏性操作审批和最终复核。
- 模板版本为 `0.1.0`、尚未发布；版本提升由用户决定。
- 下游当前系统必须完成编译、非空单元测试、真实最终产物存在和启动冒烟；测试覆盖核心成功路径与最高风险失败路径。未运行平台为 `Unverified`。
- CLI 被选择时必须遵守统一 JSON 信封、标准输出/标准错误分离、稳定错误码、退出码和非交互行为。
- 初始化门禁使用 Skill 自带 POSIX 命令解释器或 PowerShell 脚本；Rust 与 Node.js 阻断，Windows MSVC 阻断，Python 3 可选。
- 工程规则以 `docs/ENGINEERING_RULES.md` 为唯一详细来源；硬规则例外必须记录理由、风险、范围、替代验证和恢复标准。
- 候选工作流只生成证据和制品，不自动创建标签、发布到软件包仓库或提升写权限。
- 人工最终复核必须写入 `docs/VERIFICATION.md`，Agent 不得代签。
