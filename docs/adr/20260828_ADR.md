## ADR-20260828-002：初始化首轮集中收集基础字段，条件配置随后按需逐项补全

- 日期：2026-08-28；状态：Accepted。
- 关联需求：项目负责人明确要求“初始化时，一次问出全部基础问题，之后再逐步按需补全其他问题”，以减少固定信息被拆成多轮问答造成的等待，同时保留条件配置的可理解决策顺序。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-BATCHED-BASE-INITIALIZATION-FORM`；`required_version = 202608281139`。该值是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 基础字段决定：新下游实例化的固定基础字段恰好是项目展示名、ASCII `snake_case` 标识、项目路径、负责人、目标平台、接口组合和 Agent 策略模式。Agent 必须先复用当前请求中已合法提供的值，再在首轮用清晰编号一次列出其余全部基础字段；不得拆成逐字段多轮，也不得用不列字段的笼统问询替代。首轮回复有缺失或非法值时，集中说明仍需修正的基础字段与各自约束，合法字段不重问；基础字段全部解析前不进入条件阶段。
- 条件字段决定：选择自定义策略后，`superpowers`、`parallel_worktree_subagents`、`milestone_smoke`、`milestone_e2e` 每轮补全一个；选择 GUI 后，`system_tray`、`about_page`、`sponsor_page`、`single_instance`、`sidebar_mode` 每轮补全一个。不适用字段直接标记为不适用，不制造问询。GUI 四项能力仍须明确为 `enabled|disabled`，侧栏明确跳过时仍归一化为 `detailed`，显式非法值仍须重问。
- 直接初始化决定：`$desktop-initialize-rust-project` 不经实例化表单直接调用时，把尚未解析的接口组合与 Agent 策略模式放在同一首轮；只有基础决定完成后，才逐项询问自定义策略或 GUI 条件字段。由 `$desktop-instantiate-project` 发起时继续复用写入前完整表单，复制后不重复询问。
- 确认与写入边界：条件字段全部解析后，仍须运行只读路径 helper，并展示包含输入路径、唯一目标根、派生前缀、接口、策略和适用 GUI 五项配置的完整汇总；用户确认前继续禁止目录创建、复制、环境安装、Git 初始化或文件修改。
- 取代与保留范围：本决定取代同日未发布中间状态 `HARNESS-FEAT-STEPWISE-INSTANTIATION-FORM-PATH-RESOLUTION` 中“全部字段每轮只问一个”的交互方式，并以新的稳定变更标识描述当前行为。项目路径的父目录/最终根确定性解析、安全门禁、完整汇总确认、推荐策略配方、GUI 显式能力选择和 `pending` 禁止规则全部保留。
- 理由：展示名、标识、路径、负责人、平台、接口和策略模式彼此都是创建意图的固定轮廓，集中展示能让用户一次校对全貌；自定义策略和 GUI 能力是否适用取决于首轮选择，保留逐项条件问询可避免一次展示无关配置，并给每项有副作用的生命周期决定足够上下文。
- 影响范围：初始化表单参考、`$desktop-instantiate-project`、直接调用的 `$desktop-initialize-rust-project`、两项 Skill UI 元数据、AGENTS/README、Agent Policy、Rust 初始化基线、最新 Product Spec、当日 Changelog、Harness 契约片段和初始化专项回归。
- 风险与缓解：首轮字段过多可能导致漏答或格式混乱；通过固定七项、清晰编号、合法值预填复用和只集中补齐无效基础字段降低风险。若条件字段提前出现，可能把不适用配置误当必填；通过基础阶段完成门禁、显式阶段标签和结构回归阻止。集中首轮不授权写入，完整汇总确认仍是唯一写入闸门。
- 验证：Harness 回归必须解析初始化表的阶段列，证明前七项均为“首轮基础”、其余均为“条件补全”，并检查实例化与直接初始化入口保留相同阶段顺序；完整 validator 同步拒绝缺失的首轮集中问询或条件逐项语义。两个修改 Skill 另通过 Skill Creator quick validator。
- 恢复或调整标准：若真实初始化证明七项首轮表单在目标界面不可可靠提交，项目负责人可以明确调整基础字段集合、分组或交互载体；任何调整都必须继续复用合法输入、区分固定与条件字段、保留完整汇总写入闸门，并同步表单、Skills、Product Spec、ADR 与回归，不能静默退回所有字段逐轮询问。

## ADR-20260828-001：左侧 Task 以独立 Worktree、codex 分支和可审查提交交付单一结果

- 日期：2026-08-28
- 状态：Accepted
- 关联需求：项目负责人明确要求把“一个左侧 Task = 一个明确目标 + 一个独立 Worktree + 一个 `codex/*` 分支 + 一组可审查提交”设为核心约定，并统一 Task 的动作结果标题、描述内容、基线、提交、验收、主任务整合与清理规则。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-INDEPENDENT-TASK-WORKTREE-DELIVERY`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 事实依据：OpenAI Docs 要求为每个 distinct outcome 建立独立 chat，并建议用描述 outcome 的短标题；Codex Worktree 从所选分支的当前 HEAD 建立，默认处于 detached HEAD，之后可用 `codex/` 前缀创建分支，Codex 管理 Worktree 通常专用于一个 chat（[Projects and chats](https://learn.chatgpt.com/docs/projects)、[Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)，核对日期：2026-08-28）。仓库规则不能修改 Codex 桌面应用的全局 UI 默认值，因此本决定约束 Agent 创建左侧 Task 时必须显式选择项目 Worktree；人工手动新建仍需在界面中选择 Worktree。
- 核心决定：每个用户可见左侧 Task 只承载一个可独立验收结果，标题使用“动作 + 结果”。Task 描述固定包含目标、工作方式、当前事实、必须阅读的项目文档、实施范围、禁止事项、验收标准和交付要求；各节写入当前真实值，不适用项明确标记，不得删除必填节后留下隐含边界。
- 基线与分支决定：新 Task 默认从主任务已同步并确认的最新本地 `main` HEAD 创建。存在远端时先获取引用并完成安全快进；Local 主工作目录有修改时，主任务先审查差异、排除秘密/生成物并提交已确认基线。没有 `main`、存在分叉、修改无法安全归属或无法提交时停止，不回退到当前分支、`master` 或 Codex 的未提交修改复制能力。Worktree 创建后在首次编辑前建立唯一 `codex/<task-slug>` 分支并核验实际 Git 根。
- 执行与提交决定：Task 只修改自己的 Worktree，不进入 Local 主目录或其他 Task Worktree；每个逻辑闭环形成结果导向提交。交付前必须完成任务要求的测试与权威文档同步，提交全部修改并保持 `git status --porcelain=v1 --untracked-files=all` 为空；`target/`、`node_modules/`、`dist/`、`__pycache__/` 和其他生成缓存不得提交。适用目标必须编译并验证真实目标行为；没有可编译目标或最终候选不在范围内时明确报告 `Not applicable`/`Not run`，不自动扩张构建、E2E 或完整验收。
- 权限与整合决定：Task 不覆盖 `/Applications` 中的最终应用，不删除其他 Worktree，不合并 `main`，也不执行未授权推送、发布、签名或外部副作用。Task 交付分支、提交哈希、实际验证、未执行项和剩余风险；主任务复核后整合到 `main`，只有状态干净且提交已成为 `main` 祖先后，才由主任务依次移除 Worktree 和安全删除分支。
- 层级决定：`parallel_worktree_subagents` 只控制单个左侧 Task 内部是否允许显式并行 Subagent，不控制左侧 Task 是否使用 Worktree。Task 内并行继续使用 `$desktop-run-parallel-worktrees` 的 `codex/<task>/<unit>` 临时单元分支和边界 guard；它不得让两个左侧 Task 共用工作树，也不得替代 Task 自身的 `codex/*` 交付分支。
- 影响范围：最新 Product Spec、`docs/AGENT_POLICY.md`、AGENTS/README、日常实施与并行 Worktree Skills、实例化/初始化的保留规则、Harness validator、专项回归和当日 Changelog。
- 不包含：不修改 Codex 桌面应用二进制或用户全局设置，不自动 fetch/pull/push，不重命名当前 Harness 源仓库仍在使用的 `master` 分支，不授权 Task 自行合并/删除/发布，也不因 Task 模板存在而自动启动 Subagent、构建或完整验收。
- 风险：错误地把“最新 main”理解为任意当前分支会产生过时或分叉基线；自动提交未审查修改可能混入秘密；Task 自行清理会丢失未整合提交；把 Task 级 Worktree 与 Subagent 单元 Worktree 混为一层会造成分支和所有权冲突。通过 main 缺失/分叉失败关闭、基线审查、独立分支、干净交付、主任务复核和整合后清理顺序降低风险。
- 验证：Harness validator 必须机械检查 Agent Policy 模板、AGENTS/README 入口、实施 Skill 收口、并行 Skill 分层及初始化保留要求；Python 回归覆盖必填描述节、`codex/*`、干净状态、禁止自行合并和主任务清理语义。文档链接和 `.gitignore` 继续由完整 Harness validator 检查。
- 恢复或调整标准：若 Codex 官方 Worktree/branch/Handoff 行为变化，或真实多仓项目证明 `main`、一 Task 一 Worktree、提交粒度或清理顺序不再安全，项目负责人须用新的明确规则说明替代基线、所有权、迁移和恢复条件；不得通过共用 Worktree、复制未提交状态或提前强制删除形成隐式例外。

## ADR-20260827-004：固定详细侧栏 248/76 两态并由 AppShell 同步主内容偏移

- 日期：2026-08-27；状态：Accepted。
- 关联需求：项目负责人明确批准 `sidebar_mode = detailed` 的运行时标准，要求保持 `248px` 展开、`76px` 收起与 `72px`/`44px` Logo，统一使用 `22px`/`1.75` Tabler 菜单图标，禁止套用 compact 运行时或任何旧精简密度，并修复 fixed 侧栏变化后 Mantine AppShell 主内容偏移未同步的缺陷风险。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-DETAILED-SIDEBAR-RUNTIME-SYNC`；`required_version = 202608051301`。这是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 设计事实：`sidebar_mode = detailed` 命中 `tauri-gui-sidebar-detailed-v1`。首次默认展开，展开为 `248px`、`72px` Logo、图标左/名称右；收起为 `76px`、`44px` Logo、icon-only，名称只通过 `position=right`、`openDelay=0` 的 Mantine Tooltip 揭示。两态菜单图标固定 `22px`/`1.75`；展开菜单项 `44px` 最小高度和 `sm` 横向 padding，收起左右 padding 与 section margin-inline 为零；身份区使用 Mantine `xs` padding，折叠图标为 `18px` 的 `IconChevronLeft`/`IconChevronRight`。
- 状态与壳层决定：折叠偏好只使用 `app.sidebar.detailed.collapsed`；读取时只有字符串 `"true"` 表示收起，其余状态一律展开。AppShell 用 `readDetailedSidebarCollapsed()` 初始化并拥有状态，以 `detailedSidebarNavbarWidth()` 同时驱动侧栏宽度、Mantine `navbar.width` 与 `data-navbar-width`；`AppSidebarTemplate` 只接收受控状态，并从自身 `ActionIcon` 调用 `onCollapsedChange(nextCollapsed)`。该偏好不得进入 Jotai 页面会话 store、URL、TanStack Query、shared core 或业务持久化。
- 交互决定：折叠事件只属于 `data-testid="app-sidebar-collapse-toggle"` 的 ActionIcon；Logo、版本和身份区父级不代理。展开菜单项标记 `icon-with-label` 并渲染 i18n 名称且不使用 Tooltip；收起菜单项标记 `icon-only`、不渲染可见名称节点并保留完整 `aria-label`。导航仍由实际 NavLink/button 自身拥有点击和 active。Logo 只能使用 `/app-identity/logo.png`，展示版本统一规范为一个小写 `v`。
- 模板与门禁：新增受管 `AppShellTemplate.tsx` 作为 detailed 运行时接线参考，把 detailed 状态从 `AppSidebarTemplate` 内部提升到 AppShell；React 回归覆盖默认 248、身份父级无动作、ActionIcon 后 76 与主区偏移同步、Tooltip 和重挂载恢复；Node GUI 生命周期检查器与 Python Harness 合同拒绝固定 248 偏移、30px detailed 图标、父级代理或缺少回调接线。
- Profile 边界：Harness 根不是已实例化 GUI 产品，因此不创建虚假的 `docs/GUI_APP_PROFILE.md`。下游初始化仍由 `$desktop-prepare-gui-app-identity` 把 `sidebar_mode = detailed` 和 `tauri-gui-sidebar-detailed-v1` 写入真实产品 profile；任何像素或模式偏离必须由用户另行批准，并同步该产品 profile 与 ADR。
- 取代范围：本决定只取代 ADR-20260827-001 对 detailed 实现细节的较粗描述，以及 ADR-20260827-003 中“detailed 保持不变”的保留说明；compact 的 `tauri-gui-sidebar-compact-80-v1`、未选择模式时归一化为 detailed、支持页条件与顺序均不变。
- 理由与风险：fixed 侧栏自行折叠而 AppShell 仍保留旧宽度会留下空白或遮挡内容；双份内部状态也会造成刷新与渲染漂移。单一 AppShell 状态和共享宽度 helper 消除该分叉。风险主要是模板被 compact 产品误接或存储异常；通过固定 detailed wrapper、profile 模式门禁、严格 `"true"` 读取和不可用时展开缓解。
- 验证边界：Harness 仓库没有可启动的下游 Tauri 应用或前端包清单，本次只能运行受管 React 测试源码的结构验证、Python 合同和 Node 生命周期回归，不能把它们声称为真实窗口证据。首次命中该标准的下游初始化仍必须运行相关 Vitest，并在真实本机窗口观察展开横排、收起后主内容扩展和 Tooltip。
- 恢复或调整标准：模式、像素、图标尺寸、存储键、状态所有权或 AppShell 同步方式的任何变化都必须先取得项目负责人明确批准，再同步设计标准、下游 GUI profile、ADR、模板和回归；不得静默改回 compact、80/108/136px detailed 宽度或内部双份折叠状态。

- 验证：React 模板、Python Harness 合同和 Node.js GUI 生命周期检查器同时锁定新数值、全宽居中、无固定 `em/ch` 盒、fixed/`100dvh`/边框、AppShell 宽度/padding 与 detailed 不漂移；本轮只运行相关单元/结构检查，不生成 Tauri 候选或真实 GUI E2E 证据。
- 恢复或调整标准：任何像素、密度、结构或匹配优先级变化都需项目负责人明确批准，并同步新 ADR、设计标准、下游 GUI profile、模板和回归；不得静默恢复旧 compact 密度或把 compact 数值传播到 detailed。

## ADR-20260827-002：新增 Harness 自身记忆历史治理机制，`_history.md` 补充 ADR-20260805-004

- 日期：2026-08-27

- 关联需求：项目负责人要求为更好地让本项目自举，增加一个不派生到下游的技能，把 ADR 等按日记忆文件中此前仍在沿用的设定和思路整理进一份 `{ADR|Changelog|...}_history.md`，并清理过期部分，便于人类追溯和阅读。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-CURATE-MEMORY-HISTORY-SKILL`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 背景：ADR-20260805-004 把 ADR/Changelog/Work Plan/Product Status/Product Spec 五类按日记忆收敛为只保留日期最新文件、历史交给 Git，理由是同一批决定被跨多个历史日期文件反复复述、检索噪音上升。但 ADR、Changelog 自身的写入规则要求当前最新文件综合携带此前仍然有效的条目（例如当前 `docs/adr/20260827_ADR.md` 累积了 27 条 ADR-YYYYMMDD-NNN，多数标题已标注被更晚条目部分取代），只保留最新文件并不能阻止这份文件本身随时间单调增长；Work Plan、Product Status、Product Spec 三类按各自规则整篇重写为当日完整快照，不逐条累积，没有同类问题。
- 决定：新增 `$desktop-curate-harness-memory` 技能，只治理 Harness 根目录自身的 `docs/adr/`、`docs/changelog/`：当当前最新文件行数超过人工维护文本 500 行建议重构阈值，或项目负责人明确要求时，把已被后续决定完全取代、且在全仓检索确认不再被任何当前规范文档（`AGENTS.md`、`docs/ENGINEERING_RULES.md`、`docs/RUST_CLI_TEMPLATE.md`、`docs/RELEASE.md`、`docs/VERIFICATION.md`、任何 Skill/参考文档）引用的过期条目原文，一字不改追加到同目录 `ADR_history.md`/`CHANGELOG_history.md` 末尾，随后从当前最新文件删除该条目；`_history.md` 只追加、不重写、不删除，是从当前最新文件迁出的完整过期条目原文的永久存档，用于降低当前文件的阅读噪音，同时不依赖 `git log` 即可读到仍有意义的历史叙事。只标注“部分取代”而未被完整取代声明覆盖、或存在任何未判定清楚的条目，一律保守保留在当前文件，不得整条迁移；无法判定的条目在完成报告中列为候选交人工复核，不自动迁移。
- 不适用范围：不改变 ADR-20260805-004 对 Work Plan、Product Status、Product Spec 三类的“只保留最新文件、历史交给 Git”规则；三类文件不产生 `_history.md`。不改变 `docs/verification/` 与 `docs/verification/human_review.md` 的独立保留规则。不追溯要求本次立即对现有 27 条 ADR 条目执行迁移；当前最新 ADR 文件 461 行仍低于 500 行建议阈值，本决定只建立机制，实际迁移留待阈值触发或项目负责人下次要求时按 Skill 规则执行。
- 派生边界决定：`$desktop-curate-harness-memory` 与其可能产生的 `ADR_history.md`/`CHANGELOG_history.md` 一律不进入 `$desktop-instantiate-project` 复制清单，`docs/adr/`、`docs/changelog/` 本身在实例化时已被排除复制；下游从零积累自己的记忆，没有可迁移的历史条目，也不得保留、复制或独立重建该 Skill。
- 理由：一份不断膨胀、包含大量已被部分取代条目的“最新” ADR 文件既不符合 ADR-20260805-004 降低检索噪音的初衷，也让人类维护者难以分辨哪些规则仍在直接约束当前行为；引入只追加的 `_history.md` 作为当前文件的过滤视图，能在不违反“只保留最新文件、历史交给 Git”硬规则的前提下，把降噪目标同时应用到条目级别，且完全不损失可追溯性。
- 风险：机械按日期或标题关键词判断“过期”容易误删仍在依据的字段，尤其是本仓库大量条目采用“部分取代、部分继续有效”的写法；`_history.md` 本身也可能随时间变得很长。通过要求逐字段核对取代声明、无法判定时保守保留并列为候选、只追加不改写、超过 2000 行硬上限时按既有拆分惯例续卷等约束降低风险。
- 验证：新增 Skill 结构与 `agents/openai.yaml` 通过 `python3 scripts/validate_harness.py` 的 Skill/UI 元数据/Markdown 链接检查；`$desktop-instantiate-project` 复制排除清单同步更新并人工核对措辞一致；`docs/adr/README.md`、`docs/changelog/README.md`、`docs/ENGINEERING_RULES.md`、`AGENTS.md` 交叉引用一致，无需新增机械回归即可通过既有 158 项必需文件与链接完整性检查。本轮不产生真实 `_history.md` 文件，机制验证以静态一致性核对与既有 validator 通过为准。
- 恢复或调整标准：若项目负责人认定该机制不必要或产生了新的检索噪音，可通过新 ADR 废止 `$desktop-curate-harness-memory` 并要求已产生的 `_history.md` 内容通过新 ADR 明确处理方式（不得静默删除）；若需要扩展到下游或 Work Plan/Product Status/Product Spec，必须由项目负责人明确批准并记录新的适用范围。除非被新的明确决定替代，本决定持续有效。

## ADR-20260827-001：GUI 初始化改为显式能力选择并以详细侧栏作为缺省模式

- 日期：2026-08-27
- 状态：Accepted
- 关联需求：项目负责人要求选择 GUI 后再单独询问是否需要系统托盘、关于页、赞助页和单实例，并允许侧栏选择精简或详细模式；用户未选择侧栏时默认采用详细模式。托盘启用时关闭窗口不退出，托盘禁用时关闭最后一个窗口退出；详细侧栏默认展开、可折叠并持久化，折叠后通过 Tooltip 显示名称。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-GUI-INITIALIZATION-CAPABILITY-SELECTION`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 问询与事实源决定：用户选择 GUI 后，初始化器必须进入独立问询轮，逐项解析 `system_tray`、`about_page`、`sponsor_page`、`single_instance` 为 `enabled|disabled`，并提供 `sidebar_mode` 的 `compact|detailed` 选择。四项能力不得根据旧默认、推荐策略预设、页面数量或 Agent 偏好推断；用户省略、留空或跳过侧栏选择时，初始化器必须在写 profile 前确定性归一化为 `sidebar_mode = detailed`。明确选择 `compact` 或 `detailed` 时保持原值；显式非法值不是“未选择”，必须重新确认。归一化后的五项原子写入 `docs/GUI_APP_PROFILE.md` 唯一 `gui-initialization-config` 代码块，初始化基线提交前不得缺失或残留 `pending`；后续 GUI Skill 与检查器只消费完整 profile，不重复推断。
- 托盘与关闭决定：`system_tray = enabled` 时，既有非透明应用图标、稳定双项菜单、运行时 i18n、关闭隐藏、托盘左键/显示项恢复和退出项结束应用的完整契约继续作为硬门禁。`disabled` 时不得启用 `tray-icon` feature、安装托盘、保留托盘菜单/locale 资源或注册关闭隐藏处理；改由 `.on_window_event(...)` 接入主窗口 `CloseRequested` 并显式调用 `AppHandle::exit(0)`，以 `close_last_window_exits_application` 与真实本机关闭场景锁定跨平台关闭退出。
- 单实例决定：`single_instance = enabled` 时，官方 `tauri-plugin-single-instance` 首插件、只恢复既有主窗口的中性回调、两个固定命名回归和真实双启动唯一性继续作为硬门禁。`disabled` 时不得声明依赖、注册插件、保留回调或执行双启动场景。文件关联、深链和启动参数转发仍需以后独立批准并交给 core 判定业务语义。
- 页面与资源决定：动态标题、`/settings`、语言与三态主题、亮暗语义主题是所有 GUI 的固定基线。`about_page`、`sponsor_page` 各自决定对应路由、导航入口、React 组件和运行时资源；禁用时不得保留隐藏路由、不可达组件或无入口媒体。选择关于页时保留检查更新、近五版更新日志、作者/联系人/免责声明及既有零出站边界；选择赞助页时完整 sponsor 媒体进入 bundle，禁用时这些媒体只保留在 Harness Skill 源资产而不进入下游运行时 bundle。
- 侧栏决定（compact 像素/排版已由 ADR-20260827-003 取代）：`compact` 原固定为 `136px`、`56px` Logo、`30px` 图标与 `11px`/`10em` 名称；该旧密度不再具有当前效力。`detailed` 首次默认 `248px` 展开，使用 `72px` Logo 与图标+名称横排；拥有该动作的 ActionIcon 可收起为 `76px`，收起后使用 `44px` Logo、只显示图标并通过 Mantine Tooltip 显示名称。详细模式折叠偏好使用独立 local-storage 键跨重挂载和下次启动恢复，不进入页面会话 Jotai store；菜单仍具有完整可访问名称、选中态和焦点。
- 导航决定：产品功能项从顶部向下增长，底部按“已选赞助、固定设置、已选关于”的视觉顺序生成。未选页面既不占空位也不保留不可达入口。两种侧栏均直接使用 `@tabler/icons-react` 命名组件，Logo、图标和文字沿同一中心线且无裁切。
- 验证决定：`verify-gui-lifecycle-contract.mjs` 必须解析五项 profile，对启用能力验证原有完整结构与有断言命名回归，对禁用能力验证依赖、feature、插件、运行时、路由与资源缺席。`$desktop-test-gui-initialization-e2e` 仍在唯一基线提交前固定运行，但只在单实例启用时双启动、只在托盘启用时操作真实托盘；托盘禁用时实测关闭最后窗口退出。所有组合都验证所选侧栏、默认设置页、实际菜单页面可达和未选页面缺席。无法判定或观察某个适用场景仍失败关闭。
- 取代范围：本决定取代 ADR-20260825-008 的“固定 `136px` 单态侧栏”、ADR-20260825-007 的“所有 GUI 强制单实例”、ADR-20260825-006 与 ADR-20260824-004 的“所有 GUI 强制托盘/关闭隐藏”、ADR-20260825-005 的无条件双启动/托盘 E2E、ADR-20260825-002 的默认收起侧栏、ADR-20260825-001 的统一可折叠侧栏与固定支持路由，以及 ADR-20260820-002/ADR-20260824-004 的赞助媒体默认进入全部 GUI bundle。上述 ADR 中关于能力启用后的实现质量、安全、i18n、品牌事实、更新/统计零出站、主题、图标、真实宿主证据和 core-first 的约束继续有效。
- 理由：托盘、单实例和支持页会改变进程生命周期、依赖、包体与信息架构，不应由 Harness 替所有产品静默决定，因此四项能力继续要求显式选择。侧栏未选择不应阻断中性初始化；详细模式保留可见名称，同时仍可折叠获得空间效率，适合作为确定性缺省值，精简模式继续供低菜单数量工具显式选择。启用分支的严格门禁和禁用分支的反向无残留校验保持不变，避免“可选”被误读为弱实现。
- 风险与缓解：缺省规则若散落在多个消费者中可能造成行为漂移，显式非法输入若被误当作空值会掩盖配置错误；能力组合增多会扩大测试矩阵，localStorage 可能不可用或损坏，托盘禁用会改变用户习惯的退出语义。通过只在初始化器归一化、最终固定五字段 schema、非法值重新确认、组合静态检查、只执行适用真实场景、存储失败回到默认展开、独立 `aria-label`、关闭语义命名回归和禁用能力残留扫描降低风险。首次真实 GUI 下游的各组合仍保持 `Unverified`，不得以 Harness 模板测试冒充前向证据。
- 验证：Harness 模板增加条件导航与两种侧栏回归；Node.js 生命周期检查器增加 profile 解析、托盘/单实例启用与禁用分支、缺失/非法配置及关闭语义负向测试；Python Harness validator 与初始化主契约测试同步锁定问询、profile、模板、文档和 Skill。当前 Harness 不包含已实例化下游 GUI，因此本轮不运行真实 Tauri 组合 E2E；首次下游初始化仍必须按 profile 完成真实门禁。
- 恢复或调整标准：若真实下游证明五项粒度不足、某组合在目标平台不可支持或侧栏尺寸/持久化不满足可用性，项目负责人可通过新 ADR 调整字段、兼容矩阵、缺省模式、尺寸或存储实现；不得恢复静默默认任何一项能力、侧栏未选后仍缺失/`pending`、显式非法值被静默接受、禁用能力残留、托盘禁用仍关闭隐藏、详细模式默认收起或折叠后没有可发现/可访问名称。

## ADR-20260826-004：GUI 页面工作状态只在应用进程内跨路由保留

- 日期：2026-08-26
- 状态：Accepted
- 关联需求：项目负责人要求 GUI 中可交互选择的选项卡、查询项、分页等状态在路由和页面切换后仍可继续使用；返回后分页状态若查询不到数据则回到第一页；这些状态只在程序本次打开期间有效。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-GUI-PROCESS-SESSION-STATE`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本，本决定不自动改变 `Version.md`。
- 状态所有权决定：活动选项卡、已应用查询/筛选、排序、页码/每页数量及同类页面工作状态属于 GUI adapter 的纯交互状态，由应用根 Jotai store 的页面级模块 atom 持有。atom 在页面模块顶层稳定创建，Provider/store 位于不会随 route unmount 重建的应用壳；切换路由以及已启用的关闭隐藏/单实例唤醒沿用同一 store，真正退出后下一次程序运行使用新 store 和默认值。
- 生命周期决定：页面会话 atom 不使用 `atomWithStorage`、localStorage、sessionStorage、IndexedDB、Tauri Store、配置文件、数据库或 URL，不形成跨进程恢复。语言、主题与 ADR-20260827-001 批准的详细侧栏折叠偏好按各自独立契约持久化，侧栏偏好不进入页面会话 atom；TanStack Query 继续拥有异步数据/缓存，shared core 和持久层继续拥有权威业务状态，atom 不复制这些数据。
- 分页决定：查询条件、活动数据范围或每页数量变化时立即把页码设为 1。路由返回后按保存的控件状态查询；只在查询成功、当前页大于 1 且结果为空时把页码原子改为 1，由变更后的 query key 重查一次。loading、取消、超时或 error 不视为空结果；第 1 页为空时保持空态，不重复触发。恢复时失效的枚举选择回到当前安全默认。
- 模板决定：共享 GUI React 资产增加 `pageSessionState.ts` 和独立 `PageSessionState.test.ts`，作为下游页面状态 atom 与空页协调的基线；具体产品页面仍按真实字段定义自己的 tab/query 类型，不把 helper 扩张成业务状态容器。
- 验证决定：同一应用根 store 必须证明 tabs、query/filter、sort、page/pageSize 在 route unmount/remount 后保持；新 store 必须从默认值开始；另覆盖成功空页回退、loading/error 不回退和第 1 页空数据不循环。validator 同时拒绝删除 helper 的进程内约束或加入页面会话持久化 API。
- 影响范围：AGENTS/README、工程规则、Rust/GUI/React/Mantine 基线、GUI adapter/支持界面/日常实施 Skills，共享 React 资产与测试、Harness validator、最新 Product Spec 和当日 Changelog。当前不创建真实下游产品页面、不运行生产构建/E2E，也不改变设备级语言/主题偏好。
- 风险与缓解：过度持久化会在下次启动泄漏陈旧工作上下文，因此只使用内存 store；把失败误判为空会隐藏错误，因此只响应 success；陈旧页码可能产生二次查询，因此回退仅从大于 1 到 1 且第 1 页终止。页面 atom 若在组件内创建仍会丢失，所以模板和回归固定模块顶层与应用根 store 所有权。
- 恢复或调整标准：只有项目负责人明确要求某类页面状态跨进程、可分享 URL 或由 core 持久化，并给出数据生命周期、隐私、迁移与失效规则时，才以新 ADR 调整该类状态；不得通过局部 localStorage、URL search 或 Query 数据镜像形成隐式例外。

## ADR-20260826-003：控件自行拥有交互，发布候选携带近五版日志并统一可见版本前缀

- 日期：2026-08-26
- 状态：Accepted
- 关联需求：项目负责人要求页面交互事件绑定到元素自身，禁止通过父级点击切换表格内 `Switch`；关于页在“检查更新”旁增加可查看近 5 次内容的“更新日志”；每次发布前汇总上一次正式发布到当前版本的功能优化与问题修复并只保留近 5 版；所有用户可见版本号统一带 `v`。

- 事件归属决定：按钮、链接、`Switch`、`Checkbox` 和菜单项等语义控件自行绑定 handler；Card、`Table.Tr`、`Table.Td` 等父级不得代理子控件动作。父级确有独立动作时只能执行自身语义并隔离冲突传播；测试分别点击控件与周围父级区域，表格行或单元格点击不得切换行内 `Switch`。这项规则适用于所有页面，不只关于页示例。
- 关于页决定：在 ADR-20260827-001 选择启用关于页时，“检查更新”与“更新日志”作为相邻但独立的 Button，各自拥有事件。更新区 Paper/Group 不注册这两个动作；`NotConfigured` 只禁用远程检查，本地更新日志仍可打开。弹窗按最新在前显示至多 5 版，每版功能优化与问题修复各至多 10 条。未选择关于页时不建立隐藏入口。
- 发布日志决定：根 `release-notes.json` 是候选包和 GUI 关于页共用的结构化发布日志事实。`$desktop-prepare-release` 在候选构建前从上一次真实正式发布版本及 40 位提交到当前发布源码筛选最重要的用户可见变化；首发从仓库起点计算，无法可靠确定边界时返回 `Not ready`。普通缺陷即使不触发项目 Changelog，也进入当前版本的“问题修复”。
- 格式决定：每版两类合计至少一条，两类分别最多 10 条，空分类显示“无”；固定渲染标题为 `-----------更新日志 {发布日期} {发布版本}----------`，分类标题为 `###功能优化` 和 `###问题修复`。文件使用固定 schema、规范 ISO 日期、唯一版本、最新在前、最多 5 版、拒绝符号链接/非普通文件并通过同目录暂存原子替换。
- 候选绑定决定：构建 Skill 在任何测试或编译前只读校验日志最新版与当前机器版本并计算 SHA-256，把根文件同一字节作为 `release-notes.json` 打入 CLI 归档或 GUI 应用资源；manifest 记录 `releaseNotesVersion`、`releaseNotesSha256`、`releaseNotesPath`。构建、收集、验收和发布就绪复核不得生成、补写、重排或截断日志；候选形成后任何日志变化都要求新提交、新构建和重新验收。Harness 升级把该文件视为 `protected`。
- 版本展示决定：所有面向人的版本号先移除已有 `v`/`V` 前缀，再补且只补一个小写 `v`，覆盖窗口标题、侧栏、设置/关于页、更新状态、CLI `--version` 与更新日志。Cargo、JSON/协议、状态和 manifest 的机器 `version` 保持不带展示前缀的原始值，避免破坏 SemVer 解析或既有机器契约；只有明确命名的 `releaseNotesVersion` 使用展示值。
- 实现边界：GUI 模板使用共享 `formatDisplayVersion`，发布准备使用无第三方依赖的标准库 `release_notes.py`，关于页只消费本地候选事实，不把远端自由文本更新说明当作发布日志权威。CLI Clap 版本输出使用带 `v` 的展示形式，结构化 CLI 版本字段仍保持原始值。
- 影响范围：工程规则、AGENTS/README、CLI/Rust/GUI/发布文档，CLI/GUI 初始化资产，GUI 支持模板与 i18n，发布准备/构建/跨平台/收集 Skills，候选 workflow、升级所有权、Harness validator、最新 Product Spec 与当日 Changelog。当前不构建或发布候选，也不创建根日志占位文件；下游首次真实发布准备时按事件创建。
- 风险与缓解：父级与子级都含动作时可能发生传播冲突，因此默认禁止父级代理并要求双区域回归；展示前缀可能污染机器版本，因此格式化只位于用户边界；发布日志可能与候选漂移，因此构建前锁定摘要、包内逐字节核对并在候选后禁止改写；同日多个版本只能依赖列表顺序，维护脚本始终把当前版本置顶。
- 验证：发布日志 helper 覆盖格式、单 `v`、5/10 上限、同版本替换、畸形 schema、版本不一致和符号链接拒绝；GUI 模板回归覆盖两个按钮自身事件、父容器无动作、5/10 裁剪与 `v` 归一化；候选 workflow 回归覆盖构建前校验、两平台打包、包内字节、manifest 字段和顺序；CLI 资产回归覆盖 `--version` 的 `v` 前缀；Harness validator 锁定文档、Skills、升级保护与模板资产。
- 恢复或调整标准：只有项目负责人依据真实交互可用性或发布渠道格式要求明确新的事件语义、日志保留/分类/格式或版本展示规则时，才以新 ADR 取代本决定；不得通过行级点击代理、远端自由文本、候选后补写或机器版本加 `v` 形成隐式例外。

## ADR-20260826-002：按 Rust 与前端代码类型收紧文件行数门禁并固定模块目录结构

- 日期：2026-08-26
- 状态：Accepted
- 关联需求：项目负责人明确要求把 Rust 代码治理收紧为 400 行建议重构、800 行强制拆分，把前端代码治理收紧为 500 行建议重构、1000 行强制拆分，并特别保持合理文件结构与 Rust `<module>/mod.rs` 目录模块组织。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-TIERED-CODE-LINE-LIMITS`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本；下游自动 SemVer 不适用于 Harness 自身，本决定不自动改变 `Version.md`。
- Rust 决定：`.rs` 文件 400 行及以内不因行数触发专项复核；401 至 800 行列为非阻断建议重构候选，并按高内聚、职责单一和职责相近性复核是否保留；800 行通过，801 行起机械失败并强制拆分。多文件模块统一使用 `<module>/mod.rs` 作为目录入口，把职责相近的子模块置于同一目录；不得保留同级 `<module>.rs` 与同名目录，不得创建空壳转发层或压缩可读性规避门禁。
- 前端决定：现代前端源码后缀 `.astro`、`.cjs`、`.css`、`.cts`、`.html`、`.js`、`.jsx`、`.less`、`.mjs`、`.mts`、`.sass`、`.scss`、`.svelte`、`.ts`、`.tsx`、`.vue` 使用 500/1000 配置；500 行及以内不触发专项复核，501 至 1000 行列为非阻断建议重构候选，1000 行通过，1001 行起机械失败。前端按功能、页面或稳定能力职责建立高内聚目录，不强制 `index.ts` 桶文件，也不得用 `export *` 隐藏真实来源。
- 通用文本决定：其他 UTF-8 人工维护文本继续沿用 ADR-20260806-003 的 500 行语义复核与 2000 行硬上限。工具生成且禁止手工编辑的锁文件/生成物、原样内嵌且明确隔离的第三方文件继续按封闭范围排除；生成器、模板和维护说明仍按自身文件类型受门禁。
- 自动化决定：唯一行数检查器按后缀选择配置，并为每个候选或违规输出稳定 `profile`、建议阈值和硬上限。软阈值只产生可见复核提示；任一硬超限或检查器错误返回非零状态。Rust 硬超限的人类可读诊断必须同时指出 `<module>/mod.rs` 结构，不把单纯缩行误报为合格拆分。
- 取代范围：本决定只取代 ADR-20260806-003 对 Rust 与前端代码使用统一 500/2000 的部分；该决定的通用文本 500/2000、职责语义复核、生成物封闭排除和物理行计数继续有效。ADR-20260805-002 的历史 400 行全文件硬上限继续保持被取代状态。
- 影响范围：最新 Product Spec、AGENTS/README、工程规则、Rust 基线、初始化/实施/重构/i18n Skills、Harness 方法论与升级传播、统一行数检查器、Harness bridge/validator、专项回归、TECH_DEBT 当前说明和当日 Changelog。日常开发是否自动运行全仓治理检查、core-first、中文注释、发布与验收门禁不变。
- 理由：Rust 模块通过明确的目录入口可以在较低规模时按领域职责稳定拆分；前端页面和组件通常包含相邻视图、状态与样式，保留稍高的建议阈值更符合其结构。分层硬上限能阻止“语义复核”把代码文件无限保留，同时避免把文档、规格和 Skill 一并机械压到代码阈值。
- 风险与缓解：后缀分类会把同后缀的 Node.js 工具代码纳入前端配置，这是有意的确定性代码治理范围；新增后缀必须更新事实源和边界回归，不能按任意目录临时豁免。过早拆分可能产生碎片，因此建议区间仍以职责判断为准；硬超限拆分也不得创建无职责的文件或桶层。
- 验证：覆盖 Rust 400/401/800/801、前端 500/501/1000/1001、通用文本 500/501/2000/2001，检查报告 profile/阈值/上限、Rust `mod.rs` 诊断、Git 可见范围、生成锁文件排除、CLI 0/1/2 退出码和 Harness bridge；运行相关 Python 专项回归、完整 Harness validator、现行阈值引用扫描、Skill quick validator 与差异检查。
- 恢复或调整标准：只有项目负责人依据真实审阅成本或职责拆分证据明确新的语言配置、边界值和迁移方式时才能调整；不得通过路径豁免、ADR 例外、缩行或空壳模块放宽 800/1000 硬上限。

## ADR-20260826-001：下游采用按完成事件提交、按正式发布周期去重的自动语义化版本门禁

- 日期：2026-08-26
- 状态：Accepted
- 关联需求：项目负责人要求把自动版本规则整理为 Agent 可执行门禁/Skill：新功能提升版本但同一正式发布前不重复提升，独立缺陷修复逐次提升且同一缺陷不重复；Major 由用户决定、Minor 由功能决定、Patch 由缺陷修复决定，分量范围为 `0..100`。经逐项确认，本规则只适用于下游产品，Harness 继续使用时间版本；首功能执行 `MINOR+1` 并归零 Patch；只有真实正式发布成功才开启下一周期；重复缺陷以稳定 ID 去重，发布后回归必须使用新 ID；查询、诊断、复现、重构等非需求/修复完成操作不提升。
- 变更标识与所需版本：`change_id = HARNESS-FEAT-DOWNSTREAM-AUTO-VERSIONING`；`required_version = 202608051301`。该值是当前 Harness 未发布时间版本，不表示下游 SemVer，也不触发 Harness 自动提升；下游每项变化的 `required_version` 由新门禁按当时周期状态计算。
- 决定：新增持久 `$desktop-manage-version`。下游根 `Cargo.toml` 的 `[workspace.package].version` 继续作为当前版本唯一事实源；受保护的 `.harness/version-state.json` 只保存周期基线、当前目标、首功能是否已提升、待发布变化、历史缺陷 ID 和最近发布绑定。helper 使用 Python 标准库、稳定 JSON 输出和失败关闭语义，不引入第三方或全局依赖。
- 版本决定：只接受稳定三段 `MAJOR.MINOR.PATCH`，三个分量均在闭区间 `0..100`；溢出不进位并请求用户决定。Major 必须由用户批准高于当前值的精确目标，写为 `N.0.0`，并视为本周期已包含功能提升。一个正式发布周期内首个已完成功能执行 `MINOR+1` 且 `PATCH=0`，后续功能只记录所需版本、不再次因功能提升；每个新稳定缺陷 ID 的已完成修复执行 `PATCH+1`，相同 ID 的重试、补充修改和跨发布重复都幂等，真实回归使用新的回归 ID。
- 非提升决定：缺陷查询、诊断、复现、未完成或重复修复尝试，以及行为保持重构、测试补强、文档、格式和内部清理统一分类为 `maintenance`，不改变 Cargo 或状态。`plan` 始终只读；只有实现完成且本次相关测试通过后才能 `apply`。普通构建、`pending` 候选、候选收集、验收与发布准备只执行一致性检查，绝不补升或重置。
- 发布决定：只有真实渠道正式发布成功且精确版本/40 位源码提交已有证据后才能 `finalize-release`。它清空待发布变化、允许下一周期的首功能再次升 Minor，但保留历史缺陷 ID。构建成功、候选 `accepted`、标签/上传尝试、失败、取消或超时均不得调用该动作。
- 文档决定：Product Spec、ADR、Changelog 或 Work Plan 仅在自身触发条件独立满足时记录稳定 `change_id` 与门禁返回的 `required_version`；版本提升本身不创建这些记忆。早期变化记录的是其最低所需版本，最终发布版本可因后续变化更高。普通缺陷修复和维护排除规则保持不变。
- 影响范围：最新 Product Spec、AGENTS/README、工程与发布规则、Rust 初始化基线、产品定义/计划/实施/初始化/构建/收集/验收/发布准备/升级 Skills、升级所有权、Harness validator、版本 helper/专项回归和当日 Changelog。Harness `Version.md`、时间版本规则、产品业务 core、接口契约和发布授权不变。
- 理由：把提升时点绑定到“变化已完成且测试通过”避免查询或失败尝试消耗版本；把首功能状态绑定到正式发布周期符合“下次发布前不再增加”；稳定缺陷 ID 让重复修复可机械去重，而新的回归 ID 保留独立修复的可追踪 Patch；Cargo 与周期状态分责避免出现两个当前版本来源。
- 风险与缓解：错误分类可能漏升或误升，因此分类会改变产品范围或版本且存在二义性时必须询问；状态与 Cargo 漂移、符号链接、损坏 JSON、ID 跨类别复用、未批准 Major、非稳定 SemVer和溢出全部失败关闭。两文件提交无法获得文件系统级事务时，helper 在状态写失败后恢复 Cargo 原字节，并由后续 `check` 拒绝任何残留漂移。历史缺陷 ID 会增长，但它是实现全周期去重所需的有界标识集合，未来只有真实规模证据才能引入压缩/归档方案。
- 验证：标准库专项测试覆盖首功能/后续功能、Minor 归零 Patch、独立/重复缺陷、维护/只读 plan、正式发布重置与缺陷 ID 保留、新回归 ID、Major 用户批准、分量溢出、Cargo/状态漂移与不稳定版本拒绝；Harness validator 锁定初始化、开发、两类构建、跨平台、收集、验收、发布准备、项目记忆和升级保护接线。
- 恢复或调整标准：若真实下游证明发布周期边界、ID 来源或版本上限需要改变，项目负责人必须明确新的确定性规则、已有状态迁移、重复判定和发布失败行为，并以新 ADR 取代本决定；不得通过手工编辑 Cargo/状态或在构建阶段补版本形成隐式例外。

- 取代范围：本决定取代 ADR-20260825-001/-002/-004/-005 中关于默认可折叠/默认收起侧栏、折叠 Tooltip、展开 248px 宽度和初始化设置页统计同意的现行部分，并收紧 ADR-20260825-006/-007 的托盘资源门禁；单实例、托盘可见图标、关闭隐藏/恢复/退出、三态主题、关于页更新、赞助页和可选统计传输的安全边界继续有效。
- 影响范围：最新 Product Spec、AGENTS/README、Agent Policy、工程规则、Rust/GUI/React/Mantine 基线、实例化/初始化/GUI adapter/GUI 支持/GUI 初始化 E2E Skills 及元数据、React 模板与双语资源、GUI 生命周期结构检查器及专项回归、Harness validator/治理回归和当日 Changelog。非 GUI 接口、业务 core、发布签名、最终候选 E2E 选择和可选统计传输协议不变。
- 理由：原始翻译键可见说明“资源存在”不足以证明原生菜单实际解析并响应当前语言；运行时解析、断言回归和真实双语切换共同关闭该漏检路径。初始化设置页不应为默认禁用的可选出站能力占用空间或暗示产品正在采集数据。固定单态的图标上文字下导航减少无价值状态和交互，较宽侧栏与显式文字又比纯图标/Tooltip 更易识别，并保留足够的中文标签宽度。
- 风险与缓解：`10em` 只是约十个当前字体字符的布局预算，不保证任意语言单行容纳，因此允许最多两行并保留完整 `aria-label`；真实窗口 E2E 继续检查裁切、中心线和可访问名称。运行时更新原生菜单需要 GUI adapter 持有菜单项或安全重建菜单，必须由应用生命周期拥有且不得重复增加菜单项。严格双语托盘检查会阻断无法观察系统托盘的宿主，这是既有有意失败语义。
- 验证：Harness 侧模板/validator 回归锁定 `136px`、`56px`、`30px`、`11px`、`10em`、图标上文字下、无折叠控件和默认设置页无隐私/统计内容；Node.js 生命周期检查器专项回归锁定两项 `rust-i18n` 调用、新增三个有断言测试，并验证原始 key 与空断言回归都会失败。当前 Harness 不包含已实例化下游 GUI，因此本轮不构建或操作真实 Tauri 托盘；首次后续 GUI 初始化必须按更新后的 E2E 提供真实中英文刷新、固定侧栏和精简设置页前向证据，其他宿主保持 `Unverified`。
- 恢复或调整标准：只有项目负责人基于真实下游可用性证据明确改变导航或默认设置范围，并以新 ADR 同步尺寸、文本溢出、无障碍、模板与 E2E 时，才能调整单态侧栏或重新引入默认设置项。若 Tauri/rust-i18n API 演进，可替换菜单刷新实现，但不得恢复原始 key 可见、只验证资源文件、语言切换必须重启或默认统计同意区块。

## ADR-20260825-007：GUI 初始化强制单实例并以真实双启动锁定唯一主进程与主窗口（强制默认已由 ADR-20260827-001 取代，启用分支继续有效）

- 日期：2026-08-25
- 状态：Accepted
- 关联需求：项目负责人在把系统托盘提升为强制初始化约束后，进一步要求所有新初始化的 GUI 同时是单实例应用。
- 背景：既有 GUI 基线已经固定关闭隐藏、托盘恢复和显式退出，但没有阻止用户再次启动同一应用时形成第二个长期应用进程或第二个主窗口。只写“单实例”文字也无法确认插件注册顺序、第二进程退出、既有窗口唤醒和进程/窗口唯一性，因此需要与托盘相同的结构、回归和真实宿主三层门禁。
- 官方能力依据：采用 Tauri 2 官方 `tauri-plugin-single-instance`。官方文档说明该插件确保同一应用只运行一个实例，第二次启动会触发既有实例回调并由插件关闭新实例；插件必须最先注册，回调可取得 `app`、启动参数与工作目录。Windows、macOS、Linux 均受支持；Linux Snap/Flatpak 因沙箱限制还需为基于会话 DBus 的服务声明 own/talk 权限（[Tauri Single Instance](https://v2.tauri.app/plugin/single-instance/)，核对日期：2026-08-25）。
- 依赖与顺序决定：根 `[workspace.dependencies]` 是 `tauri-plugin-single-instance` 版本与来源的唯一事实源，声明经过最低直接版本解析和项目 MSRV 测试的兼容稳定下界；GUI member 只使用 `workspace = true`。插件必须是 Tauri Builder 的首个 plugin，不能放到其他插件之后，也不能仅在前端模拟互斥。
- 生命周期决定：同一用户会话再次启动相同应用身份时，第二进程必须通知既有实例后在限定时间内退出。回调只调用 GUI adapter 内共享的 `restore_main_window`，对既有 `main` 窗口依次执行显示、取消最小化和聚焦，不创建第二个主窗口，不替换第一主进程。托盘左键与 `show_window` 同样复用该恢复函数。中性脚手架必须忽略且不得记录第二次启动的参数和工作目录，不得把它们解释为文件打开、深链或其他产品动作；以后确需该能力时必须独立批准，并由 core 判定业务语义。
- 结构与回归门禁：把 ADR-20260825-006 引入的托盘检查器扩展并改名为 `verify-gui-lifecycle-contract.mjs`。它除原托盘契约外，还失败关闭地检查 workspace/member 的单实例依赖、插件初始化、首插件顺序、只恢复已有窗口的中性回调，以及 `single_instance_plugin_is_registered_first`、`second_launch_restores_existing_main_window` 两个固定回归；与三个托盘回归合计五个固定命名生命周期回归。检查器继续只使用 Node.js 标准库，并拒绝路径越界、源码符号链接、非法 UTF-8 和空源码。
- 真实双启动门禁：`$desktop-test-gui-initialization-e2e` 构建本次 debug/no-bundle 二进制并持有第一次启动句柄后，先关闭隐藏主窗口，再以独立受管子进程启动同一精确二进制。第二次启动必须在 15 秒内退出；第一 PID 必须持续，原主窗口身份必须不变且恢复、取消最小化并聚焦。宿主进程与窗口枚举必须只发现一个长期应用主进程和一个主窗口；WebView/系统 helper 不计为第二应用主进程。随后继续执行真实托盘生命周期、侧栏和菜单路由检查，并回收两个子进程句柄。
- 失败语义：缺少依赖、首插件顺序、回调、任一固定命名回归，第二进程残留、第一进程被替换、出现第二主窗口、窗口未恢复聚焦、进程/窗口唯一性无法可靠判定，或双启动无法执行，都阻断初始化能力裁剪和唯一基线提交。不得因 Draft、宿主限制、小型应用或 `milestone_e2e` 值跳过、降级或记为 `Not run`。
- 渠道边界：本机非沙箱调试证据只证明当前宿主。同一应用身份的范围以当前用户会话为准，不声称跨用户全局互斥。Snap/Flatpak 必须在对应打包清单声明插件服务所需的会话 DBus own/talk 权限，并在真实沙箱最终候选重验；缺少渠道清单或候选证据时该渠道保持 `Unverified`，不能拿普通 Linux 调试结果替代。
- 影响范围：最新 Product Spec、AGENTS/README、Agent Policy、工程规则、Rust GUI 基线、验证矩阵、实例化/初始化/GUI adapter/GUI 初始化 E2E Skills 及其元数据、GUI 生命周期结构检查器与专项回归、Harness validator/治理回归和当日 Changelog。非 GUI 初始化、自动启动、文件关联/深链、发布签名及最终候选 E2E 选择规则不变。
- 理由：官方插件提供跨平台互斥与第二启动通知，但只有首插件顺序才能避免其他插件抢先产生副作用；共享恢复函数让单实例与托盘保持一致的窗口可达性语义。结构检查快速阻止漏接线，固定回归锁定顺序和回调，真实双启动证明最终二进制的进程/窗口行为，三层证据共同防止“声明单实例但仍可开两个窗口/进程”。
- 风险与缓解：不同宿主的进程树和窗口枚举能力不同，严格唯一性判断可能让无可观察能力的 runner 无法初始化；这是有意失败，应转到可枚举真实应用主进程与窗口的宿主。Linux 沙箱需要额外 DBus 配置，按渠道独立验证。回调不使用参数/工作目录，避免中性脚手架提前建立未经批准的外部输入契约或把敏感路径写入日志。
- 验证：Node.js 专项回归覆盖完整单实例/托盘契约，以及缺失 workspace 单实例依赖、插件未最先注册、缺少单实例命名回归等失败路径。Harness Python 治理回归与 validator 锁定新文件名、依赖/首插件/五个回归和真实双启动场景。本 Harness 不包含已实例化下游 GUI，因此本轮不构建或双启动真实 Tauri 应用；首次后续 GUI 初始化必须提供真实前向证据，其他宿主和 Snap/Flatpak 保持 `Unverified`。
- 恢复或调整标准：只有项目负责人明确改变产品/平台范围，并以新 ADR 记录替代的多实例交互、窗口所有权、外部参数语义、渠道风险与真实候选证据时，才能调整或移除单实例基线。若 Tauri 官方 API、进程模型或沙箱权限要求变化，可依据官方文档与真实下游证据替换实现/探测方法，但不得恢复只写文档、插件非首位、无法判定也通过或静默多实例。

## ADR-20260825-006：GUI 系统托盘改为不可省略的结构与真实生命周期双门禁（不可省略默认已由 ADR-20260827-001 取代，启用分支继续有效）

- 日期：2026-08-25
- 状态：Accepted
- 关联需求：项目负责人发现新初始化的 GUI 项目再次丢失系统托盘，要求把托盘及其窗口生命周期提升为强制约束，不能再由初始化实现自行省略。
- 背景：既有 Product Spec、GUI adapter 与初始化说明已经描述 `tray-icon`、显示/退出和关闭隐藏，但基线提交前的真实 GUI E2E 只验证应用启动、侧栏居中和菜单路由，没有检查托盘图标、原生托盘菜单或关闭隐藏/恢复/退出生命周期。因此生成项目即使没有实际托盘，仍可能通过既有门禁并提交；问题属于可执行验收覆盖缺口，不是缺少文字约束。
- 强制实现决定：任何选择 GUI 的初始化都必须在根 Tauri 依赖启用 `tray-icon`，并从用户所选母版通过项目本地 Tauri `icon` 命令生成 `src-tauri/icons/32x32.png`。该文件必须是普通非符号链接、32×32 8-bit RGBA 非交错 PNG、至少含一个非透明像素，且被 `tauri.conf.json` 的 `bundle.icon` 精确引用。托盘安装函数必须从 Tauri Builder `.setup(...)` 实际调用，在同一实现组装并绑定只含 `show_window`/`quit` 的 `Menu`、把 `default_window_icon()` 当作必需值、调用 `.icon(...)` 并成功 `.build(app)`；默认图标缺失必须中止启动，不能静默创建无图标托盘。关闭处理必须从 `.on_window_event(...)` 可达。主鼠标左键释放和 `show_window` 都显示、取消最小化并聚焦主窗口；原生 `CloseRequested` 只 `prevent_close()` 后隐藏且进程继续；只有 `quit` 显式结束应用并回收 owned task。默认不加入自动启动。菜单绑定同时满足 Tauri 官方说明的 Linux 图标可见性要求。
- 结构门禁决定：最初新增标准库 Node.js 托盘检查器；ADR-20260825-007 已把它扩展并改名为 `verify-gui-lifecycle-contract.mjs`。当前 GUI 初始化构建前必须用该检查器验证 workspace Tauri feature、member 的 `workspace = true`、32px 图标的格式/非透明像素/配置引用、从 `.setup` 可达且在同一函数绑定 Menu/default icon/icon/build 的真实 Rust 托盘安装、已注册的关闭事件、点击/菜单/窗口/退出源码、稳定 ID、中英文原生资源，以及 `tray_show_restores_and_focuses_main_window`、`close_request_hides_without_exit`、`tray_quit_exits_application` 三个固定命名托盘回归；单实例部分按 ADR-20260825-007 追加。未调用死代码、缺图标后继续、只创建菜单项或只注册菜单事件都失败。检查器对路径越界、图标/源码符号链接、非法 UTF-8、空源码、畸形/全透明 PNG 和任何缺项失败关闭，只使用 Node.js 标准库。
- 真实生命周期门禁决定：`$desktop-test-gui-initialization-e2e` 在构建并启动本次 debug/no-bundle 二进制后，必须通过 Computer Use 定位当前宿主的真实托盘图标，保存同时识别托盘区域和应用图标的截图，并确认状态栏/通知区域出现有可见非空图形的图标，而不是透明/纯空白点击区域或只能弹出菜单的不可见占位；随后确认菜单恰好只有本地化显示/退出两个可操作项，再依次实测原生关闭使窗口隐藏但进程和托盘继续、托盘左键恢复聚焦、菜单“显示窗口”再次恢复聚焦，以及菜单“退出”结束进程并移除托盘图标。结构检查或单元测试不能替代该真实宿主证据。
- 失败语义：缺少 feature、32px 资产/配置引用/运行时接线、源码、稳定 ID、双语资源、固定命名回归、可见非空托盘图形、精确菜单或任一生命周期行为，或者当前宿主只能定位空白点击区域、无法显示、定位、操作或可靠判定托盘，都必须阻断初始化能力裁剪和唯一基线提交。不得因 Product Spec 为 Draft、页面简单、宿主差异、实现偏好或 `milestone_e2e` 值静默跳过、降级或记为 `Not run`。
- 影响范围：最新 Product Spec、AGENTS/README、Agent Policy、工程规则、验证矩阵、Rust GUI 基线、实例化/初始化/GUI adapter/GUI 初始化 E2E Skills 及其元数据、Harness validator、治理回归和当日 Changelog。非 GUI 初始化、最终候选 E2E 选择、签名、发布和 Verification 证据留存规则不变。
- 理由：系统托盘与“关闭只隐藏”共同决定桌面应用的基本可达性和退出语义；只检查配置或源码无法证明宿主实际显示了托盘，只做 Computer Use 又会在构建前才发现确定性的接线缺失。结构门禁用于快速失败，命名回归锁定代码行为边界，真实 E2E 证明最终调试二进制与当前操作系统集成，三层证据共同关闭既有漏检路径。
- 风险与缓解：真实托盘位置和可访问性会随操作系统、桌面环境和状态栏设置变化，严格失败可能使某些无可观察托盘的 runner 无法初始化 GUI。该结果是有意的安全失败：GUI 初始化必须转到能真实观察目标托盘的受支持宿主，而不是生成缺少关键生命周期的基线；其他平台仍明确标记 `Unverified`。32px PNG 检查只证明图像结构与非透明像素，不能证明当前主题/桌面实际可辨，因此必须保留真实截图门禁。检查器只识别稳定 Tauri 结构片段，若官方 API 演进则由真实迁移证据更新，不以放松门禁代替适配。
- 验证：Node.js 专项回归覆盖完整契约通过，以及缺少 `tray-icon`、托盘安装未从 `.setup` 接线、菜单未绑定、默认图标可选回退、`bundle.icon` 未引用 32px 来源、32px PNG 全透明、真实托盘创建、固定命名回归或中文资源时失败；Python Harness 治理回归与 validator 锁定检查器文件、初始化调用顺序、固定 ID/测试名、图标资产/接线和真实托盘可见图形 E2E 场景。本 Harness 不包含已实例化下游 GUI，因此本轮不构建或操作真实托盘；首个后续 GUI 下游必须产生真实前向证据后才能创建基线提交。
- 恢复或调整标准：只有项目负责人明确改变产品/平台范围，并以新 ADR 记录替代交互、可达性、退出语义、目标宿主、风险与真实候选证据时，才能调整或移除系统托盘。Tauri API、操作系统托盘模型或 Computer Use 可观察能力变化时可替换实现与探测方法，但不得恢复“只写文档、只看源码、无法观察也通过”或静默无托盘初始化。

## ADR-20260825-005：GUI 初始化提交前固定真实本机 E2E，并统一 Tabler 图标来源（E2E 场景已由 ADR-20260827-001 改为按 profile 执行）

- 日期：2026-08-25

## ADR-20260825-003：Rust、前端依赖与受管工具统一声明可验证的最低兼容版本范围

- 日期：2026-08-25
- 状态：Accepted
- 关联需求：项目负责人要求 Rust 与前端都以“兼容的最小版本”作为要求，而不是指定某个精确版本，并清理当前工程中把普通依赖或工具写成指定/最新版本的规则与实现。
- 决定：依赖清单和环境契约以“完整、包含且经过验证的最低兼容稳定版本”为事实来源；锁文件负责固定某次实际解析结果。正常安装或锁定可以得到范围内较新的稳定版本，但“较新”不再是选型目标，也不能改变兼容下界。只有使用到新的 API/feature、修复安全或平台兼容问题，且提高后的下界通过相同验证时，才提高最低版本。
- Rust 边界：registry 直接依赖使用完整三段下界的 Cargo 兼容要求，例如 `1.2.3` 表示 Cargo 默认 caret 兼容范围而不是精确 `=1.2.3`；禁止普通依赖使用 `=`、通配符、未经批准的 Git/tag 或无下界范围。根 `rust-version` 继续表示最低支持 Rust，member 继承 workspace 依赖。Cargo 官方说明普通版本要求使用 caret 兼容语义，`rust-version` 声明最低 Rust（[dependency requirements](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html)、[rust-version](https://doc.rust-lang.org/stable/cargo/reference/rust-version.html)，核对日期：2026-08-25）。
- 前端与工具边界：`dependencies`/`devDependencies` 使用带完整三段下界的 caret 或由上游官方明确支持的兼容范围，禁止裸精确版本、`latest`、tag、通配符或无下界范围。`engines.node` 使用当前 Vite 基线要求 `^20.19.0 || >=22.12.0`，`engines.pnpm` 使用 `>=10.0.0`；缺失 pnpm 时安装 `pnpm@^10.0.0`，现有更高兼容版本可继续使用。macOS→Windows 受管工具 `cargo-xwin` 以本机现有且能提供 build/check/test 子命令的 0.22.0 作为已观测下界，兼容范围要求 `>=0.22.0, <0.24.0`；缺失时由 Cargo 以该范围和 `--locked` 安装，既有范围外版本失败关闭，不因当前仓库已有更高发布版而把下界抬到 0.23。Cargo 官方 `cargo install --version` 接受版本要求而非只能接受精确版本（[cargo install](https://doc.rust-lang.org/cargo/commands/cargo-install.html)，核对日期：2026-08-25）。Homebrew 的 LLVM/LLD/NSIS 只做宿主能力探测，不把 formula 当前解析结果伪装成项目兼容版本。旧式精确 `packageManager` 字段不得充当兼容要求；实际包解析由 `pnpm-lock.yaml` 固定。pnpm 官方允许 `engines` 使用范围，并提供 `resolutionMode: lowest-direct` 验证直接依赖下界（[package manifest](https://pnpm.io/package_json)、[resolution settings](https://pnpm.io/settings/other)，核对日期：2026-08-25）；Vite 官方当前 Node.js 要求为上述范围（[Vite guide](https://vite.dev/guide/)，核对日期：2026-08-25）。
- 下界验证：Rust 新增或提高直接下界时，在临时副本中执行 `cargo +nightly update -Zdirect-minimal-versions`，再用根 `Cargo.toml` 声明的最低 Rust 工具链运行受影响的非空测试；前端在临时配置中使用 pnpm `resolutionMode: lowest-direct`，于声明的最低 Node.js/pnpm 环境执行冻结清单所需的类型检查、单元测试与生产构建。日常工作仍使用提交的正常锁文件，不把最低版本解析结果覆盖为日常锁文件。
- 精确值例外：应用/Harness 发布版本、协议或模式版本、Rust edition、目标三元组、资产摘要、签名密钥指纹、按供应链安全要求钉住的 CI action commit 不是依赖兼容要求，可以继续使用精确值。普通依赖若因上游缺陷、安全事件或互操作协议必须精确固定，先记录硬规则例外、风险、验证和解除条件。
- 取代范围：本决定取代 ADR-20260805-003 及现行文档中“优先采用较新/最新兼容稳定依赖”的版本选择部分，也取代环境门禁中缺失 pnpm 时安装 `pnpm@latest` 的做法；固定技术族、最小 feature、三平台、MSRV、锁文件可复现与依赖准入的其余规则继续有效。
- 影响范围：AGENTS/README、工程规则、最新 Product Spec、Rust/CLI/TUI/MCP/GUI 基线与 Skills、中性 Cargo 资产、Node.js/pnpm/cargo-xwin 环境门禁、跨平台 MSRV workflow、Harness validator、专项回归、TECH_DEBT 与当日 Changelog。
- 理由：精确锁死清单会错误缩小消费者可用范围，追逐“最新”又无法证明真正支持的下界；把清单下界与锁文件当前解析分开，可以同时得到可声明的兼容性、日常可复现性和受控升级。最低版本解析能发现宽泛要求掩盖的隐式下界，例如库间对 serde 等共享依赖的真实约束。
- 风险：生态的最低版本解析可能暴露上游元数据错误，范围内较新版本也可能引入回归，Node.js 非连续兼容范围不能用单一数字比较。通过完整三段下界、两类解析策略、声明最低工具链测试、日常冻结锁文件和安全例外 ADR 降低风险；最低版本通过不等于所有兼容版本都已逐一验证。
- 验证：中性 Rust workspace 已以直接最低版本解析到声明下界，并在 Rust 1.90.0 上通过 7 条 workspace/all-target/all-feature 锁定测试；环境门禁增加 Node.js 范围边界、pnpm 最低版本/缺失安装范围，以及 `cargo-xwin >=0.22.0, <0.24.0` 安装、0.22/0.23 范围内复探和范围外拒绝的正负向回归；本机真实 `cargo-xwin 0.22.0` 的版本/帮助探测与 xwin `--check-only` 全门禁通过。validator 检查规则、清单、workflow 和 Skills 不再恢复精确/最新普通依赖要求。真实 GUI 依赖与完整 NSIS 交叉构建尚待首个下游前向运行，保持 `Unverified`。
- 恢复或调整标准：若 Cargo、pnpm 或固定前端技术族改变最低版本解析能力，依据官方文档与真实下游证据更新解析方法和下界；不得退回裸精确版本、`latest` 或只测试当前锁文件后宣称兼容下界。

## ADR-20260825-001：GUI 固定侧栏与设置页，并固化签名更新、强更和最小统计契约（侧栏模式与支持页默认性已由 ADR-20260827-001 取代）

- 关联需求：项目负责人要求 GUI 始终显示版本号，使用可收起的固定左侧菜单；产品功能从顶部向下排列，底部固定项从下向上为关于、设置、赞助；设置页提供中英文切换和检查更新。同时要求完整审查更新检查、强制更新与统计上报逻辑，并把安全、状态和构建要求固化到对应 Skills。

- 风险：用户可能误以为关闭窗口已经退出，静态联系人、免责声明、价格、权益或支付码可能随时间失效，默认赞助媒体也会增加包体积。通过清晰托盘退出入口、本地化菜单、固定字段门禁、品牌复核责任、原字节清单与明确“静态展示不代表交易状态”降低风险；真实候选仍需在各目标平台运行验收后才能声称可用。

## ADR-20260824-003：Superpowers 默认关闭，环境门禁收敛为初始化与错误恢复

- 日期：2026-08-24
- 状态：Accepted
- 关联需求：项目负责人要求默认禁用 Superpowers，并要求环境检测、安装等动作只在初始化阶段或实际遇到环境错误时进行，不得每次任务重复走环境流程。
- 背景：Harness 源策略与推荐预设此前都把 Superpowers 设为 `enabled`，使默认路径开放了并非所有下游需要的外部工作流能力。环境规则虽已避免普通文档任务，却仍允许显式构建仅因“缺少可复用环境证据”在真实命令前运行完整门禁，Tauri 构建还会因选择 xwin 目标预先安装发布工具；这会把证据状态和任务类型误当成环境故障，并在环境实际可用时重复探测或安装。
- 策略决定：`docs/AGENT_POLICY.md` 的 Harness 源值和初始化推荐预设统一使用 `superpowers: disabled`。推荐预设继续启用已受显式请求约束的 Worktree/Subagent 和候选冒烟，并保持 E2E 建议默认值为 `disabled`。下游仍可通过自定义选择明确启用 Superpowers；没有该明确选择时，本次及后续 Agent 都不得调用或遵循 `superpowers:*` Skill。
- 环境决定：中性 `$desktop-initialize-rust-project` 在写入脚手架前主动运行一次与已选接口匹配的完整环境门禁并补齐缺失适用项。初始化完成后，日常开发和构建必须先运行本次真实测试或构建命令；只有该命令已经失败，且保存的命令、退出状态和脱敏诊断明确指向门禁管理的工具链、目标或系统依赖缺失/不兼容时，才调用 `$desktop-check-development-environment`。门禁成功后只重试原失败命令一次，仍失败即停止并保留两次结果。
- 排除与目标门禁：新任务、新会话、首次修改代码、显式构建、选择某个目标、缺少/过期环境证据或工具链可能变化都不得触发环境预检。代码/编译语义错误、测试断言、普通依赖解析或网络、产品配置、凭据、签名和公证失败不得误判为环境错误。macOS→Windows xwin 专用门禁只有在实际失败命令就是已批准的 xwin 构建且错误属于其受管工具时才运行；不得自动安装 Homebrew，也不得临时拼装门禁外安装命令。
- 影响范围：最新 Product Spec、Agent Policy、AGENTS/README、Rust/GUI 基线、实例化/初始化/实施/环境/CLI 构建/Tauri 构建 Skills、Harness validator、相关回归和当日 Changelog。
- 不包含：不移除环境门禁脚本，不改变其供应链校验、接口条件或失败关闭规则；不改变用户自定义启用 Superpowers 的能力，不构建真实下游或候选，不运行签名、公证、E2E 或发布。
- 理由：默认关闭可选的 Superpowers 能力能保持下游最小权限和可预测流程；把环境门禁绑定到一次性初始化或已观察到的真实环境失败，可以消除按任务/证据状态重复探测，同时保留缺失工具时的自动恢复闭环。
- 风险：先尝试真实命令会在缺少工具时产生一次预期失败，并可能增加构建恢复时间；错误分类过窄会把真实环境故障直接返回，过宽则会把代码或凭据问题误判为可安装依赖。通过保留原命令/退出状态/脱敏诊断、限定受管错误类别、只重试一次和禁止门禁外安装降低风险。
- 验证：更新策略预设正反向回归、初始化/环境/构建 Skill 必需片段与旧预检描述拒绝门禁；运行默认 Python 单元测试、完整 Harness validator 和差异检查。本次不实际安装工具链或构建候选，环境脚本的既有隔离测试继续证明其安装与失败路径。
- 恢复或调整标准：若真实下游证明某项 Superpowers 能力应成为所有项目的最小默认，必须由项目负责人明确其权限、触发器和失败边界后更新预设；若某类环境错误无法在真实命令后安全恢复，可为该具体不可逆风险增加窄的前置探测，但不得恢复按任务、显式构建或证据状态运行完整环境流程。

## ADR-20260824-002：GUI 初始化创建项目内 macOS DMG 背景并由构建固定引用

- 日期：2026-08-24
- 状态：Accepted
- 关联需求：项目负责人要求在初始化项目时创建 macOS 构建背景图，并让构建 Skill 引用这张图片。
- 背景：现有 Tauri 规则已经要求最终 DMG 包含本地背景并验证 `.background/background.png`，GUI 身份流程也要求正式背景经过预览批准，但中性初始化没有提供真实图片或确定性项目路径，构建 Skill只检查最终卷。结果是新 GUI 下游可能带着背景配置空缺进入打包，直到 Finder 布局阶段才失败，也无法从初始化基线追溯构建实际消费的图片。
- 决定：`$desktop-initialize-rust-project` 携带一张无产品、Harness 或第三方身份的 660×400 PNG；选择 GUI 时，在删除初始化能力前逐字节复制为 `<项目标识>_gui/src-tauri/dmg/background.png`。`$desktop-add-gui-adapter` 把 `tauri.conf.json` 的 `bundle.macOS.dmg.background` 固定为 `./dmg/background.png`，窗口固定为 660×400，应用与 Applications 落点分别为 `(180, 220)` 与 `(480, 220)`。初始化源资产只负责建立基线，运行时和构建只能消费项目内副本。
- 视觉批准与构建决定：首次真实 GUI 开发由 `$desktop-prepare-gui-app-identity` 展示该基线，让用户批准或在同一路径替换，并在 `docs/GUI_APP_PROFILE.md` 记录当前 SHA-256、尺寸、落点和文案语言。`$desktop-build-tauri-release` 在任何测试前校验项目内图片为非符号链接 660×400 PNG、摘要与资料一致、Tauri 配置仍引用固定路径；随后仍须对最终 DMG 只读验证 `.DS_Store`、背景、唯一应用包与 Applications 链接。源码图片检查不能替代最终卷检查。
- 影响范围：最新 Product Spec、AGENTS/README、Rust/GUI 基线、实例化/初始化/GUI 身份/GUI adapter/Tauri 构建 Skills、Harness 必需文件与初始化/发布 validator、专项回归和当日 Changelog。
- 不包含：不创建具体下游项目，不生成应用图标，不替任何产品批准正式视觉，不构建 DMG/NSIS，不运行 E2E、签名、公证、stapling 或发布；其他平台保持 `Unverified`。
- 理由：把一张真实、无产品身份的图片放进一次性初始化载荷，可以让每个 GUI 下游从首个提交起拥有可解析、可预览且可由 Tauri 直接消费的背景；固定项目内路径避免初始化 Skill 裁剪后出现悬空引用，同路径替换又保留正式产品定制空间。
- 风险：中性图片可能被误认为正式品牌资产，固定尺寸和坐标可能不适合未来产品文案，生成图片的文字或构图也可能在缩放后失真。通过明确“待 GUI 身份批准”、固定预览步骤、尺寸/摘要门禁、允许同路径替换和最终 DMG 只读检查降低风险。
- 验证：解析 PNG 签名和 IHDR，确认资产为 660×400、非空且非符号链接；视觉检查文字准确、箭头方向与两个落点区域；新增初始化资产尺寸负向回归与 Tauri 构建引用负向回归；运行相关 Python 单元测试、默认 discovery、完整 Harness validator、变更 Skill quick validator 和差异检查。本次不构建真实下游或候选。
- 恢复或调整标准：若真实下游证明其他尺寸、坐标或无文字背景更可靠，项目负责人可更新中性资产与唯一基线值，并同步初始化、GUI 身份、Tauri 配置、构建门禁和回归；不得通过移除项目内背景、跳过视觉批准或只检查源码配置来绕过最终 DMG 布局证据。

## ADR-20260824-001：日常开发收敛为必要单元测试，构建逐次确认 E2E 并运行全量单元测试

- 日期：2026-08-24
- 状态：Accepted
- 关联需求：项目负责人要求收敛每次开发流程，除必要 ADR、Changelog 等事件触发记录和本次开发需要的单元测试外，不增加额外步骤；每次构建必须全量运行单元测试，并询问用户是否启用 E2E。
- 背景：现有 Harness 把任务分为快速、标准、里程碑三档，多步骤或中等风险开发会自动引入持久 Work Plan，所有实现轮次还强制执行文件行数、中文声明注释、lint/静态等全仓门禁；E2E 则只在里程碑末端按持久策略解析，构建阶段明确禁止询问或消费。这套分层虽然审计完整，但与项目负责人要求的日常最短开发闭环和逐次构建选择不一致。
- 开发决定：日常开发统一直接进入 `$desktop-implement-change`，只完成当前批准范围、增加或更新本次必要的单元/回归测试并运行这些测试。不得仅因多步骤、多模块、中等风险、可并行或 Agent 偏好自动增加 `$desktop-plan-change`、Work Plan、全仓测试、格式化、lint、静态检查、构建、冒烟、E2E、Verification 或人工复核。Product Spec、ADR、Changelog、Product Status、Work Plan 与 Verification 仍按各自真实事件触发；用户明确要求计划、跨会话交接、发布/审计或必要风险边界时可以单独启用对应能力。
- 构建决定：显式构建在任何测试或编译前必须解析一次“当前构建是否启用 E2E”。若用户已在当前构建请求中明确选择则复用且不重复询问，否则询问一次；`docs/AGENT_POLICY.md` 的 `milestone_e2e` 仅是建议默认值，不能替代逐次选择。构建必须运行项目全部非空单元测试：Rust 使用 workspace/all-targets/all-features 的锁定测试，GUI 同时运行完整 Rust workspace 和前端单元测试套件；失败或零测试阻断候选。
- 阶段边界：E2E 不混入单元测试、编译、签名或打包命令。当前构建选择为启用或产品/渠道硬要求时，只在最终真实候选形成后由验收/E2E 能力执行；禁用时记录 `Not run` 与剩余风险。安全、隐私、数据迁移、破坏性操作、生产/付费/凭据副作用、对外兼容契约、签名、发布和渠道要求仍保留解决当前风险所必需的授权与门禁，不得被“精简开发”解释为绕过。
- 取代范围：本决定取代 2026-08-03 起“每项任务必须选择快速/标准/里程碑，复杂开发自动建立 Work Plan”以及“构建阶段不得解析 E2E 选择”的长期流程要求；此前关于真实候选、core-first、非 Mock 验收、签名公证、跨平台状态和人工发布复核的决定继续有效。
- 影响范围：最新 Product Spec、AGENTS/README、Agent Policy、工程规则、Rust/发布/验证文档、规划/实施/构建/验收/E2E/升级与适配器 Skills、Harness validator、候选 workflow 契约、回归测试和当日 Changelog。
- 风险：只运行本次相关单元测试可能延后发现跨模块、格式、静态或平台退化；逐次询问 E2E 会增加构建前一次交互；持久 E2E 偏好与当前选择可能被混淆。通过在显式构建中强制全量单元测试、让发布/渠道继续保留必要门禁、把持久值严格限定为建议默认值、并要求 E2E 只针对最终真实候选来降低风险。
- 验证：为开发最小闭环、构建逐次 E2E 解析和 Rust/GUI 全量非空单元测试增加确定性 validator 与负向回归；运行相关 Python 单元测试、默认 discovery、完整 Harness validator、统一文件行数门禁和差异检查。本次不构建真实下游、不运行 E2E、签名、公证或发布，这些范围保持 `Unverified`。
- 恢复或调整标准：若真实下游证明开发期必须恢复某项普遍门禁，应由项目负责人明确该门禁、触发条件和成本后以新 ADR 调整，不得通过 Skill 自行恢复全套流程；若逐次 E2E 选择造成不可接受的自动化阻断，可改为用户明确的构建参数，但仍必须逐次解析且不得仅依赖持久偏好。

## ADR-20260820-002：把产品家族品牌支持资源作为条件 GUI 依赖完整传播（运行时 sponsor 默认打包已由 ADR-20260827-001 取代）

- 日期：2026-08-20
- 状态：Accepted
- 关联需求：项目负责人要求再次检查真实下游的关于页、赞助页、相关约束与模板，并进一步确认支付二维码、固定价格/联系人、品牌更新 banner 和未使用小图都应整体进入 Harness，因为本 Harness 产出的下游共享同一品牌；来源下游自身的项目名称等仍不得同步。
- 背景：只读审计确认来源有 12 张赞助图片和 1 张更新 banner，没有已跟踪视频。真实页面同时固化三档赞助价格、品牌联系人、双支付码与中英文品牌赞助说明；关于页还混有来源产品名、产品功能、路由和更新服务。ADR-20260820-001 曾基于去身份化原则排除全部资源，但项目负责人随后明确：工作室品牌、赞助材料和更新视觉不是单一下游身份，而是所有产出产品共享的品牌事实。
- 边界决定：补充并在资源传播范围上取代 ADR-20260820-001 的“Harness 只传播 Skill/参考且不复制资源”限制。`$desktop-prepare-gui-support-surfaces` 必须携带完整品牌依赖包：13 个原始图片字节、固定赞助档位/价格、品牌联系人、中英文品牌赞助文案、产品实例文档模板、媒体清单、类型化 React 页面/媒体组件与非空组件测试。GUI 下游完整保留该 Skill 资产；只有产品明确选择关于、赞助或更新视觉后，相关文件才进入应用 bundle，选择 GUI 本身仍不自动创建页面、路由或网络请求。
- 身份隔离决定：共享工作室名称、联系人、赞助价格、支付二维码与 banner 是明确批准的品牌资产；来源下游的产品名称/标识、产品功能文案、路由、版本、固定服务地址、更新/遥测协议字段、秘密、签名身份、绝对路径与历史证据仍必须排除。终端下游按需生成的 `docs/GUI_SUPPORT_SURFACES.md` 继续由升级器保护，Harness 只提供 `.template.md`，不得把某个产品实例作为所有产品的完成事实。
- 支付与媒体决定：媒体清单逐文件记录路径、MIME、尺寸、SHA-256、用途、品牌/支付敏感性、复制来源类别和内部专有复用批准。支付二维码必须保持原始字节且不得优化、重绘或解码后重建；携带或展示静态支付码不授权订单、权益、账户、自动支付、支付状态确认或生产副作用。图片必须提供语义化 `alt` 或显式装饰声明。来源没有视频，因此不伪造视频文件；媒体组件仍要求本地视频使用 controls、字幕轨、文字稿、可选 poster、禁止 autoplay 与远程追踪，并尊重 reduced motion。
- 页面决定：关于页保持产品名、版本、功能区块和动作由当前下游事实注入，但默认复用品牌联系人；赞助页默认消费品牌档位、文案与全部赞助资源，同时修复来源的固定 800px、固定三栏、全页 `pointer-events: none` 和支付图片缺少替代文本问题。未使用小图不删除，按原文件完整打包并在清单中标为可选/当前未引用；更新 banner 只作为本地视觉资源，不隐式启用更新检查或固定 endpoint。
- 影响范围：最新 Product Spec、AGENTS/README、工程规则、Rust/GUI 基线、`$desktop-prepare-gui-support-surfaces` 的参考与依赖资产、GUI 初始化/升级条件传播、Harness validator、专项回归、当日 Work Plan、Product Status 与 Changelog。
- 理由：产品家族共享品牌时，保留原始品牌与支付资产能避免每个下游重复复制或错误替换，并保持赞助信息一致；条件安装、产品实例保护和严格排除来源项目身份仍能维持 scaffold 与具体产品之间的边界。
- 风险：支付码、价格和联系方式可能过期或被误用于未获批准页面；原始图片的逐文件外部来源记录不足；未使用图片会增加仓库和包体积。通过专有内部复用批准记录、摘要锁定、敏感性标记、只有已选界面才进入 bundle、付款说明人工复核、无自动交易逻辑和未来品牌复核条件降低风险。
- 验证：逐字节比较 13 个目标资产与来源、解析并核对图片尺寸/MIME/SHA-256、视觉检查品牌 banner 与支付码未被改写；对模板运行 TypeScript 与非空 Vitest/Testing Library 前向测试；验证响应式布局、图片替代文本、视频无 autoplay 且需要字幕/文字稿；运行 GUI 支持专项正负向回归、升级 conditional ownership 回归、完整 Harness validator、统一行数门禁、链接/差异扫描，并证明来源下游产品名、标识、固定服务地址和秘密没有进入资产包。
- 恢复或调整标准：品牌联系人、价格、支付码或视觉更新时必须由项目负责人重新确认，替换后更新清单摘要与相关测试；若产品家族不再共享该品牌，则恢复去身份化资产或把品牌包迁出通用 Harness。若未来加入真实视频，必须先记录来源/内部复用批准、字幕、文字稿、poster、体积预算和打包路径，再通过同一条件传播与 validator 门禁。

## ADR-20260820-001：从真实终端下游反向抽象 GUI 支持界面与 Tauri 分发门禁，同时隔离产品身份

- 日期：2026-08-20
- 状态：Accepted
- 关联需求：项目负责人要求从用户指定、已经过真实使用磨合的终端下游中抽象并同步 Harness 工程改进到模板，反复检查到没有遗漏，同时不得同步该下游的项目名称、品牌或其他产品实例。
- 背景：来源锁与 Git 历史显示，终端下游在既有 Harness 基线上积累了三类可复用改进：Homebrew 将 LLD 从 LLVM 拆包后的 xwin 工具链处理、使用已授权 `notarytool` Keychain profile 的公证探测、以及 GUI 支持界面和 DMG Finder 拖拽布局。来源同时包含产品名称、联系人、赞助资源、固定服务字段、秘密常量、签名身份和打包图片；直接复制会把一个产品的身份、安全缺陷和业务协议变成所有下游的默认值，也会违反中性 scaffold、core-first、升级保护和秘密隔离规则。
- 抽象决定：反向同步采用“来源锁基线 → 终端下游当前字节 → 当前模板工作树”的三方审计。只接收能脱离产品身份成立、具有明确失败模式和非空回归的工程能力；产品名称/标识、联系人、资源、固定 endpoint/协议字段、秘密、签名身份、版本、产物、哈希、验证结论和业务实现一律排除。来源路径和名称只用于当前任务只读审计，不进入长期 Harness 规则、Skill、脚本、参考或产品事实。
- GUI 支持界面决定：新增条件 Skill `$desktop-prepare-gui-support-surfaces`。窗口标题、关于/帮助/赞助入口、更新检查和遥测彼此独立，只有已批准 GUI 产品明确选择的项才实现；中性 scaffold 不预装页面、路由、资源、配置或网络请求。终端下游按需创建的 `docs/GUI_SUPPORT_SURFACES.md` 保存产品实例并由升级器保护，Harness 只传播 Skill/参考。展示与宿主机制属于 GUI adapter，跨接口资格、值域、默认值和状态转换属于 core；涉及权益、支付、账户、自更新、强制更新或渠道发布时必须另行定范围。
- 出站与秘密决定：每项远程能力默认禁用并具有独立的目的、触发器、方法、允许地址/字段/响应、重定向、超时、响应大小、重试/并发、owner/取消/关闭、日志、同意与保留清单。可选网络失败默认 fail-open，但不得把失败解释为成功；禁止 detached task 和无限重试。遥测默认关闭并要求字段级最小化、同意/退出、标识符生命周期、保留与删除边界。秘密实值只来自已批准安全运行时来源，不能进入源码常量、文档、配置样例、测试夹具、日志或前端 bundle。
- Tauri 分发决定：macOS→Windows xwin 环境门禁分别探测/安装/复探 Homebrew `llvm` 与可能拆分的 `lld`，已存在但缺少命令的 formula 失败关闭而不静默重装。Apple 公证允许一组完整环境凭据或已授权且在线可用的 Keychain profile，两种模式互斥，探测不输出 profile 名或秘密。macOS DMG 必须在最终布局、签名、公证和 stapling 后只读挂载真实字节，验证非空 `.DS_Store`、本地背景、唯一顶层应用包和指向 `/Applications` 的链接，再计算摘要；里程碑验收对当前最终字节重跑同一检查，不得自动接受软件许可或沿用旧候选证据。headless CI 不得无界等待 Finder AppleScript，任何后处理都使旧签名、摘要与验收证据失效。
- 影响范围：最新 Product Spec、AGENTS/README、工程规则、Rust/GUI 基线、GUI 身份/适配器/初始化 Skills、新支持界面 Skill、Tauri 构建与环境 Skills、发布文档、升级 ownership policy/manifest、Harness validator、专项测试、当日 Work Plan、Product Status 与 Changelog。
- 不包含：不修改终端下游，不复制其名称、路径、品牌、联系人、资源、服务端协议、秘密、签名/公证身份、候选或历史证据；不在模板创建 `docs/GUI_SUPPORT_SURFACES.md`；不实际构建 DMG/NSIS，不运行冒烟/E2E，不签名、公证、staple、上传、tag、push 或发布。
- 理由：真实下游暴露的环境兼容和打包失败比假设性设计更能证明 Harness 缺口，但只有剥离产品实例并把安全边界改为默认禁用、最小授权和最终字节验证，才能安全传播到未知下游。条件 Skill 和受保护实例文档让方法可以升级，而产品事实不会被模板或其他产品覆盖。
- 风险：文本门禁只能证明规则和已知身份没有直接泄漏，不能证明未来调用者不会填入不合规产品实例；Finder 布局 helper 的模拟挂载回归不能替代真实 DMG 前向证据；Keychain profile 在线探测依赖 Apple 服务可用。通过固定地址拒绝、模板实例文件缺失门禁、条件 ownership 顺序、秘密来源规则、专项失败路径测试、最终双向来源审计和 `Unverified` 标记降低风险。
- 验证：运行 xwin、公证与 DMG 布局专项回归，Skill 结构校验，GUI 支持界面中性/固定地址负向回归，升级条件规则顺序回归，默认 Python discovery、完整 Harness validator、统一文件规模检查、Rust 中性资产门禁、Markdown 链接、差异和身份/固定凭据扫描；真实 DMG/NSIS、Windows/Linux、签名、公证、冒烟/E2E 与发布均不记为通过。
- 恢复或调整标准：若真实下游证明某项支持界面需要稳定的跨产品 schema，应先以去身份化、默认禁用和兼容迁移证据提出新决定，不得直接复制产品协议。若 Tauri/Apple/Homebrew 官方行为变化，应以新的前向失败和官方资料调整探测或布局门禁；不得通过移除最终字节检查、输出 profile/秘密或恢复产品默认值来绕过。

## ADR-20260812-001：扩展 Rust/GUI 技术事实标准并建立收敛的中文声明注释门禁

- 日期：2026-08-12
- 状态：Accepted
- 关联需求：项目负责人要求从本机两个成熟下游 Harness 同步有意义的 Rust、前端技术选型，并把中文注释门禁优化到当前 Agent-first Harness。
- 背景：Rust 来源提供了 HTTP middleware、配置、可观测性、协议/存储/认证候选和可执行中文注释检查器，但采用单 package/single-bin Server 架构、默认多线程 runtime，直接复制会违反当前 workspace/core-first 与四类独立适配器边界。Web 来源补齐 Vite、文件路由、严格 TypeScript、前端质量工具链、Mantine 规范、配置/日志/Release 扫描和 TypeScript AST 注释检查思路，但其中文门禁工作计划仍未完成，机械检查全部局部变量与匿名回调，并自动生成数百条“保存变量”“执行处理逻辑”式套话，与当前语义注释和闭包豁免规则冲突。两个来源工作树均有未提交内容，因此本决定以用户指定的本机工作树字节作为审计输入，不把来源 `HEAD` 当成这些能力的发布溯源。
- Rust 技术决定：获批 HTTP 服务固定使用 Tokio + Axum + Tower/Tower HTTP；真实配置固定使用 config-rs，`notify` 仅用于批准的窄热重载；本地结构化日志正式固定为 tracing + tracing-subscriber + tracing-appender，OpenTelemetry OTLP/HTTP 只有在产品、隐私、采样、endpoint 和失败行为获批后默认关闭地追加。每个 spawned task 必须有 owner、取消、并发上限和关闭回收，禁止 detached task；timeout 不等于业务成功，锁不得跨越不受控 `.await`，HTTP 在监听前完成必需检查并支持 graceful shutdown。
- 条件技术决定：OpenAPI 使用 utoipa + utoipa-axum + Scalar code-first；GraphQL 使用兼容的 async-graphql + async-graphql-axum；非关系型能力优先官方 MongoDB async driver 与 redis-rs Tokio；本地认证优先 jsonwebtoken + Argon2id。这些只是能力触发后的固定候选，不进入中性依赖，且不得绕过消费者、数据、隐私、安全、密钥和生命周期范围闸门。本条扩展而不取消 ADR-20260805-003 的 Tokio、Clap、SeaORM、anyhow、thiserror、serde 与 jiff 事实标准。
- GUI 技术决定：Tauri React 前端固定追加 Vite、TanStack Router 文件路由与自动 route code splitting、严格 TypeScript、ESLint/`typescript-eslint`、Prettier、Vitest、Testing Library、jest-dom、user-event 与 jsdom。`src/routeTree.gen.ts` 是唯一生成路由树并按根相对精确排除。Mantine 采用单 Provider/单 theme、语义令牌、稳定样式优先级、完整交互状态、窄窗口/文本缩放、键盘/焦点/live region 和 Testing Library 语义测试规范。
- GUI 配置与日志决定：`development/test/release` 是统一逻辑 profile，但只有真实公开配置出现时才建立配置文件和类型化冻结对象；所有 Vite 变量均视为用户可读，禁止凭据，产品模块不得散落读取 `import.meta.env`。真实前端日志使用稳定 `level/scope/event/context` 和严格脱敏，Tauri 优先通过窄命令汇入 Rust tracing，不建立第二套持久日志或默认远程遥测。Release 在 Tauri 打包前静态检查最终 Vite `dist`，拒绝 source map、开发/测试 endpoint、debug/info 哨兵、本机绝对路径和未经批准的 console 输出。
- Rust 注释门禁决定：下游永久保留 workspace-aware `check_rust_chinese_comments.py` 及专项测试。检查器从 Cargo package/virtual workspace 根解析全部 members，扫描每个 package 的 `build.rs`、`src/**/*.rs` 和 `tests/**/*.rs`，机械覆盖 struct、enum、union、type alias、trait、具名函数、关联函数、方法和测试；要求声明自身紧邻且包含汉字的 outer doc comment，支持中间 attribute。它不要求字段、局部变量、闭包和宏展开产物，且以稳定 JSON、根相对 path/line/column/kind/name 和退出码 0/1/2 区分通过、声明违规与运行错误。
- TypeScript 注释门禁决定：只有选择 GUI 的下游才复制并运行随 `$desktop-add-gui-adapter` 提供的 TypeScript Compiler AST 参考检查器。机械范围收敛为 interface、type alias、enum、class、具名函数、方法/访问器/构造器、直接及后置命名/默认导出的箭头组件/hooks，以及测试文件或显式 `vitest` 导入中的 `test`/`it` 场景；字段、局部变量、循环绑定、业务同名调用和普通匿名/极短回调继续由所属结构/函数注释覆盖。门禁同时接入 `pnpm lint` 与项目 validator，精确排除生成路由树，并对语法残缺、非法 UTF-8、NUL、源码符号链接和空扫描失败关闭。非 GUI 下游不得因该门禁要求 Node.js/pnpm。
- 语义边界：两类检查器都只证明注释存在、归属正确且至少含一个汉字，不能判断业务意义、正确性或时效；人工/Agent 仍按 `docs/ENGINEERING_RULES.md` 复核。禁止提供自动注释器或批量生成套话，门禁不得扩张为注释比例、字符数或关键词质量评分。
- 影响范围：最新 Product Spec、AGENTS/README、Rust/GUI 基线、Mantine 参考、工程规则、初始化/实施/重构/适配器/构建/验证/升级 Skills、升级所有权、Harness validator、中文注释检查器与回归、当日 Work Plan 和 Changelog。
- 不包含：不复制来源的单 crate Server 或 Web/Extension/Plasmo/Chrome 架构，不新增独立 WEB adapter，不改变 core-first/current-thread/Tauri runtime/i18n/依赖锁定规则，不预装条件依赖，不捆绑页面或业务起始资产，不修改中性 Cargo 资产或锁文件，不构建、验收或发布真实下游候选。
- 理由：同步能力事实而保留当前架构边界，可以复用来源中成熟的生态组合和 AST/诊断思路，又避免把宿主专用架构与低价值注释噪音引入通用 Harness。workspace-aware、失败关闭和双接线能覆盖 Agent 容易遗漏的声明归属；保留有限豁免和语义复核可以让注释质量高于机械覆盖率。
- 风险：自维护 Rust 词法扫描器无法完整展开过程宏或替代 rustc；TypeScript 参考检查器尚未由本 Harness 真实生成到下游；前端最终产物扫描规则可能需要按真实配置字段扩展。通过 Cargo/Clippy/测试补充语法与宏边界、专项负例、Harness bridge、能力触发、精确排除、首次真实 GUI 下游前向证据和 `Unverified` 标记降低风险。Rust 检查器 501–2000 行候选已复核为单一“Cargo workspace Rust 声明注释检查”职责，内部的 workspace 枚举、词法识别、诊断和 CLI 都服务同一结果模型，因此当前保留为一个高内聚文件。
- 验证：运行 Rust 检查器专项回归与 Harness bridge 回归；对完整中性 Rust workspace 单次根调用验证全部成员；使用来源 Web 已安装的 TypeScript/Vitest 只读依赖执行 GUI 参考检查器专项测试；运行默认 Python discovery、完整 Harness validator、行数门禁、Markdown 链接、升级器回归和差异检查。没有真实 GUI 初始化/构建候选，因此该前向范围保持 `Unverified`，不得声称已交付真实 GUI scaffold。
- 恢复或调整标准：真实下游若证明某项固定技术不满足 MSRV、Node/WebView、平台、安全、性能或渠道要求，必须用新硬规则例外 ADR 记录替代证据与迁移/恢复标准。若机械门禁稳定误报或漏报受管声明，应先补回归并收窄/修正 AST/词法规则；不得以降低语义要求、扩大目录排除或重新引入自动套话作为恢复方式。

## ADR-20260806-003：文件规模治理改为 500 行语义复核与 2000 行硬门禁

- 状态：Accepted
- 关联需求：项目负责人明确要求单文件超过 500 行时基于业务高内聚、职责单一和职责相近性考虑拆分，不满足即重构；超过 2000 行必须强制拆分；Rust 文件结构继续采用目录/`mod.rs` 形式。
- 背景：ADR-20260805-002 把全部人工维护文本设为 400 行硬上限，能够强制早期拆分，但也会机械拒绝职责高度集中且仍可独立审阅的文件。新的治理目标是把架构质量判断放回真实职责边界，同时保留一个不可降级的极端文件规模上限。
- 决定：所有人工维护文本超过 500 个物理行时必须进入语义复核，逐项判断业务是否高内聚、是否围绕单一职责、各部分职责是否相近；三项均成立时可以保留至 2000 行，任一项不成立时必须按真实职责重构拆分。超过 2000 行无条件失败并强制拆分，2000 行通过、2001 行失败。
- Rust 结构：Rust 模块拆分统一使用 `<module>/mod.rs` 作为目录入口，职责相近的子模块置于该目录；不得以同级 `<module>.rs` 加同名目录或空壳转发层规避职责判断。
- 自动化边界：统一检查器机械列出 501 至 2000 行的复核候选，但不替代 Agent 的语义判断；只有超过 2000 行或检查器运行错误时返回失败。生成锁文件/生成物和原样隔离第三方文件继续沿用封闭范围排除。
- 替代关系：本决定明确替代 ADR-20260805-002 中“人工维护文本最多 400 行、401 行失败且无例外”的行数阈值、完成门禁和恢复标准；该 ADR 的项目记忆事件触发决定及历史实施事实继续有效。
- 理由：500 行阈值促使 Agent 在文件规模开始影响审阅时进行职责分析，避免为行数而拆出低内聚的空壳文件；2000 行硬门禁防止语义复核被用作无限增长的豁免。
- 风险：语义复核比单一阈值更依赖判断，可能出现不一致。缓解方式是检查器稳定列出候选，执行 Skill 强制报告三项判断，Rust 拆分结构保持确定性，2000 行以上继续机械失败。
- 验证：覆盖 500/501/2000/2001 行边界、Git 可见范围、生成文件排除、CLI 退出码与 Harness 报告接线；运行默认 Python 回归、完整 Harness validator、现行阈值引用扫描和差异检查。
- 恢复或调整标准：若 500 行语义复核长期产生不可接受的一致性或审阅成本，可由项目负责人重新调整复核字段或阈值；不得在没有新决定时放宽 2000 行硬门禁。

## ADR-20260806-002：新增异步优先、Tracing 落盘可读日志与产出物真实可用验收三项硬规则

- 日期：2026-08-06
- 状态：Accepted
- 关联需求：项目负责人明确要求为 Harness 新增三项约束：(1) 能使用异步的场景默认使用异步；(2) Tracing 可观测信息必须落盘到日志文件，且格式便于人类阅读与分析；(3) 所有产出物的验收都以真实可用为准，禁止以 Mock 冒充验收证据；并要求把三项约束转化为对 AI Agent 友好、可执行的表达写入 Harness 工程文档。
- 背景：现有规则已经把异步优先限定在 Rust 适配器的 I/O/等待/计时/进程/协议范围（`AGENTS.md`、`docs/RUST_CLI_TEMPLATE.md`），core 侧只是“可以”暴露 `async fn` 而非默认；tracing 已被 ADR-20260805-003 固定为可观测性标准，但只约束事件/span 结构化与脱敏，未规定落盘位置和可读性；`docs/VERIFICATION.md` 与 `docs/ENGINEERING_RULES.md` 已在里程碑验收层面禁止 Mock/stub/占位冒充真实候选，但未把“真实可用优先于 Mock”提升为覆盖全部产出物验收（含快速/标准路径完成声明）的通用原则，也未与既有测试隔离规则（对不可控外部依赖如网络、时间的合理测试替身）划清边界。三项都是长期、难以逆转的工程判断标准，按规则须记入当日 ADR。
- 决定：
  - **异步优先**：下游 Rust core 与全部适配器只要存在真实 I/O、等待、计时、进程、协议或跨边界调用，默认必须实现为异步（`async fn`），只有确认调用链纯 CPU 密集、无等待点、无跨边界调用时才保留同步实现；core 暴露的默认操作签名优先异步而非“可以选择异步”，且保持运行时中立（不出现 `tokio::runtime::Handle`、`JoinHandle`、Tokio 套接字或适配器类型），只有真实业务需要 Tokio 具体原语时才增加 core 的 Tokio 生产依赖。本决定强化而不替代 `docs/RUST_CLI_TEMPLATE.md` 现有“异步与运行时边界”一节的 CPU 密集判断、`spawn_blocking` 使用条件与例外记录要求。
  - **Tracing 落盘可读日志**：已启用 tracing 的下游 Rust 项目必须把结构化 event/span 同时写入本地日志文件，不得只写标准错误或丢弃；日志文件必须使用便于人类直接阅读与检索的格式，至少包含时间戳、级别、目标 target 与事件消息，并支持按时间或大小滚动避免无限增长；标准输出继续保持 `docs/CLI_CONTRACT.md` 规定的单一 JSON 文档，不得被日志污染。日志文件默认写入项目约定的本地日志目录，不得记录密钥、令牌、个人数据或未脱敏业务载荷，沿用 ADR-20260805-003 已有的脱敏要求；推荐通过 `tracing-subscriber` 的可读 `fmt` layer 搭配 `tracing-appender` 之类的滚动文件 writer 实现，或等效方案。
  - **验收以真实可用为准**：任何路径（快速、标准、里程碑）对产出物给出“完成”“可用”“已验证”结论时，必须以真实运行、真实调用产出物本身得到的可观察结果为依据；模拟实现、测试替身、占位页面、中性脚手架、开发预览、仅调用内部函数或仅展示 Mock 数据的结果不得被称为验收通过。该决定与既有测试隔离规则并行不冲突：单元/集成测试仍可以为不可控外部依赖（网络、当前时间、随机性、用户主目录等）使用受控测试替身以保证确定性，但测试替身证明的是代码单元内部正确性，不能被引用为“产出物已经真实可用”的验收证据；里程碑路径现有的真实候选、绑定源码提交和运行环境要求不变，本决定把同一判断标准明确扩展到快速/标准路径的完成声明措辞。
- 影响范围：`AGENTS.md`、`docs/RUST_CLI_TEMPLATE.md`、`docs/VERIFICATION.md`、最新 Product Spec、当日 Changelog。
- 不包含：不新增机械门禁强制扫描“未落盘的 tracing 调用”或“未异步化的函数”，语义判断仍由人工/Agent 依据代码执行路径审查；不改变里程碑路径已有的真实候选、签名、冒烟/E2E 门槛；不改变既有测试隔离规则允许的替身范围；不为中性初始化脚手架无条件添加日志文件写入依赖，只在真实业务出现 tracing 使用路径时按需引入 `tracing-subscriber`/`tracing-appender` 等配套 crate。
- 风险：把“异步优先”误读为强制所有函数异步化会在纯 CPU 密集路径引入不必要的运行时开销；日志落盘若配置不当可能无限增长或记录敏感信息；“真实可用验收”若与测试隔离规则混淆，可能被误用为禁止一切测试替身，损害测试的确定性和可重复性。通过保留 CPU 密集例外、复用现有脱敏与滚动要求、以及明确测试隔离与产出物验收的边界来降低风险。
- 验证：静态核对 `AGENTS.md`、`docs/RUST_CLI_TEMPLATE.md`、`docs/VERIFICATION.md`、最新 Product Spec 新增片段与本决定一致；运行默认 Python 回归（`python3 -m unittest discover -s scripts`）与 `python3 scripts/validate_harness.py` 确认文档链接、必需片段和文件行数门禁未退化。
- 恢复或调整标准：若真实下游证明某类操作因目标平台、宿主强制同步 API 或测量证据不适合异步化，必须按硬规则例外记录理由、影响范围和恢复条件；若日志落盘格式或位置需要适配特定部署环境，须由项目负责人明确确认后以新 ADR 调整；本决定持续有效直至被新的明确决定替代。

## ADR-20260806-001：固定下游 GUI i18n 技术选型事实标准，界面国际化成为开发期硬性必选项

- 日期：2026-08-06
- 状态：Accepted
- 关联需求：项目负责人明确要求在开发 GUI 工具时，i18n 支持是开发期必选项而非可选增强；要求为 Rust 后端与 React 前端分别确定成为事实标准的 i18n 框架；默认语言必须跟随系统语言；界面必须提供可发现的语言切换入口；并要求把上述约束整理写入文档与 Skill。
- 背景：`$desktop-add-gui-adapter` 此前只固定了 Tauri 2 + React + TypeScript + Mantine UI + TanStack Router + TanStack Query + Jotai 技术栈（见 ADR-20260805-001 与 `docs/RUST_CLI_TEMPLATE.md`），未对界面文案的国际化方式、系统语言探测来源和语言切换入口作出约束；缺少事实标准会导致不同下游各自选型、探测方式不一致、Rust 侧原生文案（托盘、通知、原生菜单）与 React 侧界面文案使用不同的语言状态来源，产生体验分裂和维护成本。
- 决定：
  - Tauri GUI 前端固定使用 `i18next` 搭配 `react-i18next` 作为 React 界面文案国际化事实标准，负责翻译资源加载、参数插值、复数规则和组件层语言消费；这是当前 React 生态最广泛采用的 i18n 组合，与已固定的 Mantine/TanStack/Jotai 技术栈均有成熟集成先例。
  - Tauri Rust 后端（GUI adapter 层，不含 core）固定使用 `rust-i18n`，负责系统托盘菜单、原生窗口标题、系统通知等未经过 React 渲染路径、必须由 Rust 直接产出的用户可见文案；`rust-i18n` 是 Rust 生态中该场景下载量与采用率最高的宏驱动 i18n crate。
  - 系统语言探测统一使用官方 Tauri 插件 `tauri-plugin-os` 的 `locale()` API，在应用启动时获取一次操作系统 BCP-47 locale，作为前端 `i18next` 初始化语言和 Rust 端 `rust-i18n` 当前语言的唯一探测来源；不得分别依赖 WebView 的 `navigator.language`、环境变量或平台专有 API 造成前后端探测结果不一致。
  - i18n 接入在 GUI 开发中是硬性必选项：任何真实产品 GUI 首次向用户交付带文案的页面、命令结果或原生机制文案时，必须同步接入上述 i18n 技术栈，不得以“当前只支持一种语言”“页面简单”为由推迟；中性初始化脚手架阶段允许暂不接入，但首次业务页面/命令必须已满足本决定。
  - 默认语言必须在首次启动时使用 `tauri-plugin-os` 探测到的系统 locale；探测到的语言没有对应翻译资源时回退到英文。GUI 必须提供可发现的语言切换入口（如设置页或菜单项），用户手动切换后的选择必须持久化并在后续启动时覆盖系统探测结果，直至用户重置。
- 能力边界：固定选型表示 GUI 能力被选中且进入首次真实页面/命令开发时必须采用，不表示中性初始化无条件预装；未选择 GUI 的下游不引入 `i18next`、`react-i18next`、`rust-i18n` 或 `tauri-plugin-os`。具体已支持的语言列表、翻译文案内容和文案来源由下游产品按真实需求确定，本决定不预设任何具体语言集合。
- 架构边界：翻译资源、语言判断、区域化格式化和语言切换交互属于 GUI 前端与 Tauri 适配层职责；core 必须保持语言无关，只暴露稳定、语言中立的领域错误标识、结构化数据和机器可读时间戳（沿用既有 jiff 决定），由 GUI 适配器和 `i18next` 把错误标识、数值和日期时间映射为当前语言的展示文案。不得把翻译文案、语言选择逻辑或区域化格式化规则下沉到 core，即使当前只有 GUI 一个消费者也同样适用；这与 ADR-20260805-001 的 core-first 边界一致。
- 依赖边界：前端依赖通过 pnpm 包清单与锁文件引入 `i18next`、`react-i18next`；Rust 端依赖通过根 `[workspace.dependencies]` 声明 `rust-i18n` 与 `tauri-plugin-os`，且只在 GUI 适配器成员中启用，不得让 core 或其他适配器依赖上述任一 i18n 包。用户语言偏好是 GUI 本地的设备级展示偏好而非权威业务状态，必须由 GUI 适配器自有的本地持久化位置（而非共享 core 的持久化层）保存，不得借此新建第二套业务数据权威副本。
- 影响范围：`docs/RUST_CLI_TEMPLATE.md`、`.agents/skills/desktop-add-gui-adapter/SKILL.md`、`.agents/skills/desktop-add-gui-adapter/references/gui-baseline.md`、`.agents/skills/desktop-add-gui-adapter/references/react-frontend-baseline.md`、`AGENTS.md`、最新 Product Spec、当日 Changelog、`scripts/harness_validation_governance_tests.py` 中引用最新 Product Spec 文件名的回归。
- 不包含：不实现任何具体产品的翻译文案或语言列表；不构建、验收或发布候选；不为 CLI/TUI/MCP 适配器引入 i18n 义务（当前决定范围限定在 Tauri GUI）；不新增机械门禁强制校验文案是否已翻译，该项留待真实下游出现具体页面后按需评估。
- 风险：把“必选项”误读为初始化阶段无条件预装会增加中性脚手架体积；把语言判断或翻译文案下沉到 core 会破坏 core 语言中立性并可能诱发第二套展示状态；分别探测系统语言会造成 Rust 原生文案与 React 界面文案语言不一致。通过能力触发、core-first 架构边界重申、统一 `tauri-plugin-os` 探测来源和本决定的机械回归降低风险。
- 验证：静态核对 `rust-i18n`、`react-i18next`/`i18next`、`tauri-plugin-os` 在 GUI baseline、React 前端 baseline、`$desktop-add-gui-adapter` SKILL 和 `docs/RUST_CLI_TEMPLATE.md` 中的职责、能力触发与 core/adapter 边界描述一致；运行默认 Python 回归、完整 Harness validator、Markdown 链接和文件行数检查确认无退化。
- 恢复或调整标准：若真实下游证明 `i18next`/`react-i18next`、`rust-i18n` 或 `tauri-plugin-os` 无法满足目标 WebView、Rust MSRV、平台或安全约束，必须先记录替代技术、证据、迁移影响和恢复条件的硬规则例外 ADR；永久替换本事实标准须由项目负责人明确确认并以新 ADR 取代本决定。

## ADR-20260805-003：固定下游 Rust 技术选型事实标准

- 日期：2026-08-05
- 状态：Accepted
- 关联需求：项目负责人明确要求先把 Tokio、Axum、Clap、SeaORM、tracing、anyhow、thiserror、serde 与 jiff 固化为 Rust 技术选型事实标准，未来再继续扩展。
- 决定：Tokio 是异步运行时标准；Axum 是获批 Rust HTTP 服务标准；Clap 是 CLI 参数与子命令标准；SeaORM 是获批关系型数据库 ORM 标准；tracing 是结构化可观测性标准；anyhow 用于二进制和适配器装配边界的错误上下文；thiserror 用于 core、库和可恢复边界的稳定类型化错误；serde 是序列化/反序列化标准；jiff 是日期、时间、时区、时间戳和时间跨度标准。
- 能力边界：固定选型按真实能力触发，不等于中性初始化无条件安装所有依赖。未批准 HTTP 服务时不引入 Axum，未批准关系型持久化时不引入 SeaORM，没有真实观测、序列化或日期时间路径时不添加占位依赖。Tokio 随所选 Rust 适配器生效，Clap 只随 CLI 生效；Axum 不恢复已经移除的独立 WEB 适配器。
- 架构边界：Axum 路由、提取器和响应映射属于 HTTP 边界，SeaORM 实体与驱动属于基础设施边界，业务规则、迁移策略、事务语义和结果解释仍由 core 决定。thiserror 保留跨接口可判定错误，anyhow 只补充应用边界上下文，不得成为公开稳定领域错误契约。tracing 使用结构化 event/span，并禁止记录密钥、令牌、个人数据或未脱敏业务载荷。
- 依赖边界：全部 Rust 依赖仍由根 `[workspace.dependencies]` 统一声明，成员只用 `workspace = true`；只启用满足真实能力的最小 feature，并在 Rust 1.90、Windows/macOS/Linux 与锁定验证约束内采用较新兼容稳定版本。
- 影响范围：最新 Product Spec、Rust 基线、AGENTS/README、初始化与实施 Skills、Harness validator、回归测试和当日 Changelog。
- 不包含：本轮不选择具体版本、不更新中性 Cargo.lock、不实现 HTTP 服务、数据库、日志管线或产品业务，也不构建、验收或发布候选；后续扩展技术族由项目负责人继续确认。
- 风险：把“固定”误读为全部预装会增加编译体积、供应链面和无用抽象；把 anyhow 下沉到 core 会破坏稳定错误匹配；把 tracing 当作任意载荷日志会产生数据泄露。通过能力触发、错误分层、最小 feature、敏感字段禁录和机械事实门禁降低风险。
- 验证：静态核对九项技术的职责、能力触发、core/adapter 所有权和例外路径；新增 validator 必需片段回归，并运行默认 Python 回归、完整 Harness validator、Markdown 链接、文件行数与差异检查。
- 恢复或调整标准：真实下游若证明某项固定技术无法满足 MSRV、目标平台、安全、性能或渠道硬要求，必须先记录替代技术、证据、迁移影响和恢复条件的硬规则例外 ADR；永久替换事实标准须由项目负责人明确确认并以新 ADR 取代本决定。

## ADR-20260805-002：项目记忆排除日常维护流水账，并硬限制人工维护文本为 400 行

- 日期：2026-08-05
- 状态：Accepted
- 关联需求：项目负责人明确要求 Bug 修复、重构等维护操作不计入 ADR、Changelog 等项目记忆，并严格限制单文件不得超过 400 行。
- 背景：现有事件触发规则仍允许用户可感知的缺陷修复进入 Changelog，多个执行入口也可能因“发生了修改”而更新其他记忆；这会把维护流水账混入产品边界、长期决定和交付证据。现有文件规则只是 400/800 行软审查，validator 只给警告，仓库已有多份维护脚本、测试和长文档超过 400 行。字面限制所有 UTF-8 文件又会覆盖 Cargo/pnpm 等工具生成且不可拆分的锁文件，破坏当前可复现构建契约。
- 记忆决定：普通缺陷修复、不改变可观察行为的纯重构、格式整理、测试补强和内部清理本身不触发 Product Spec、ADR、Product Status、Changelog 或 Verification；完成结果只在最终回复和测试/CI 中报告。复杂、多模块、跨会话或中风险维护仍可因执行协调独立建立 Work Plan。若同一任务另外改变产品边界、引入长期决定或硬规则例外、形成重要阻断/交接、进入发布/人工复核/长期审计，或触发安全/渠道硬要求，只记录该独立事件；“修复”或“重构”标签不得绕过门禁。已有 TECH_DEBT 条目恢复准确状态不属于新增修复记录。
- 行数决定：所有由人类或 Agent 维护的文本文件，包括源码、测试、脚本、文档、配置、Skills、参考和模板，统一按 `splitlines()` 等价的物理行计数并硬限制为最多 400 行；400 行通过，401 行失败。超限必须按职责拆分，不能以警告、计划说明或 ADR 例外降级。工具生成且禁止手工编辑的锁文件/生成物与原样内嵌第三方文件不属于人工维护文件；这是范围定义而非超限豁免，其生成器、模板和维护说明仍受门禁。
- 机械决定：提供可随 `$desktop-implement-change` 保留到下游的单一检查器，使用 Git 的 NUL 分隔清单覆盖已跟踪和未忽略的未跟踪文件，不跟随符号链接，并明确报告枚举、读取和 UTF-8 文本判断失败。Harness validator、初始化、实施、里程碑验证和发布准备复用该门禁；升级传播必须同时包含检查器和回归测试。
- 历史决定：不改写 Verification 的真实历史，过长的现有 Verification 和方法论文档只做事实守恒拆分，不删除失败证据、人工签署或有效方法论。ADR、Changelog、Work Plan、Product Status、Product Spec 五类按日记忆改为只保留最新日期文件，旧日期文件随即删除、历史交由 Git 版本控制承担（见 ADR-20260805-004，同日修正本条）。当前未发布的同日 Changelog 合并为新规则下仍合格的新增/变化，移除作为维护流水账的“修复”分组。
- 影响范围：最新 Product Spec、工程规则、AGENTS/README、项目记忆索引、执行/验证/发布/升级 Skills、Harness 方法论、当前 Verification 组织、下游初始化与升级传播、文件行数检查器、validator 和回归测试。
- 不包含：不改变产品用途、接口组合、core-first 职责、发布授权或历史验收结论；不要求手工拆分或编辑 Cargo/pnpm 等工具生成锁文件，也不把普通维护任务包装成新的长期决定。
- 理由：事件触发的项目记忆能保留产品、架构、阻断和交付事实而不制造实现流水账；统一 400 行硬门禁可把职责拆分从建议变为可重复验证的完成条件，同时保持生成依赖锁的真实性与可复现性。
- 风险：过度排除可能漏记被称为“修复”的安全、发布或长期架构事件；通过独立触发器优先和禁止用任务标签绕过门禁降低风险。大规模文件拆分可能造成导入、测试发现、链接或历史证据丢失；必须以行为回归、链接检查、事实守恒复核和完整 validator 收口。
- 验证：覆盖 400/401 行、无尾换行、隐藏/空格路径、已跟踪/未忽略文件、忽略文件、二进制、符号链接、生成锁文件及 Git/读取失败；拆分全部现有超限人工维护文件；运行默认 Python 回归、升级器回归、完整 Harness validator、Markdown 链接与差异检查。
- 恢复或调整标准：若某类文件被证明不是人类或 Agent 维护，必须以可机械识别的工具生成或第三方来源纳入封闭分类，不得按路径任意放宽。人工维护文本的 400 行上限和日常维护不形成项目记忆流水账持续有效，除非项目负责人以新的明确产品约束替代。

## ADR-20260805-001：强制采用 core-first 与 CLI/TUI/MCP/GUI 薄适配器架构

- 日期：2026-08-05
- 状态：Accepted
- 关联需求：项目负责人要求后续业务逻辑尽可能由 core 统一实现，CLI、MCP、TUI、GUI 只作为调用 core 的薄层；系统托盘等接口或平台特有能力仍由对应适配器实现，并要求本轮完成当前未完成目标。
- 背景：现有 Harness 已禁止 core 反向依赖适配器，并要求 CLI 不重复业务规则，但最新 Product Spec 没有保留早期“业务在 core、适配器只映射”的完整约束，Rust 基线又只对 CLI 写出明确薄层职责。方法论文档还把“平台能力”笼统列入 core，可能诱导把系统托盘、窗口生命周期或终端恢复错误下沉；反过来，MCP/GUI 的“验证输入”和 TUI 的“应用状态”也可能被误读为允许在适配器内实现领域校验、业务状态和用例编排。
- 决定：Core-first 成为所有下游的硬架构规则。凡不依赖某一具体接口或宿主才能成立的领域类型、业务规则、语义校验、业务默认值、应用用例与工作流编排、领域状态转换、稳定领域错误、平台无关权限、权威业务状态、迁移与持久化策略，都必须在共享 core 中实现并通过明确 API 暴露；即使当前只存在一个适配器也同样适用。
- 薄层决定：CLI、TUI、MCP、GUI 仅负责运行时和依赖装配、接口语法或协议结构解析、展示与纯交互状态、调用 core，以及把 core 结果/错误映射为参数错误、协议结果、视图状态或退出码。适配器不得复制、改写或另建业务规则、平台无关校验、业务权限、权威业务状态、迁移或持久化策略；包含条件、重试或状态决策的跨 core 调用编排必须提升为单个 core 用例 API。
- 校验决定：适配器可以拒绝无法解析、缺少协议必填字段或违反宿主能力约束的调用；值域、跨字段关系、资源状态、业务权限、幂等性、可否执行以及会改变业务结果的默认值由 core 判定。格式正确但业务无效的输入必须进入 core，并在全部适配器中保留同一稳定领域错误。
- 平台边界：CLI 参数/标准流/退出码，MCP schema 注解/stdio 生命周期，TUI 焦点/选择/滚动/按键/终端恢复，以及 GUI React 状态、窗口/WebView、CSP、系统托盘、通知、自动启动和平台生命周期属于对应适配器。托盘点击、快捷键或通知动作触发的业务行为仍调用 core；平台机制本身不是 core-first 例外。文件系统、网络、外部进程等具体驱动可留在适配器或基础设施模块，何时调用、业务策略和结果如何改变领域状态仍归 core；真实需要时 core 可以定义运行时中立的能力接口，由适配器装配实现，不为假想未来预建抽象。
- 依赖决定：每个适配器直接依赖 core；core 不直接或通过 workspace 中间 crate 到达任何适配器或接口框架；适配器彼此不直接或通过 workspace 中间 crate 依赖、启动或解析输出。不含接口依赖的基础设施 crate 仍可被 core 合法复用。薄层按职责判断而不按行数、分支数或文件大小判断，协议映射和展示代码较长不自动构成违规。
- 测试决定：新增或修改业务行为时先提供 core 的核心成功路径和最高风险失败路径测试，再覆盖适配器映射与接口契约。每个公开操作在计划、实施或完成输出中记录“适配器操作 → core 用例 API → core 测试”映射；仅修改布局、协议映射或平台机制而不改 core 时，必须说明其接口/宿主专属性。语义归属仍由 Agent/人工评审，自动门禁只验证确定的依赖方向、必需规则和中性资产边界，不用关键词或代码行数伪装完整语义证明。
- 例外：普通接口/平台机制按上述边界实现，无需 ADR。真正把接口无关业务保留在适配器属于硬规则偏离，必须按 `docs/ENGINEERING_RULES.md` 记录理由、范围、风险、替代验证和恢复标准；“目前只有一个接口”、实现方便或避免新增 core API 不是可接受理由。
- 影响范围：最新 Product Spec、AGENTS/README、工程规则、Rust 基线、方法论文档、产品定义/规划/实施/验收/初始化 Skills、四类适配器 Skills 与参考、默认 Skill 提示、中性 Rust 资产、Harness validator、回归测试、升级受管工程层和变更记录。
- 不包含：不在 Harness 根实现具体产品业务；不为未知产品增加通用服务容器、仓库 trait、插件系统、额外 crate 或跨接口注册器；不把纯 UI/协议/平台状态塞入 core；不构建真实下游、候选或发布物，也不运行冒烟/E2E。
- 理由：把接口无关行为放在单一 core 中可让未来新增接口直接复用相同业务语义、错误和测试，并防止多个入口产生行为漂移；同时保留明确的平台机制边界，可以避免 core 反向耦合 Tauri、终端、MCP 或 CLI。
- 风险：过度集中可能把焦点、窗口或协议状态误放 core，也可能促使维护者为假想适配器提前抽象；只依赖文本片段的门禁无法证明真实业务语义。通过职责清单、单适配器同样适用、平台机制正例、禁止按行数判薄层、依赖图检查和语义复核降低风险。
- 验证：增加 core-first 规则/Skill 必需片段与负向退化测试；校验中性 core 不含接口语义和接口框架生产依赖，CLI 直接依赖 core；为可复用检查器覆盖合法方向、缺失 core 依赖、core 反向依赖、adapter 间依赖、重命名/目标依赖与接口框架泄漏。运行相关 Python 回归、中性 Rust 测试、Skill 结构/Markdown 链接、完整 Harness validator 和差异检查。
