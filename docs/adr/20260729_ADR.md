# 2026-07-29 ADR

## ADR-20260729-001：逐任务授权的前台并行 Worktree 与 Subagent 模式

- 日期：2026-07-29
- 状态：Accepted
- 关联需求：每次任务开始执行前询问用户是否启用并行 Worktree 和 Subagent；Subagent 执行过程不得作为用户不可见的后台工作。
- 背景：复杂变更可从并行拆分受益，但自动并行会增加分支、Worktree、冲突与资源管理成本；只在后台运行 Subagent 又会削弱用户对任务范围、阻塞和整合状态的判断。
- 决定：对会修改仓库或执行交付工作的任务，在实质执行前询问一次且只对当前任务生效。用户明确同意、任务至少有两个独立子任务且文件所有权可分离时，写入型 Subagent 各自在独立 Git Worktree 与 `codex/` 分支工作；纯只读子任务可共享只读上下文。主 Agent 在启动、阻塞、阶段完成、整合和验证节点发送用户可见更新，并同步等待所有必需结果后才能结束任务。纯问答、只读调查和即时安全处置不触发询问；拒绝、未答复或不可安全拆分时使用单 Agent 流程。
- 影响范围：`AGENTS.md`、README、Product Spec、Product Status、Work Plan、相关规划/实施/验证 Skills、新增协作 Skill、Harness validator、验证与 Changelog。
- 不包含：不逐行展示内部推理，不让多个写入者修改同一工作树，不自动 push、发布或删除含未整合修改的 Worktree。
- 理由：逐任务授权保留人类控制；Worktree 隔离降低并行写入冲突；明确阶段更新和同步等待在不暴露内部推理的前提下提供可审计可见性。
- 风险：Codex 宿主对状态流的展示能力可能不同；过细更新会制造噪声；Worktree 可能残留；错误拆分仍可能产生语义冲突。
- 验证：validator 检查授权、隔离、可见节点、同步等待、拒绝回退和安全清理契约；使用隔离临时 Git 仓库验证 Worktree 脚本的正向与风险失败路径；真实 Subagent 宿主交互在发布前 E2E 记录。
- 恢复或调整标准：若并行模式不能稳定降低周期或导致冲突、残留和用户认知成本上升，保留逐任务询问但默认推荐单 Agent，或在新 ADR 中收紧适用条件。

## ADR-20260729-002：开发轮次验证与发布整体验收分层

- 日期：2026-07-29
- 状态：Accepted
- 关联需求：每轮开发仅进行单元测试与验证，把整体验收适当延迟到用户准备发布前。
- 背景：每次小改动重复最终产物构建、启动冒烟、E2E、跨平台和人工整体验收，会拖慢开发反馈；但若只运行单元测试，也可能遗漏格式、编译、契约或变更相关风险。
- 决定：每轮开发执行非空单元测试与变更相关的必要验证，必要验证可包含格式、lint、静态检查、目标集成/契约测试和最小只读冒烟。最终产物、完整构建矩阵、Computer Use E2E、归档与人工最终复核默认延迟到用户明确准备发布、要求交付验收，或本轮直接修改发布链路时。发布准备必须基于当前源码重新运行完整闭环，历史结果不能替代。
- 影响范围：`AGENTS.md`、Product Spec、工程规则、计划/实施/验收/发布 Skills、`docs/VERIFICATION.md`、`docs/RELEASE.md` 与 validator。
- 不包含：不允许零测试，不取消缺陷回归测试，不允许把失败结果交给下一轮，不把日常验证结论标记为发布就绪。
- 理由：把快速反馈与发布可信度分开，既减少重复成本，又保留与改动风险相称的即时证据和发布前完整门禁。
- 风险：变更相关验证选择不足可能延迟发现集成问题；长时间不做完整验收可能积累风险；发布前一次性暴露问题会增加修复压力。
- 验证：validator 检查开发门禁和发布门禁没有混用；测试覆盖成功路径、最高风险失败路径和发布触发条件；发布前运行完整 Harness 与 bundled asset 验证并记录未验证平台。
- 恢复或调整标准：若发布前集中失败频繁或修复成本上升，则按失败数据把对应集成、构建或冒烟检查前移到受影响开发轮次，而不恢复无差别全量验收。
