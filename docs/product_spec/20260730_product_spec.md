## 一句话目标

为以 AI Agent 为第一消费者、人类负责方向、审批和最终复核的跨平台收费小工具，提供一个不实现具体业务、可一次性建立终端下游项目，并让协作过程、工程边界与发布证据都可审计的 Harness。

## 用户、问题与结果

- 核心用户：使用 AI Agent 创建、交付和维护企业收费小工具的项目负责人。
- 主要问题：项目意图和约束容易跨会话丢失；复杂编码任务缺少可控的并行协作入口；在产品/范围设计、实施计划设计及其他非编码阶段询问并行模式会制造无关打断；旧 Harness SemVer 不能直接表达版本确定时间；重型真实环境验收过早触发会拖慢反馈并产生非预期外部操作。
- 输入：项目身份、目标目录、接口组合、产品意图、编码/实现阶段的并行授权、Harness 版本确认时间、本次构建/发布的手动验收选择、实现、验证证据、商业授权和人工审批。
- 输出：独立终端项目根、shared core 与所选 adapter、可见的 Agent 协作过程、分层验证证据、项目记忆，以及保持法律条款的双语企业专有许可证。
- 可观察结果：Agent 能恢复上下文；用户只在编码/实现阶段决定是否启用并行模式并观察其阶段；其他阶段不中断询问；Harness 版本可按上海时区时间排序；开发轮次快速反馈；发布门禁保持可审计。

## MVP 包含

### Harness 与下游生命周期

- Harness 只提供文档、项目 Skills、中性资产和验证入口，不实现具体业务。
- `$instantiate-project` 只执行一次，要求展示名、ASCII `snake_case` 标识、完整目标项目目录路径、负责人和目标平台；目标必须不存在或为空，解析后的 basename 必须与项目标识一致，复制后该目录是初始化、开发、验证和发布准备的唯一项目根目录。
- 下游具有独立 Git 仓库、`main` 初始分支、无 remote 的唯一初始化基线 commit；`git rev-parse --show-toplevel` 必须精确等于项目根，复制不得包含源 `.git` 或 Harness 的日期项目记忆。
- 下游默认采用 Rust 2024、Rust 1.90 MSRV（即 MSRV 1.90.0）、shared core 与用户从 CLI/TUI/MCP/GUI/WEB 独立选择的 adapters；1.90.0 是最低兼容版本而非精确版本锁，未选择任何接口时默认 CLI。
- TUI 固定采用 Ratatui、tui-realm 与 tui-realm-stdlib；GUI/WEB 前端固定采用 React、TypeScript、Mantine UI、TanStack Router、TanStack Query 与 Jotai。偏离必须形成硬规则例外 ADR。
- Product Spec 缺失或为 Draft 时仅允许无业务副作用的 `scaffold status`，CLI JSON 返回 `productDefinitionRequired=true`；完整 scaffold 验证后删除实例化、初始化和模板专用派生入口，同时保留非空 Skills 地图和约束地图。
- `docs/AGENT_POLICY.md` 是 superpowers 能力开关的唯一来源；GUI 首次真实开发前调用 `$prepare-gui-app-identity`。
- `$rename-project-identity` 负责展示名、标识、路径、配置、Skills、文档和双语许可证项目名的全量改名，保留法律条款。
- 文件、中文业务注释、文档、测试与例外统一遵守 `docs/ENGINEERING_RULES.md`。

### 可选并行 Worktree 与 Subagent 协作

- 仅在代码或实现变更阶段，在实质编码前询问一次是否启用并行 Worktree + Subagent 模式。
- 产品定义、范围设计、实施计划设计、纯文档维护、纯问答、只读调查、验证复核、构建、发布准备、交付工作和即时安全处置不询问并行模式；这些阶段不因会写入仓库而转入询问分支。
- 只有用户对当前编码/实现任务明确同意时才启用；同意不得跨任务继承。拒绝、未答复或任务不适合安全拆分时，使用单 Agent 当前工作树流程。
- 并行模式只用于存在至少两个可独立交付、文件所有权清晰且合并顺序可定义的子任务；不能为了满足形式而创建 Subagent。
- 每个写入型 Subagent 使用独立 Git Worktree 和独立 `codex/` 前缀分支；只读分析可不创建 Worktree。不得让多个写入者直接修改同一工作树或未声明的重叠文件。
- 写入前从精确单元 Worktree 调用仓库 helper `guard`，逐项声明写入目标并校验实际 cwd、Git top-level、登记 Worktree、当前分支和符号链接解析后的路径边界。该门禁不能替代宿主或操作系统级 sandbox。
- 主 Agent 在调用 Subagent 前公开子任务、所有权、Worktree/分支和验证边界；在启动、阻塞、阶段完成、整合与验证节点发送可见更新，并同步等待全部必需结果。
- Subagent 不得自行扩大范围、覆盖其他参与者修改或进行发布；主 Agent 负责冲突处理、整合、最终验证和结果说明。

### 分层开发、验证与发布

- 首次代码开发前调用 `$check-development-environment`；Rust 始终阻断，Windows 同时检查 MSVC，GUI/WEB 额外检查 Node.js 与 pnpm。
- 每轮开发执行非空单元测试与变更相关的必要验证，包括按风险选择的格式、lint、静态、目标集成/契约测试和最小只读冒烟。
- 每轮开发不重复执行发布级整体验收；普通交付状态复核和发布链路修改不得自动触发重型真实环境验收。
- Computer Use E2E 及同类重型验收只能在用户发起构建/发布任务后，于首次发布构建前逐项选择；产品规格或渠道硬要求不得跳过。
- 构建/发布准备必须基于当前源码重新执行编译、非空单元测试、相关集成/契约、最终产物构建与存在性检查、真实产物只读启动冒烟；任一失败都阻断后续打包和发布动作。
- 已启用或必需的手动验收在产物构建后、打包前执行；失败、超时、取消或未执行均阻断。未启用且非硬要求时记录 `Not run`、原因和风险。
- 日常验证失败可在原任务范围内修复并重跑；发布、破坏性操作、范围变化和最终完成声明继续由人工授权或复核。

### 商业许可与知识产权

- Harness 与收费下游采用非开源企业专有商业许可；根 `LICENSE.zh-CN.md` 和 `LICENSE.en.md` 保持一致，第三方材料继续受各自许可约束。
- 下游是终端项目，不得作为 Harness、模板、脚手架、SDK、生成器或产品底座继续派生，除非另有书面授权。
- 价格、客户、期限、地域、授权数量、支持和特殊源码权限由正式商业文件确定；正式销售前完成法务与第三方许可证复核。

## 不包含

- 不在 Harness 根实现具体产品、账户、支付、云托管、远程部署或业务命令。
- 不在产品定义、范围设计、实施计划设计、纯文档维护、问答、只读调查、验证复核、构建、发布准备或交付阶段询问 Worktree/Subagent，也不因这些阶段产生仓库写入而扩大触发范围。
- 不自动为所有编码任务启用并行模式，不在用户未同意时创建 Worktree/Subagent，不把不可拆分任务强行并行。
- 不承诺逐行直播 Subagent 内部推理；可见性针对计划、所有权、状态、阻塞、结果、整合和验证证据。
- 不取消日常单元测试、缺陷回归测试或变更相关验证，不允许把已知失败的开发结果标为发布就绪。
- 不因普通交付复核、修改发布链路或历史任务曾启用过，就自动执行或继承 Computer Use E2E 等手动验收。
- 不自动 tag、配置 remote、push、发布、签名或上传制品；不改变现行企业专有商业许可。

## 可靠性与风险约束

- 不覆盖用户修改；并行前必须检查工作树、分支、Git top-level、目标 Worktree 路径与文件所有权，拒绝符号链接越界和不明确的重叠写入。
- Worktree/分支创建、整合和清理必须可追踪；未整合分支或含未提交修改的 Worktree 不得自动删除。
- 用户可见更新不得泄露秘密或内部推理，只报告任务事实、命令级证据、状态和决策。
- 触发阶段必须按任务目的判断，不能仅凭“会写文件”认定为编码；产品/范围设计和实施计划设计即使写入项目记忆也保持单 Agent。
- Harness 时间版本必须是上海时区的 12 位有效年月日时分；同一分钟内不得通过私自追加后缀制造第二个版本。下游产品继续使用其独立版本事实与默认 SemVer。
- 延迟整体验收不能降低发布门禁；发布准备必须基于当前源码重新生成证据，历史开发轮次结果不能替代。
- 每次构建/发布任务的手动验收选择必须可审计；硬要求、启用、未启用、执行结果和剩余风险分别记录。
- 重要、难以逆转或偏离硬规则的决定进入当日 ADR；用户可见维护流程变化同步状态、验证与 Changelog。

## 成功标准

- [ ] Agent 只在代码/实现阶段询问一次并行授权，授权不跨任务继承；拒绝后能完成单 Agent 流程。
- [ ] 产品/范围设计、实施计划设计、纯文档维护、问答、只读调查、验证复核、构建、发布准备和交付任务不出现并行模式询问。
- [ ] 适合并行的任务可建立至少两个独立 Worktree/Subagent 单元，所有权、分支、整合顺序和验证边界明确。
- [ ] helper `guard` 对错误 cwd、Git 根、detached/错误分支、空写入清单、绝对越界和符号链接逃逸稳定拒绝，并准确公开宿主级限制。
- [ ] 用户能看到启动、阻塞、阶段结果、整合与验证更新；主 Agent同步等待全部必需结果。
- [ ] 日常开发门禁执行非空单元测试和变更相关验证，并明确记录未运行的发布级验收。
- [ ] 构建或发布准备按当前源码执行不可跳过的基础闭环；所有必需或当次启用的手动验收在打包前通过。
- [ ] 规则、相关 Skills、validator、README、AGENTS、项目记忆和验证文档保持一致。
- [ ] `Version.md` 中的 Harness 当前版本为上海时区合法 `YYYYMMDDHHMM`，README、发布规则、当前规格、Changelog 和 validator 摘要一致；下游 SemVer 不受影响。
- [ ] 双语许可证、独立下游 Git 根、一次性初始化裁剪、五类 adapter 和身份改名等既有成功标准继续有效。
