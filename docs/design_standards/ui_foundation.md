# UI 统一设计基座

`standard_id = ui-foundation-v1`

所有 GUI 的页面、组件和展示层必须使用同一套语义 Token、标准组件与交互反馈。业务页面负责内容与布局，共用基座负责视觉和交互的一致性；修改主题或组件默认值后，所有消费者应一起生效。

本标准由负责人于 2026-10-28 提供的《软件 UI-Harness 设计规范》v1.0 提炼并适配。源文件 SHA-256 为 `1fed24221cbccbe94a9240084cacb6891c459a65e9bfb13162e00fbac00781d4`。附件中的色值和尺寸样例不是产品品牌事实，工具建议不构成安装授权；本文件是吸收后规则的唯一来源，不另保留会独立演化的全文副本。

## 适用与组合

- 本基座匹配所有 GUI，按 [设计标准索引](README.md) 与框架、组件标准组合。CLI、TUI、MCP 可保留资料，但不因本标准新增 GUI、CSS、组件库或工具依赖。
- 本基座是当前唯一视觉规则来源。框架/组件文档只补充相容的 API、交互、无障碍及状态合同；旧风格、旧像素硬锁和第三方审美与本基座冲突时直接清理，不作为回退。后续用户明确批准的新方向仍可修订本基座。
- Tauri 使用 [Tauri GUI 标准](tauri_gui.md) 的 Mantine theme、组件和 CSS 接线；GPUI 使用 [GPUI 标准](gpui_gui.md) 及项目本地 GPUI Kit 设计指南的原生主题/组件机制。不得把 React、Web Storage、CSS 或前端检查工具套到原生 GPUI。
- 不再自动安装或激活其他风格 Skill。GPUI Kit 原文只用于 API、组件机制与原生交互参考，其中独立的视觉建议不自动生效；既有下游自有第三方资产仍受升级保护。

## Token 与样式分层

| 层 | 职责 | 约束 |
|---|---|---|
| 语义 Token | 品牌/功能/中性色、字体族/字号/字重/行高、间距、圆角、边框、阴影、动效、断点与浮层层级 | 应用内只有一个权威主题定义；亮暗模式使用同一语义 |
| 全局基础 | 框架必要的 reset、全局排版与主题挂载 | 在应用根装配一次，不逐页重复初始化 |
| 标准组件 | 控件尺寸、变体、状态与复用反馈模式 | 由组件库与共享默认值表达，不复制一套近似实现 |
| 业务布局 | 页面结构、区域排列和业务特有内容 | 使用 Token 与组件公开接口，不重写基础视觉规则 |

“一套样式基座”指同一来源与职责分层，可以拆成多个高内聚文件。页面不得建立自己的品牌色、基础按钮样式或第二套主题；业务布局使用 CSS Modules 或框架作用域隔离，不能通过隔离绕过基座。

### 颜色与主题

- 品牌主色/辅助色、success/warning/danger/info、主/次/辅助/占位文本，以及页面/surface/hover/遮罩/边框/分割线，统一映射为语义 Token。功能色表达对应含义，并配合文字、图标或语义属性，不只靠颜色传递状态。
- 颜色字面量只在权威主题定义、颜色资产或确有数据含义的可视化色板中出现；页面和业务组件消费语义 Token，不散落 hex、rgb 或只适合浅色的值。可视化色板也须集中定义并有文字/形状等辅助编码。
- 新增业务颜色先复用已有语义；确需扩展时在主题层说明用途及亮暗映射，按已有设计治理确认。附件示例蓝、绿、灰色和阴影不作为新默认值。
- 两条 GUI 路径都保持浅色、深色、跟随系统三态及完整亮暗语义主题，不把深色降为可选。主题偏好与页面会话的归属继续按框架标准处理。

### 节奏、字体、图标与动效

- 布局间距与常用控件展示尺寸统一使用 4px 节奏和框架语义档位；Tauri 在 `react/appDesignTokens.ts`、GPUI 在 `app/design_tokens.rs` 集中定义应用展示 Token。删除旧侧栏和页面的独立像素硬锁；边框、文字排版及必要光学校正使用各自语义 Token，不把无障碍或媒体比例机械取整。
- 字体族、字号阶梯、字重、行高、圆角和阴影由主题分级；页面按标题、正文、辅助信息等语义调用，不随意另写裸值。普通内容优先边界和留白，阴影只表达浮层或真实层级。
- 同一容器类型和使用上下文统一控件高度、标签位置、标签宽度、行高、间距与对齐。使用共享尺寸档位；附件的“大/默认/小/迷你”映射到框架已有档位，不新增重复枚举或局部密度体系。
- 图标来源与线条风格遵循框架标准，统一尺寸和文字间距；仅图标控件有完整可访问名称。Tauri 固定 Tabler，GPUI 使用其原生图标机制。
- hover、active、弹层与状态过渡统一使用主题时长/缓动；尊重 reduced motion。断点、浮层层级和遮罩同样集中管理，不逐页发明。

## 控件与反馈

- 优先直接复用 Mantine / GPUI Kit 标准控件及其公开配置。组件库自身已经提供基础组件，不为每个 Button、Input 或 Switch 再套一层无约束价值的包装；只把重复且稳定的真实组合提取为项目共享组件。
- 页面不得用原生标签加自定义样式重造控件，也不得用 `div` 模拟按钮、链接或开关。原生语义元素用于必要布局或库未覆盖的真实能力时，必须满足同一 Token、键盘、焦点、名称和状态合同。
- 按钮按主/次/轻量/危险语义调用，同一操作组最多一个主动作；表格内动作保持低强调与足够点击目标。危险动作说明对象和影响，不可轻易恢复时二次确认，取消保持安全默认；确认不替代真实业务权限检查。
- 工具栏、表单、弹层底部和行内操作分别统一使用共享尺寸；不以局部覆盖基础 padding、字号、颜色、圆角或私有选择器制造新档位。运行时测量和真实业务布局值仍按框架公开接口表达。
- 每个控件统一提供适用的 focus/hover/active/disabled/read-only/loading/error 状态，焦点可见且不被遮挡。按钮、开关、复选框和链接的动作由控件自身拥有，父容器周围区域不能代理子控件动作。
- 表单使用可见标签、就近说明与错误。相同上下文保持同一标签模式，窄屏可按共享响应式规则回流；不强迫所有窗口宽度固定为同一方向。
- Modal、Drawer、Popover、Tooltip 和消息反馈复用框架组件及共享默认值；键盘可达、Escape、焦点圈定与关闭后焦点恢复按具体组件语义验证。长说明和唯一错误信息不能仅藏在 Tooltip/Toast。
- 首次加载、后台刷新、提交中、成功、空态、可重试错误和权限失败使用共享模式；加载、失败与空结果分别表达。复用结构和反馈方式，具体文案仍描述当前对象与可执行下一步，并进入 i18n。

## 表格与偏好边界

业务表格复用同一框架标准与实际存在的共享表格模式，不逐页重造表头、操作栏、状态区域和列配置。公共回调使用稳定列 ID、业务 ID 与类型化输入输出，统一表达选中、排序和列配置变化；尚无真实消费者时不预建通用表格框架。

| 能力 | 接入条件 |
|---|---|
| 行选择与批量操作 | 由批准需求确定；Mantine 列表继续使用 `none/current-page/cross-page` 合同。删除、导出、状态变更不是默认业务能力；无能力时不显示假按钮 |
| 权限适配 | 展示层按权威结果禁用/隐藏，实际操作仍由 core/服务端重新判定，不把前端置灰当作授权证明 |
| 排序 | 只对实际可排序字段开放；Mantine 列表沿用已有单列排序与稳定次序，不假定支持多列排序 |
| 列显隐与顺序 | 命中 Mantine 列表时使用既有列设置、稳定 key 和迁移合同；列顺序拖拽不等于列宽拖拽 |
| 列宽拖拽及保存 | 是按真实需求新增的能力；现有模板未提供，不宣称已经内置，也不擅自扩大偏好 schema |
| 固定表头/列、展开、筛选、编辑、虚拟化或无限滚动 | 只在需求和所选专项标准允许时实现；命中 Mantine 列表继续采用其 offset 分页，不能自行替换 |

状态缓存不是默认许可。普通 GUI 页面会话、Mantine 列表的 URL/sessionStorage/Query/列偏好，以及 GPUI 原生状态各自遵循专项标准；本基座不增加持久字段，不把业务行、权限或查询结果缓存到样式偏好中。新增表格能力必须同时实现交互、错误和适用回归，不能只展示入口。

## 响应式与可访问性

- 共享断点只表达真实结构变化；页面消费断点和统一的紧凑/常规/宽松布局档位。同一模式下的表单、筛选栏、详情和弹层保持节奏一致，不逐页创建近似断点。
- 双语长文案、窄窗口和文本缩放允许自然换行；页面不整体横向溢出，确需二维浏览的数据区域局部滚动。壳层消费中央布局 Token；最低窗口尺寸与窗口恢复仍由原生窗口合同决定。
- 键盘操作、语义名称、焦点、状态播报、对比度、触控目标和 reduced motion 按命中的框架标准验证；不能用 Token 名称或统一色板推定无障碍已经通过。

## 实施与最小检查

本标准要求使用已有工程能力落实一致性，不在 Harness 模板中创建产品主题、业务组件或前端运行工程，也不自动安装 Stylelint、ESLint 或其他依赖。下游优先使用已声明工具；新增依赖按既有依赖准入处理。GPUI 通过原生主题和 Rust/Kit 机制落实，不引入 CSS 检查器。

本次变化命中哪一层，就检查哪一层；日常变更仍遵守 [工程规则](../ENGINEERING_RULES.md) 的最小验证范围，不追加整仓扫描、构建或 E2E。

- 改 Token/组件默认值：确认唯一主题来源、实际消费者与亮暗映射；在相关组件中检查双语、状态、对齐和必要对比度。
- 改页面布局：确认没有局部重造控件、散落基础色值/尺寸、重复主题或越过专项标准；检查实际窄窗口、长文案和缩放影响。
- 改控件/浮层：覆盖实际动作与父容器周围区域、键盘、焦点、pending 防重及最高风险失败反馈。
- 改表格：调用命中标准/Skill 的 checklist，核对能力实际存在、权限、排序/分页、选择与偏好边界；未实现能力明确列为未提供。
- 改 Harness 规范与路由：运行仓库声明的 `node scripts/validate_harness.mjs`；改 Node 门禁时再运行 `node scripts/run_harness_tests.mjs`。这些检查只证明规范入口和工程合同，不证明真实下游视觉、构建或 E2E 已通过。
