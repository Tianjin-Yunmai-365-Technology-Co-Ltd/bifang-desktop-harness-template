# GPUI GUI 设计标准

稳定标识：`gpui-gui-common-v1`。

仅匹配根 Cargo metadata 中 `interfaces` 包含 `gui` 且 `gui-framework = "gpui"` 的原生桌面界面。技术栈和模板入口由 `$desktop-add-gpui-adapter` 管理；本标准不引入 Tauri、WebView、React、Mantine、pnpm 或 JavaScript 图标库。

## 壳层与信息架构

- 原生窗口、根视图、菜单、纯交互状态、主题和语言属于 `<project-id>_gui`；业务规则与权威业务状态仍属于 `<project-id>_core`。中性初始化只显示脚手架状态，不生成业务功能或示例数据。
- 首次主窗口为 1440×900，最小 960×640，居中且可调整；不得把 DMG 安装卷窗口尺寸当成主窗口尺寸。平台不支持的窗口行为必须明确报告。
- 侧栏顶部显示本地应用 Logo，当前 Cargo 版本紧随其后，版本展示只有一个小写 `v`。功能项向下增长，底部顺序为已选赞助、固定设置、已选关于。
- `sidebar_mode = compact` 使用 80px 全宽居中竖排菜单，不提供折叠按钮；`detailed` 使用 248px 展开、76px 收起，只在收起时隐藏名称，并提供完整 Tooltip/可访问名称。详细模式折叠状态属于 adapter 的设备级偏好。
- 侧栏宽度、内容偏移和折叠按钮消费同一状态，不能分别缓存导致错位。动作绑定在拥有该动作的按钮或菜单项自身，点击容器周围区域不能代理子控件动作。

## 设置、主题与语言

- 设置页始终存在，固定只含当前应用名称/版本、语言和浅色/深色/跟随系统三态主题。中性阶段不增加隐私、统计或不可用桌面能力占位开关。
- 使用 gpui-kit 的主题/组件机制和 `rust-i18n`。所有实际页面提供中文、英文与英文回退；语言切换同步导航、设置、所选支持页和原生标题，不能显示未解析的翻译键。
- 系统主题和显式主题必须驱动同一亮暗语义颜色，不在页面中散落硬编码浅色值。主题、语言与详细侧栏偏好可持久化；普通页面会话状态仅在当前进程保留，不能借偏好存储复制 core 权威数据。
- 原生标题取当前应用展示名与权威 Cargo 版本；联系人只有经确认后才加入，不复制参考项目名称、版本或产品身份。

## 关于页与赞助页

- `about_page` 与 `sponsor_page` 分别决定页面、入口、组件和运行时资源是否存在；禁用时全部缺席。模板代码来自受维护的 GPUI 中性资产，不能在初始化后依赖源 `gpui-demo` 的绝对路径。
- 关于页显示权威应用名、版本、作者/联系人与经批准的免责声明。更新服务未配置时明确显示不可用并保持零出站；不得把静态文字、假成功或 Tauri updater 插件当成 GPUI 更新实现。
- 赞助页使用本地、可审计的品牌媒体与当前主题，图片保持比例并允许合理滚动；支付二维码不重绘、不解码重建。页面展示不授权订单、权益、支付回调或自动交易。
- 支持页模块保持独立职责；大视图拆为 Rust `<module>/mod.rs` 和内聚子模块，不以转发空壳规避文件上限。所有模块遵守工程规则的中文声明注释与测试组织要求。

## 能力与验证

当前 GPUI 首版模板尚未提供六项原生宿主能力 `system_tray`、`system_notification`、`autostart`、`single_instance`、`deep_link`、`global_shortcut`；当前均标为 `unavailable`，九字段 profile 中只能写 `disabled`，不提供虚假开关或注册逻辑。它们不适用 Tauri 插件、ACL 或命令合同；这是模板覆盖范围，不是 GPUI 框架的永久技术限制；后续可在明确范围内通过独立能力 Skill、真实实现与宿主回归增加。

初始化在非空 Rust 测试和实际 `cargo build` 后，通过 Computer Use 验证本机真实窗口、两个侧栏模式中的所选项、设置、语言/主题切换、关于/赞助存在或缺席，以及关闭最后窗口后进程结束。测试使用隔离偏好目录并回收进程；当前宿主结果不代表其他平台或安装包已通过。工程验证临时项目只有用户明确授权时才可使用参考中性 Logo，并必须标记为验证用途，不能称为正式身份完成。
