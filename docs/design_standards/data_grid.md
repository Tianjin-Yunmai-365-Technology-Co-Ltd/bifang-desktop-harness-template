# 通用 Grid 数据网格标准

`standard_id = data-grid-v1`

匹配所有 GUI 中按行列浏览重复记录的数据网格，先遵守 [UI 基座](ui_foundation.md)。本标准定义跨框架可观察行为；Tauri/Mantine 继续叠加 [列表页标准](mantine_list_view.md) 与 `$mantine-list-view`，GPUI 使用原生组件和原生可访问性机制，不引入 Web 依赖。它不要求无列表的中性 GUI 预建网格、数据源或业务动作。

## 密度、排版与回流

- 使用统一的紧凑密度、行列对齐、细分割线与清晰层级。字体、字号、字重、行高、单元格内边距和数字样式消费中央 Token；密度来自留白组织，不通过缩小辅助文字或点击目标实现。
- 表头滚动时保持可见，使用随主题变化的不透明背景和正确层级，不与数据重叠，不遮挡键盘焦点。表头高度随换行增长，不按一行文字硬锁。
- 数据行依真实数据顺序交替斑马纹；hover、selected 和 focus 可区分。选中另有 Checkbox/Radio 或等价非颜色标记；高对比模式仍保留可见轮廓。
- 容器与网格都不得产生横向滚动。容器、列和单元格允许收缩，按列职责分配相对宽度，默认长值自然换行；连续英文、URL、标识符也不得撑开布局。不能用整体 `overflow: hidden` 把溢出问题变成内容丢失。
- 必要省略必须有明确可发现、可用鼠标及键盘打开的完整值视图，支持选择复制、Escape 和焦点恢复；`title` 或仅 hover 的 Tooltip 不足以承担该能力。仅显示时不自动增加按钮。
- 窄窗口、200% 文本缩放和用户文本间距覆盖时，工具栏、筛选、分页与行内动作自然回流。列过多时可把次要信息移入可访问的行详情；隐藏的字段仍须可达，主标识、关键状态与操作不得消失。不能把所有列挤成无法操作的窄条，也不能退回横向滚动。

## 查询与分页

- 支持真实数据源允许的搜索、筛选、排序、分页和每页数量切换；不为尚无能力的字段展示假入口。查询草稿与已应用条件分开，明确显示已应用摘要、重置入口、排序字段/方向、总数与当前 X–Y 范围。
- 相同排序值维持稳定次序，以稳定业务 ID 作最终 tie-breaker；默认排序也确定。搜索、筛选、排序、每页数量改变时与 page=1 原子提交；规范化后条件未变时不触发新导航或请求。
- 只在可信成功响应后纠正越界；零数据规范为第 1 页，不显示不存在的范围。loading/error/旧页 placeholder 不能驱动纠页。
- Tauri/Mantine 的 offset 分页、固定页大小、URL/session 与 Query 所有权以专项标准为准；不新增并行状态源。GPUI 由原生页面状态与实际数据源接线，不复制浏览器存储合同。

## 单选、多选与范围

- 选择数量 `single | multiple` 与范围 `current-page | cross-page` 分开声明；`none` 不显示选择控件。只保存稳定业务 ID，不复制业务行作为选择权威。
- 单选用 Radio 或原生等价语义，选择新项替换原项，并提供清空；不显示全选。多选用 Checkbox，页头表达本页的未选/全选/半选；全选和取消全选只操作当前真实页。
- 可见摘要明确已选数量和范围；跨页选择不能用页头 Checkbox 冒充“选择所有匹配结果”。如未来需要全结果选择，必须另行实现数据源支持、条件快照与排除项合同。
- 当前页选择在翻页或查询组合改变时清空，成功刷新后裁剪消失的 ID。跨页声明条件改变后清空/保留策略；父级确认新查询指纹前，隐藏失效集合并禁用选择动作，避免首帧误操作。刷新、删除后也按权威结果校正可操作状态。
- 提供选择摘要、清空及真实下一步；单选可用单项动作，多选按实际需求提供批量动作，不预设删除/导出等业务能力。权限和当前状态由 core/服务端重新判定，客户端选择不能充当授权。

## 状态、恢复与交互

| 状态 | 必需行为 |
|---|---|
| 首次加载 | 有名称的进度和接近最终结构的占位，区域标明 busy |
| 全局空数据 | 说明暂无数据，只提供真实可执行的下一步 |
| 查询无匹配 | 说明当前条件无匹配，提供有效的重置条件 |
| 首次/新页错误 | 说明失败对象，按错误类型提供重试或真实恢复入口 |
| 同查询后台刷新 | 保留现有行、选择和滚动位置；在表格之后或既有状态槽位就近显示进度 |
| 后台刷新错误 | 保留现有内容并说明更新失败；可重试才显示入口，不闪空或移动表格起点 |

- 反馈槽位稳定，长错误允许增长；不要用固定高度裁掉恢复控件。换页 placeholder 明确只读，不能把旧数据冒充新页成功结果。
- 重试和提交在 pending 时防重复；禁用原因通过相邻说明、状态或可访问描述可理解，不能只靠变灰/Tooltip。按钮、链接、选择和行内开关各自拥有事件；点击父行或单元格不代理其动作。
- 原生 table 保持 caption、列 `scope=col`、主行 `scope=row` 和排序语义，控件使用原生键盘规则（Tab、Enter、Space；同组 Radio 支持方向键）。不要仅因称为 Grid 就增加 `role=grid`；真正采用交互式 ARIA grid 时必须同时实现 roving focus、方向键、Home/End 与行列索引及虚拟化焦点恢复。
- 加载、选择、结果与错误提供克制的状态播报；不重复播报、不抢焦点、不把状态仅编码成颜色。亮暗主题分别检查文字、边界、选中与焦点对比。

## 数据与渲染成本

- 按页请求和渲染，使用稳定 query key、业务 ID 与列定义；输入可采用提交或有界 debounce，中文输入法组合阶段不提交中间文本。只应用最新请求，消费取消信号；组件不再维护第二条相同请求路径。
- 新鲜期与失效由数据源声明，不强制每次挂载刷新。重复点击重试不取消重启进行中的请求；终态错误不自动重试，其他重试有界；成功变更只失效受影响查询。
- 优先分页和稳定 props，避免逐行订阅无关全局状态、无意义导航与重绘。只有真实测量表明需要时才引入虚拟化；同时维护可变行高、完整值、粘性表头、可访问行列位置与焦点，不因本标准新增依赖或基准任务。

## 最小检查

按实际修改覆盖稳定排序、条件重置、越界页、选择数量与范围、全选/半选/清空、查询失效首帧、重试防重和刷新保留。真实界面另检查亮暗主题、窄窗口、中英文长值、200% 文本缩放、文本间距覆盖、键盘、焦点与无横滚；模板契约测试不能证明真实宿主视觉已经通过。
